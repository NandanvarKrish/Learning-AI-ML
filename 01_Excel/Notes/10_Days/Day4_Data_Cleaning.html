🕳 Missing Data — Imputation Strategies CHOOSE CAREFULLY
How you fill missing values can make or break a model. The wrong imputation strategy introduces bias that's invisible but deadly. Here's the decision framework used by professional data scientists:
Data TypeMissing %StrategyExcel Formula
Numeric<5%Impute with mean=AVERAGE(col)
Numeric (skewed)<5%Impute with median=MEDIAN(col)
Categorical<10%Impute with mode=MODE.SNGL(col)
Any type10–30%Add "Missing" flag column + impute=ISBLANK(A2)*1
Any type>30%Drop the column — too unreliableDelete column
Time seriesAnyForward fill (use previous value)=IF(ISBLANK(A2),A1,A2)
🏷 Categorical Encoding — One-Hot in Excel ML REQUIRED
ML algorithms need numbers — they can't process "Engineering", "Marketing", "Finance". One-hot encoding converts each category into a binary column (0/1). It's the most important preprocessing step for categorical features.
// Original column: Department = "Eng" | "Mkt" | "Sci" | "Fin" // One-hot encoding creates 4 new columns: Is_Eng = IF([@Department]="Eng", 1, 0) Is_Mkt = IF([@Department]="Mkt", 1, 0) Is_Sci = IF([@Department]="Sci", 1, 0) // Note: drop one column (Is_Fin) to avoid dummy variable trap // The dropped column = reference category (implied when all others = 0) // Ordinal encoding (when categories have natural order) Grade_Num = SWITCH([@Grade], "A",4, "B",3, "C",2, "D",1, "F",0) // Verify encoding: each row should sum to exactly 1 =SUM([@Is_Eng],[@Is_Mkt],[@Is_Sci],[@Is_Fin]) → must = 1 for every row

🕵️ Missing Data Audit & Imputation
Find every null, choose the right imputation strategy, document every decision
Audit
▼
Before touching a single value, you need to know the full scope of missing data. Imputing without understanding the missing pattern can introduce serious bias — especially if data is Missing Not At Random (MNAR), where the absence itself carries information.
1
Create Day4_Cleaning.xlsx. In sheet "DirtyData", paste or type a deliberately messy 60-row dataset with columns: CustomerID, Name, Age, Income, Department, Score, JoinDate, Churned (Yes/No). Manually blank out ~15% of numeric cells and ~10% of category cells to simulate real missing data.
2
Create a Data Quality Audit table in a separate area. For each column, calculate:
Total Rows: =COUNTA(A2:A61)
Blanks: =COUNTBLANK(A2:A61)
Missing %: =COUNTBLANK(A2:A61)/60 (format as %)
Recommended Action: manually type (Impute/Drop/Flag)
3
Use Go To Special to visually locate all blanks: Ctrl+G (Go To) → Special → Blanks → OK. All blank cells are now selected (highlighted in blue). Count them in the status bar bottom-right.
4
Impute numeric columns (Age, Income, Score): In a helper column, use: =IF(ISBLANK([@Age]), AVERAGE(DirtyData[Age]), [@Age]). This replaces blanks with the column mean while keeping existing values untouched.
5
Impute categorical column (Department): =IF(ISBLANK([@Department]), "Unknown", [@Department]). For ML, "Unknown" becomes its own category — potentially informative. Alternatively use MODE: =IF(ISBLANK([@Department]), MODE.SNGL(DirtyData[Department_Num]), [@Department]) (requires numeric encoding first).
6
Add a "Was_Imputed" flag column for each imputed numeric: =IF(ISBLANK([@Age]),1,0). This binary flag tells the model "this value was estimated, not measured" — it often improves predictions because the missingness itself carries signal.
// Audit — missing data scorecard =COUNTBLANK(B2:B61) → Count blanks =COUNTBLANK(B2:B61)/ROWS(B2:B61) → % missing // Mean imputation (non-destructive — use helper column) =IF(ISBLANK([@Age]), AVERAGE(DirtyData[Age]), [@Age]) // Median imputation (for skewed Income) =IF(ISBLANK([@Income]), MEDIAN(DirtyData[Income]), [@Income]) // Categorical → "Unknown" =IF(ISBLANK([@Department]), "Unknown", [@Department]) // Missing flag (keep for ML — missingness = feature) =IF(ISBLANK([@Age]), 1, 0)
⚠️
Never impute in-place on raw data. Always create a new column (e.g., "Age_Clean") and keep the original. This preserves your audit trail. In production ML, you need to explain every data transformation — and "I overwrote the original" is not acceptable.

🔍 Duplicate Detection & Removal
Find exact AND fuzzy duplicates — then decide what to keep
Practice
▼
Duplicates in training data make models overfit to repeated examples. In transactional data, they inflate counts and revenue metrics. There are two types — exact duplicates (same row) and partial duplicates (same entity, different rows). Both need different treatments.
1
Create sheet "DedupLab". Copy your DirtyData and manually add 8 duplicate rows (copy-paste 4 random rows twice). Also add 3 "fuzzy" duplicates — same CustomerID but slightly different Name (e.g., "John Smith" vs "john smith").
2
Detect exact duplicates with COUNTIF: Add column "Dup_Flag":
=COUNTIF($A$2:A2, A2)>1
This counts how many times the CustomerID appeared ABOVE the current row. Returns TRUE for every duplicate (second occurrence onward).
3
Apply conditional formatting to Dup_Flag: TRUE rows get orange fill. Count total duplicates: =COUNTIF(Dup_Flag_Range, TRUE). What % of your dataset are duplicates?
4
Use the Remove Duplicates tool: Data tab → Remove Duplicates → select CustomerID column only → OK. Excel removes rows where CustomerID has already appeared above. Note the "X rows removed" message.
5
Detect fuzzy name duplicates: Add a "Name_Lower" column: =LOWER(TRIM([@Name])). Now sort by Name_Lower. Visually identical names (different capitalization/spacing) appear together. Use EXACT() or manual review to identify true fuzzy dups.
6
Record counts: In your Notes sheet, write: rows before dedup, rows removed, rows after dedup, % removed. This "data lineage" record is required documentation in any ML project — it proves your model was trained on clean data.
// Detect exact duplicate in column A (running count from top) =COUNTIF($A$2:A2, A2)>1 → TRUE for 2nd+ occurrence // Count total duplicates =COUNTIF(F2:F61, TRUE) // Full-row duplicate (compare entire row as text) =COUNTIF($A$2:A2, A2&B2&C2&D2)>1 → concatenate all cols // Fuzzy duplicate prep — normalize names =LOWER(TRIM([@Name])) // Check if two names are exactly identical (case sensitive) =EXACT(LOWER(TRIM(A2)), LOWER(TRIM(A3))) // Unique values only (Excel 365) =UNIQUE(A2:A61)
💡
ML implication: Duplicates in training data but not test data make your model appear more accurate than it is. A model that "memorized" a duplicate row will correctly predict it — but that's not generalization. Always deduplicate before splitting train/test.

⚙ Power Query ETL Pipeline
Build a reusable, click-to-refresh data cleaning pipeline
Power Query
▼
Power Query transforms your one-time manual cleaning into a repeatable, documented pipeline. Every step is recorded. When new data arrives, you click "Refresh" and all transformations run automatically. This is professional data engineering — inside Excel.
1
Click anywhere inside your DirtyData Table → Data tab → From Table/Range. Power Query Editor opens. You'll see your data in a preview with column headers at the top.
2
Step 1 — Change data types: Click the type icon (ABC or 123) in each column header. Set: CustomerID → Whole Number, Age → Whole Number, Income → Decimal Number, Score → Decimal Number, JoinDate → Date. Watch "Changed Type" appear in Applied Steps panel.
3
Step 2 — Remove blank rows: Home tab → Remove Rows → Remove Blank Rows. This removes rows where ALL cells are blank. For partial nulls: Click Score column header → right-click → Remove Rows → Remove Errors.
4
Step 3 — Replace null values: Select Age column → Transform → Replace Values → Value to Find: null → Replace With: average value (you'll need to calculate this outside PQ first). Do this for Income and Score columns.
5
Step 4 — Add custom columns: Add Column tab → Custom Column → Name: "Age_Group" → Formula: if [Age] < 30 then "Young" else if [Age] < 50 then "Mid" else "Senior". This is M language — Power Query's own syntax.
6
Step 5 — Load back to Excel: Home → Close & Load → Close & Load To → Existing Worksheet → pick an empty cell. A new Table appears with all transformations applied. Check the "Applied Steps" shows your full pipeline (should have 5+ steps).
7
Test refresh: Go back to DirtyData and add 5 new rows. Then right-click the Power Query output table → Refresh. Watch the new rows appear, already cleaned and with Age_Group applied — automatically. This is ETL.
// Power Query M Language examples (Add Column → Custom Column) // Age group conditional (M syntax) if [Age] < 30 then "Young" else if [Age] < 50 then "Mid" else "Senior" // Replace null with fixed value (M syntax) if [Income] = null then 45000 else [Income] // Clean text in M Text.Trim(Text.Proper([Name])) // Combine columns in M [CustomerID] & "-" & [Department] // Excel formula (outside PQ) to get column mean for imputation =ROUND(AVERAGE(DirtyData[Age]),0) → use this value in PQ Replace
🚀
Why Power Query matters for ML: When you receive updated data weekly (new customers, new transactions), your cleaning pipeline runs in one click. No manual re-work. This is the difference between a one-time analysis and a production ML system that actually gets maintained.

🏷 Categorical Encoding + Date Features
One-hot encode departments and extract ML-ready date features
Practice
▼
ML algorithms are mathematical — they cannot understand the string "Engineering". You must convert every categorical variable to numbers, and every date to its component features (year, month, day-of-week). This task builds the final feature matrix ready for modeling.
1
Create sheet "Encodelab". Paste your cleaned data (from Power Query output). You'll work with the Department column (4 categories: Eng, Mkt, Sci, Fin) and JoinDate column.
2
One-hot encode Department (4 new columns):
Is_Eng: =IF([@Department]="Eng",1,0)
Is_Mkt: =IF([@Department]="Mkt",1,0)
Is_Sci: =IF([@Department]="Sci",1,0)
(Drop Is_Fin — dummy variable trap: 3 columns fully describe 4 categories)
3
Verify encoding: Add a "Check" column: =Is_Eng+Is_Mkt+Is_Sci+Is_Fin. Every row MUST equal 1. If any row = 0, your category string doesn't match (likely whitespace or case issue — use TRIM/LOWER first).
4
Encode Churned (Yes/No) as binary: =IF([@Churned]="Yes",1,0). This is your target variable — the thing your ML model will predict. Binary targets (0/1) are required for logistic regression and most classifiers.
5
Date feature engineering — extract ML features from JoinDate:
Join_Year: =YEAR([@JoinDate])
Join_Month: =MONTH([@JoinDate])
Join_DayOfWeek: =WEEKDAY([@JoinDate],2) (1=Mon, 7=Sun)
Tenure_Days: =TODAY()-[@JoinDate] (days since joining)
Tenure_Years: =DATEDIF([@JoinDate],TODAY(),"Y")
6
Flash Fill bonus: If you have a "FullName" column ("John Smith"), click in a blank "FirstName" column, type "John" in the first row, then press Ctrl+E. Excel detects the pattern and fills all 60 rows instantly. Do the same for LastName with "Smith".
// One-hot encoding (n categories → n-1 columns) Is_Eng = IF([@Department]="Eng", 1, 0) Is_Mkt = IF([@Department]="Mkt", 1, 0) Is_Sci = IF([@Department]="Sci", 1, 0) // Drop Is_Fin → dummy variable trap (multicollinearity) // Verify: all rows must sum to 1 Check = IF(Is_Eng+Is_Mkt+Is_Sci+Is_Fin=1, "✓ OK", "✗ ERROR") // Binary target variable Churned_Num = IF([@Churned]="Yes", 1, 0) // Date feature engineering Join_Year = YEAR([@JoinDate]) Join_Month = MONTH([@JoinDate]) Join_DOW = WEEKDAY([@JoinDate], 2) Tenure_Days = TODAY()-[@JoinDate] Tenure_Years = DATEDIF([@JoinDate], TODAY(), "Y")
🚨
Dummy Variable Trap: If you create a binary column for EVERY category (4 columns for 4 categories), you have perfect multicollinearity — one column is always perfectly predictable from the others. This crashes regression models. Always use n−1 columns for n categories. The dropped category becomes the "reference" (when all encoded columns = 0).

🏆 Full Clean Pipeline + Final Feature Matrix
Assemble the complete ML-ready feature matrix from scratch in 8 minutes
Project
▼
Assemble everything into the final ML-ready feature matrix. This is the deliverable of Day 4 — a clean, encoded, normalized table that you could hand to any ML algorithm tomorrow. No strings, no blanks, no duplicates, no unscaled features.
1
Create sheet "FinalFeatures". This is your master clean dataset. It should have ONLY numeric columns — no raw text, no dates, no blanks.
2
Include these columns (all numeric): CustomerID, Age_Clean, Income_Clean, Score_Clean, Tenure_Days, Join_Month, Join_DOW, Is_Eng, Is_Mkt, Is_Sci, Age_Was_Imputed, Income_Was_Imputed, Churned_Num (target).
3
Final quality checks — run ALL of these on each column:
Blanks: =COUNTBLANK(col) → must be 0
Non-numeric: =ROWS(col)-COUNT(col) → must be 0
Min: =MIN(col) → check no negative ages/scores
Max: =MAX(col) → check no unrealistic values
Duplicates: =ROWS(A)-SUMPRODUCT(1/COUNTIF(A,A)) → must be 0
4
Data Cleaning Log (Notes sheet): Document every decision you made:
- Rows started: 68 (60 original + 8 duplicates added)
- Duplicates removed: 8
- Age nulls imputed with mean (n=9)
- Income nulls imputed with median (n=7, skewed)
- Department blanks → "Unknown" (n=6)
- Columns dropped: Name, JoinDate (replaced by features)
- Final rows: 60, Final columns: 13
5
Apply Data Validation to prevent future dirty data: Select Age_Clean column → Data → Data Validation → Whole Number → Between 18 and 90. Set error alert: Stop → "Age must be 18–90". Test by typing 150 — it should be rejected.
6
Save as Day4_Complete.xlsx. FinalFeatures sheet is your ML input. Any algorithm — regression, classification, clustering — can now consume this table directly. Congratulations: you've completed a professional data cleaning pipeline.
// Final quality check — run on every column =COUNTBLANK(col) → 0 = no missing values ✓ =ROWS(col)-COUNT(col) → 0 = all numeric ✓ =MIN(col) → check for negatives =MAX(col) → check for outliers // Duplicate check on entire dataset =ROWS(A2:A61)-SUMPRODUCT(1/COUNTIF(A2:A61,A2:A61)) → 0 = no dups ✓ // One-hot sum check (must = 1 for every row) =COUNTIF(Check_Col, "✗ ERROR") → 0 = encoding correct ✓ // Data Validation formula example (custom rule) // =AND(A2>=18, A2<=90) — enter in Data Validation → Custom
🎖️
You now have a professional ML-ready dataset. Every transformation is documented. The data lineage is traceable. New data can flow through Power Query automatically. This is the standard expected in data science teams at tech companies — and you built it in Excel.
