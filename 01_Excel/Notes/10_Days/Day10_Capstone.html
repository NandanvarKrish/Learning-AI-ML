📥 Project Setup & Data Import
Workbook structure, dataset import, and initial data audit
Setup
▼
A professional ML project starts with intentional structure. Every sheet has a purpose. Every column has a type. Every decision is documented. You're not just building a model — you're building an auditable, maintainable data product.
1
Create Day10_Capstone.xlsx. Create these sheets in order (right-click tab → Insert):
📥 RawData — original untouched data
🧹 CleanData — cleaned and encoded data
📊 EDA — charts and statistics
🤖 Model — regression or classifier output
📏 Evaluation — train/test metrics
🚀 ScoringEngine — live prediction tool
📋 ModelCard — documentation
Colour each tab differently for easy navigation.
2
In RawData sheet: manually create your chosen dataset with 80 rows and all required columns. Make it realistic — add natural variation, a few outliers, 5–8% missing values. Convert to Table named RawData.
3
Initial Data Audit (Day 3/4 skills): For each column calculate:
• Row count: =ROWS(RawData)
• Missing %: =COUNTBLANK(col)/80*100
• Data type: text/number/date/boolean
• Min, Max, Mean (for numerics)
Build this as a Quality Audit table in the RawData sheet — 1 row per column.
4
Document your hypothesis: In the ModelCard sheet, write in cell A1: "Project Hypothesis: I predict [feature X] will be the strongest predictor of [target] because [reason]." This written hypothesis is what makes your EDA purposeful rather than exploratory.
// Quality Audit formulas (one row per column) Row_Count = ROWS(RawData[ColumnName]) Missing_Pct = COUNTBLANK(RawData[ColumnName])/80*100 Is_Numeric = ISNUMBER(INDEX(RawData[ColumnName],1)) Min_Val = MIN(RawData[ColumnName]) Max_Val = MAX(RawData[ColumnName]) Mean_Val = AVERAGE(RawData[ColumnName]) Skew_Val = SKEW(RawData[ColumnName])
🎯
Why start with the hypothesis? Analysts who write their hypothesis first build more focused, actionable EDA. Analysts who skip it wander through charts without direction. Your hypothesis will either be confirmed (satisfying) or challenged (even more interesting). Both outcomes make you smarter about the data.

10 – 25 min
🧹 Data Cleaning Sprint + EDA
Full cleaning pipeline in 10 minutes — then 5-question EDA in 5
Practice
▼
After 9 days of practice, this should feel automatic. Apply all cleaning steps systematically, document every decision, then run your EDA framework to answer the 5 critical questions before any model is trained.
1
In CleanData sheet, create a new Table CleanData by copying RawData. Apply the full Day 4 pipeline in order:
① Impute numeric nulls with median
② Impute categorical nulls with "Unknown"
③ Add Was_Imputed flag columns
④ Remove duplicates (check CustomerID / StudentID)
⑤ Fix data types (convert text-as-numbers)
⑥ One-hot encode categorical features
⑦ Extract date features (Year, Month, DOW) if applicable
Log every step in ModelCard sheet.
2
Normalize features for any model that uses distance or regularisation:
Add Z-Score columns for all continuous features: =([@val]-AVERAGE(col))/STDEV.S(col)
Verify: AVERAGE of each Z-Score col ≈ 0, STDEV ≈ 1.
3
In EDA sheet — answer the 5-Question Framework (Day 5) rapidly:
Q1: Target distribution (histogram + skew check)
Q2: Feature correlation with target (RSQ table + bar chart)
Q3: Outlier count per feature (IQR method, 2 mins)
Q4: Feature-feature correlations (4×4 heatmap)
Q5: Group differences (grouped bar chart by main category)
4
Feature selection decision: Based on Q2 and Q4, choose your final features. Rule: keep features with |r| ≥ 0.15 with target AND no pair of kept features with |r| > 0.8 with each other. Write the final list in ModelCard: "Selected Features: [list]".
5
Add EDA Write-up text box in EDA sheet: 5 bullet findings, 1 sentence each. Confirm or refute your hypothesis. This write-up goes verbatim into Section 2 of your ModelCard.
// Full cleaning pipeline summary // Step 1: Median imputation =IF(ISBLANK([@Price]), MEDIAN(RawData[Price]), [@Price]) // Step 2: Categorical imputation =IF(ISBLANK([@Region]), "Unknown", [@Region]) // Step 3: Was_Imputed flag =IF(ISBLANK([@Price]), 1, 0) // Step 4: One-hot encode Region Is_North = IF([@Region]="North", 1, 0) // EDA — feature importance ranking =RSQ(CleanData[Target], CleanData[Feature1]) // Top feature check =INDEX(Feature_names, MATCH(MAX(RSQ_values), RSQ_values, 0))
⏱
Speed target: Cleaning should take ≤8 minutes. EDA should take ≤7 minutes. You've done this 9 times. Trust your muscle memory — move fast, document as you go. The goal isn't perfection, it's systematic completeness.

25 – 38 min
🤖 Model Build & Evaluation
Train/test split → model → metrics → overfitting check
Practice
▼
This is the heart of the capstone — apply the right model for your chosen problem, evaluate it honestly on the test set, and use the Day 9 framework to check for overfitting. By the end of this task, you'll know whether your model is ready to deploy or needs more work.
1
In Model sheet — Train/Test Split:
Copy CleanData to Model sheet. Add Random column → RAND() → immediately freeze (Paste Special → Values). Add Split column: =IF([@Random]<=0.8,"Train","Test"). Verify ~64 Train, ~16 Test.
2
For Regression datasets (House Price, Sales):
Run ToolPak Regression on Train rows using selected features.
Record: β coefficients, R², Adjusted R², Standard Error, p-values per feature.
Apply backward elimination: remove any feature with p > 0.05, re-run, compare Adj R².
3
For Classification datasets (Student Pass, Churn):
Set up logistic regression with Solver (Day 7). Run Solver → record trained β₀, β₁, β₂, β₃.
Calculate Predicted Probability and Predicted Class (threshold = 0.5).
Build Confusion Matrix: TP, TN, FP, FN → Accuracy, Precision, Recall, F1.
4
In Evaluation sheet — Performance Metrics:
Regression: Train MAE, Test MAE, Train RMSE, Test RMSE, MAPE, Gap%
Classification: Train Accuracy/F1, Test Accuracy/F1, Confusion matrix
Apply the overfitting check: Gap% < 20% = ✓ well generalised.
5
Beat the baseline: Calculate baseline metric (always predict mean for regression / majority class for classification). Your model MUST beat this. Record: Model RMSE vs Baseline RMSE, % improvement.
6
Feature importance summary: Sort your features by absolute coefficient value (standardised). Which feature drives predictions most? Does this confirm or challenge your Day 10 hypothesis? Write one paragraph in ModelCard: "Model Findings."
// Train/test split (freeze RAND immediately) =IF([@Random]<=0.8, "Train", "Test") // Regression metrics (test set only) Test_MAE = AVERAGEIF(Split, "Test", Abs_Error_col) Test_RMSE = SQRT(AVERAGEIF(Split, "Test", Sq_Error_col)) Test_MAPE = AVERAGEIF(Split, "Test", MAPE_col) * 100 // Classification metrics (test set) TP = COUNTIFS(Split,"Test", Actual,1, Predicted,1) TN = COUNTIFS(Split,"Test", Actual,0, Predicted,0) FP = COUNTIFS(Split,"Test", Actual,0, Predicted,1) FN = COUNTIFS(Split,"Test", Actual,1, Predicted,0) F1 = 2*TP/(2*TP+FP+FN) // Overfitting check Gap_pct = (Test_RMSE-Train_RMSE)/Train_RMSE*100 Status = IF(Gap_pct<20, "✓ Deploy Ready", "⚠ More Work Needed")
⚠️
If your model fails the overfitting check: Remove your weakest feature (highest p-value or lowest |r|) and re-run. If it still fails with 2 features, your dataset of 80 rows may simply be too small to support a complex model. Simplify — a 2-feature model that generalises well is infinitely more valuable than a 5-feature model that overfits.

🚀 Live Scoring Engine + Model Card
Deploy your model as a self-service prediction tool with full documentation
Project
▼
A model that exists only in a ToolPak output table is not deployed. Deployment means a non-technical stakeholder can enter data and receive a prediction without touching formulas. Your scoring engine achieves this. The model card makes it trustworthy, auditable, and maintainable.
1
In ScoringEngine sheet — build the prediction interface:
Header: Your model name, version, date trained
Yellow input cells (one per feature, with data validation):
Each feature gets a labelled input cell with validation (range limits or dropdown lists)
Grey auto-calculated cells: One-hot encoding, Z-score scaling
Green output cells: Prediction, Confidence/CI, Grade/Risk Level, Recommended Action
2
For Regression scoring engine:
Predicted Value: =ROUND(β₀ + β₁*F1 + β₂*F2 + β₃*F3, 1)
95% Lower: =Predicted - 1.96*StdError
95% Upper: =Predicted + 1.96*StdError
Category: =IFS(Predicted>=Q3,"High",Predicted>=Q1,"Medium",TRUE,"Low")
3
For Classification scoring engine:
Log_Odds: =β₀+β₁*F1+β₂*F2+β₃*F3
Probability: =ROUND(1/(1+EXP(-Log_Odds)),3)
Prediction: =IF(Probability>=0.5,"POSITIVE ✓","NEGATIVE ✗")
Risk Level: =IFS(Prob>=0.8,"Low",Prob>=0.5,"Medium",TRUE,"High")
Action: =SWITCH(Risk,"Low","No action","Medium","Monitor","High","Intervene now")
4
Add Performance Panel (right side): live-linked metrics from Evaluation sheet. Accuracy/RMSE, F1/MAPE, Train/Test gap — all reference Evaluation sheet cells so they're always current.
5
Complete the Model Card in ModelCard sheet:

// Scoring engine — regression prediction Predicted = ROUND(β₀ + β₁*F1 + β₂*F2 + β₃*F3, 1) CI_Lower = Predicted - 1.96*StdErr CI_Upper = Predicted + 1.96*StdErr // Scoring engine — classification prediction Log_Odds = β₀ + β₁*F1 + β₂*F2 + β₃*F3 Prob = ROUND(1/(1+EXP(-Log_Odds)), 3) Prediction= IF(Prob>=0.5, "POSITIVE ✓", "NEGATIVE ✗") Confidence= TEXT(MAX(Prob,1-Prob),"0%") & " confident" // Protect the scoring engine // Review → Protect Sheet → allow Select Unlocked Cells only // Users can type in yellow cells but can't break formulas

🏆 Final Dashboard + 2-Minute Presentation
Assemble the complete project and prepare your confident 2-minute pitch
Capstone
▼
The last 10 minutes are about communication, not computation. Your model is built. Now you present it. A 2-minute structured pitch — Problem, Data, Method, Result, Limitation, Next Step — is the professional standard for presenting ML work to any audience, technical or not.
1
Create sheet "FinalDashboard". This is your one-page project summary. It should tell the complete story at a glance:
Top left: Project title, dataset, date
Top right: 4 KPI tiles (train rows, test rows, primary metric, baseline comparison)
Middle left: Best chart from your EDA (feature importance or target distribution)
Middle right: Performance metrics table (Train vs Test)
Bottom: Scoring engine preview (3 test scenarios with predictions)
Very bottom: 3-bullet limitations
2
3 test scenarios table: Create 3 rows of input data (e.g., high performer, average, at-risk). Apply your scoring engine formula to each. Show: Inputs | Predicted Value | Confidence | Risk Level | Action. This is the most convincing section — it shows the model making real, explainable predictions.
3
Comparison chart — Model vs Baseline: Build a bar chart comparing your model's Test RMSE or F1 vs the baseline. Add a data label showing % improvement. This single chart answers the most important stakeholder question: "Is the model worth using?"
4
Write your 2-Minute Pitch in the ModelCard sheet (Section: Presentation Script):
🎯 Problem (15 sec): "We want to predict [target] because [business reason]."
📊 Data (15 sec): "We used [N] rows, [K] features, cleaned using [methods]."
🤖 Method (20 sec): "We built a [model type] using [features]. The key finding from EDA was [insight]."
📏 Result (30 sec): "Test [metric] = [value], [X]% better than baseline. The model [does/doesn't] generalise well (gap = [X]%)."
⚠️ Limitation (20 sec): "Key limitation: [most important limitation]. We should not use this model for [specific out-of-scope case]."
🚀 Next Step (20 sec): "The immediate next step is [action]. In Python, this model would scale to [N] rows."
5
Final quality checklist: Before saving, verify ALL of the following:
☐ All 7 sheets complete and properly named
☐ Model trained on Train rows only
☐ Test RMSE or F1 better than baseline
☐ Gap% within acceptable range (no severe overfitting)
☐ Scoring engine works (change inputs → output updates)
☐ Model Card all 12 fields filled
☐ Presentation script written
☐ FinalDashboard tells the story at a glance
Save as Day10_Capstone_Final.xlsx.
