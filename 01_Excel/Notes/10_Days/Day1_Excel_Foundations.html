🔢 Data Types — Why They Matter for ML CRITICAL
Numbers stored as text return SUM=0. This silently breaks every formula and ML calculation. Always verify types before analysis — it takes 10 seconds and prevents hours of debugging.
TypeHow to DetectFix FormulaML Impact
NumberRight-aligned in cellAlready numeric ✓Works correctly
Text-as-NumberLeft-aligned, green triangle=VALUE(A1)SUM=0, breaks models
DateRight-aligned, date format=DATEVALUE(A1)Extract YEAR/MONTH features
BooleanALL CAPS, centered=A1*1 (TRUE→1)Direct use in models
Error#VALUE!, #N/A, #REF!=IFERROR(A1,0)Propagates everywhere
📌 Cell References — Absolute vs Relative CORE
Press F4 while editing a formula to cycle through all 4 reference modes. Constants (tax rates, model coefficients) must always be absolute ($). Row values must always be relative.
// 4 modes — press F4 to cycle A1 → Relative: both row and col shift when copied $A1 → Mixed: col fixed, row moves A$1 → Mixed: row fixed, col moves $A$1 → Absolute: nothing changes when copied // Example: tax rate in C1, revenue in B5:B24 =B5*(1-$C$1) → B5 shifts per row, $C$1 always = tax rate
📋 Format as Table (Ctrl+T) POWER USER
Tables give you structured references, auto-expansion, built-in filters, and make PivotTables and Power Query work seamlessly. Start every ML project with a Table.
// Structured references (Table named "StudentData") =StudentData[Score] → Entire Score column =StudentData[@Score] → This row's Score value =AVERAGE(StudentData[Score]) → Column average =AVERAGE(AllScores) → Named range — most readable

🔢 Data Types Laboratory
Detect and fix the silent killer of ML models
Practice
▼
Numbers stored as text give SUM=0 and break every ML model silently. You must be able to detect and fix this in under 30 seconds — it's a daily skill on every real project.
1
Create sheet "TypesLab". Build a 10-row table: Name (text), Score (number), Date (date), Pass (TRUE/FALSE), Revenue (currency).
2
Format column G as Text (Ctrl+1 → Text). Enter "95", "82", "76". Notice left-alignment. Try =SUM(G2:G4) → returns 0. This is the bug.
3
Fix: In column H use =VALUE(G2). Also try: select G2:G4 → Data → Text to Columns → Finish. Check alignment changed to right.
4
Boolean encoding: Column I = TRUE/FALSE. Column J = =I2*1 → converts TRUE→1, FALSE→0. This is the start of one-hot encoding for ML.
5
Extract date ML features: =YEAR(D2), =MONTH(D2), =WEEKDAY(D2,2). These become time-series features in predictive models.
=VALUE(A2) → Text "123" becomes number 123 =ISNUMBER(A2) → TRUE if stored as number =ISTEXT(A2) → TRUE if stored as text (bug detector) =YEAR(D2) → Extract year (ML time feature) =WEEKDAY(D2,2) → Day of week 1–7
⚠️
Always run =ISNUMBER() checks on feature columns. A quick =SUM() returning 0 on "numbers" = text-as-number bug. Fix before any analysis.

📌 Cell References Exercise
Change 1 cell → watch 20 rows update instantly
Practice
▼
Build a profit model where changing one constant updates all rows instantly. Same logic powers ML scoring engines — change coefficients, all predictions update automatically.
1
Create sheet "RefCalc". B1 = "Tax Rate", C1 = 0.18. B2 = "Discount", C2 = 0.10. These are your absolute-reference constants.
2
A5:A24 = 20 product names. B5:B24 = revenues (1000–5000). C5:C24 = costs (200–800).
3
D5 = =B5-C5 (gross profit, fully relative). E5 = =D5*(1-$C$2). F5 = =E5*(1-$C$1).
4
Copy D5:F5 → select D6:F24 → paste. Check: D6 = =B6-C6 (relative shifted ✓). F6 still shows $C$1 (absolute fixed ✓).
5
The proof: Change C1 from 0.18 → 0.25. All 20 rows in col F update instantly. Change C2 → col E updates. One cell, 20-row impact.
6
Add summary: Total Revenue =SUM(B5:B24), Net Profit =SUM(F5:F24), Avg Margin =SUM(F5:F24)/SUM(B5:B24). Format as currency and %.
=B5-C5 → Gross Profit (fully relative) =D5*(1-$C$2) → After discount ($C$2 absolute) =E5*(1-$C$1) → After tax ($C$1 absolute) // Copied to row 6: =B6-C6 → Row shifted correctly ✓ =E6*(1-$C$1) → $C$1 stayed fixed ✓
🧠
Rule: Any value that must NEVER change when copied = use $. Constants, model coefficients, lookup ranges → always absolute (F4). Row values → always relative.
