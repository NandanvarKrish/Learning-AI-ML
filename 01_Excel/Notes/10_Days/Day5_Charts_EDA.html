🧠 Key Concepts Deep Dive
📊 Chart Types — Right Chart, Right Question CHOOSE CORRECTLY
Using the wrong chart type is worse than no chart — it misleads. A pie chart with 8 slices is unreadable. A line chart for categorical data implies trends that don't exist. Know which chart answers which question.
🔵
Scatter Plot
Relationship between two numeric features. Add trendline for R².
Feature vs Target
📊
Histogram
Distribution shape of a single numeric variable. Bins = data buckets.
Distribution
📦
Box Plot
Q1–Q3 range, median, whiskers, outlier dots. Compare groups.
Outliers + Groups
🌡️
Heatmap
Color-coded matrix — correlation tables, confusion matrices.
Correlation Matrix
📉
Line Chart
Trends over time. Only use when X-axis is truly time or ordered.
Time Series
🥧
Pie Chart
Parts of a whole — max 4 slices. Hard to compare precisely.
Use Bar Instead
🔍 The 5-Question EDA Framework ALWAYS ASK THESE
Every EDA should answer exactly these 5 questions before any model is trained. If you can't answer all 5, you don't understand your data well enough to build a reliable model.
1
What does the target variable look like?
Distribution shape, range, skew. For classification: class balance (are labels 50/50 or 95/5?). → Build histogram + count by class.
2
Which features correlate with the target?
Scatter each feature vs target. Calculate r. Rank by |r|. Features with |r| < 0.1 are weak candidates. → Scatter matrix or correlation bar chart.
3
Are there outliers and how extreme are they?
Box plots per feature. IQR method. Do outliers appear in features that strongly predict the target? → Box plot grid + outlier count table.
4
Do features correlate with each other?
Correlation heatmap. Flag pairs with |r| > 0.7 — multicollinearity risk. → Colour-coded correlation matrix from Day 3.
5
Are there patterns across categories?
Average target per category group. Do Engineering students score higher? Does churn vary by region? → Grouped bar chart or pivot.
🔵 Scatter Plots & R² — Predictive Power Score FEATURE SELECTION
R² (R-squared) on a scatter trendline tells you what % of the target variable's variation is explained by that single feature. R²=0.70 means the feature explains 70% of the target's movement — that's a powerful predictor. R²=0.01 means almost no linear relationship.
// Build scatter: Insert → Chart → X Y (Scatter) // X-axis = feature column, Y-axis = target column // Add trendline: right-click a data point → Add Trendline // → Linear → check ✓ Display Equation → check ✓ Display R-squared // R² interpretation guide: // R² > 0.7 → Strong predictor → Include in model ✓ // R² 0.3–0.7→ Moderate predictor → Likely include ✓ // R² 0.1–0.3→ Weak predictor → Investigate further // R² < 0.1 → Very weak → Probably exclude ✗ // Calculate R² without chart (for all features at once): =RSQ(target_range, feature_range) → R² value 0–1 =CORREL(target, feature)^2 → Same as RSQ (r²) // Rank features by R² in a table: // Feature | r | r² | Rank — sort by r² descending
🎨 Dashboard Design Principles STORYTELLING
A dashboard isn't a collection of charts — it's a narrative. Each chart answers one specific question. The layout guides the reader from summary to detail. Colour should encode meaning, not decoration. Labels should eliminate ambiguity.
// Layout hierarchy (Z-pattern reading order): // TOP-LEFT: Title + key insight headline // TOP-RIGHT: Most important chart (target distribution) // MIDDLE: Supporting charts (feature relationships) // BOTTOM: Detail tables or drill-down data // Colour rules for ML dashboards: // ✓ Use ONE accent colour for "good/high" values // ✓ Use red ONLY for problems, outliers, errors // ✓ Use grey for context/background data // ✗ Never use 5+ colours in one chart // ✗ Never use 3D charts — they distort proportions // ✗ Never use gridlines heavier than the data itself // Every chart needs: // • Descriptive title (not "Chart 1" — "Score vs Study Hours") // • Axis labels with units // • Data source note // • One-sentence insight caption below

📊 EDA Chart Set — The Core 4
Build histogram, scatter, box plot, and grouped bar chart for any dataset
Practice
▼
Every ML EDA starts with the same four charts. Together they answer: what does the data look like (histogram), how do features relate to the target (scatter), where are the outliers (box plot), and how do groups compare (bar chart). Build all four in 15 minutes.
1
Open your Day4_Complete.xlsx or create Day5_EDA.xlsx with a fresh 80-row dataset. Columns: StudentID, Score (target), StudyHours, Attendance, Income, Department. Convert to a Table named EDAData.
2
Chart 1 — Histogram of Score (target variable):
Select Score column → Insert → Charts → Insert Statistic Chart → Histogram.
Right-click X-axis → Format Axis → set Bin Width to 5 (or "Number of bins" = 12).
Title: "Score Distribution". Remove gap between bars (Format Data Series → Gap Width: 0%).
Add a text box: "Shape: [normal/skewed/bimodal]?" — fill in your observation.
3
Chart 2 — Scatter: StudyHours vs Score:
Select StudyHours and Score columns (Ctrl+click) → Insert → X Y Scatter → Scatter.
Right-click any data point → Add Trendline → Linear → check ✓ Display R-squared.
Title: "Study Hours vs Score". X-label: "Study Hours/Day". Y-label: "Exam Score".
Read the R² value. Write it in a cell next to the chart with interpretation.
4
Chart 3 — Box Plot:
Select Score column → Insert → Insert Statistic Chart → Box and Whisker.
This shows Q1 (bottom of box), Median (middle line), Q3 (top of box), and outlier dots.
Right-click → Format Data Series → check ✓ Show Mean Markers (X symbol).
Compare the Mean marker vs Median line — if they're far apart, the data is skewed.
5
Chart 4 — Grouped Bar: Average Score by Department:
First build a summary table: AVERAGEIF for each department (Eng, Mkt, Sci, Fin).
Select the 2-column summary table → Insert → Column Chart → 2D Clustered Column.
Title: "Average Score by Department". Sort bars from highest to lowest for readability.
// Summary table for grouped bar chart =AVERAGEIF(EDAData[Department], "Eng", EDAData[Score]) =AVERAGEIF(EDAData[Department], "Mkt", EDAData[Score]) =AVERAGEIF(EDAData[Department], "Sci", EDAData[Score]) =AVERAGEIF(EDAData[Department], "Fin", EDAData[Score]) // Calculate R² for any feature vs target =RSQ(EDAData[Score], EDAData[StudyHours]) → R² value =CORREL(EDAData[Score], EDAData[StudyHours]) → r value (R² = r²) // Rank all features by R² with target // Build a table: Feature | r | R² | Rank // Sort R² column descending = feature importance ranking
💡
Chart formatting quick wins: Delete chart gridlines (click → Delete). Remove chart border (Format Chart Area → No border). Use soft grey (#999) for axes. Make your title bigger and bolder than axis labels. Less ink = more signal.

Scatter + trendline + R²
Box plot with mean marker
Grouped bar by Department
All charts titled + labelled

15 – 28 min
🌡️ Correlation Heatmap + Feature R² Ranking
Visualize which features matter most — your first feature importance chart
Practice
▼
A correlation heatmap instantly shows you which features are related to each other and to the target. Combined with an R² ranking bar chart, this is the visual equivalent of feature importance scores in scikit-learn — built entirely in Excel.
1
Build a 4×4 correlation matrix (from Day 3, or rebuild here) for Score, StudyHours, Attendance, Income using CORREL(). Round to 2 decimal places with =ROUND(CORREL(...),2). Label both row and column headers clearly.
2
Apply heatmap formatting: Select the 4×4 value cells → Home → Conditional Formatting → Color Scales → More Rules → 3-Color Scale:
Minimum: −1 → Red (#FF4444)
Midpoint: 0 → White (#FFFFFF)
Maximum: +1 → Green (#00AA66)
Now the matrix is a visual heatmap — dark green = strong positive, dark red = strong negative, white = no relationship.
3
Add data labels inside the heatmap cells: select the 4×4 area → Home → Conditional Formatting → New Rule → Format only cells containing → Cell Value → between −0.1 and 0.1 → set font to grey. This dims weak correlations visually, making strong ones pop.
4
Feature R² ranking bar chart: Build a 2-column table: Feature name | R² with Score. Sort by R² descending. Insert → Bar Chart (horizontal bars are easier to read with text labels). Title: "Feature Predictive Power (R²)". This IS your feature importance chart.
5
Add data bars inside the R² column: Select R² values → Conditional Formatting → Data Bars → Solid Fill → green. Now each cell shows a mini bar representing its R² value — a micro-chart inside the table itself.
6
Annotation: Add a text box on the heatmap chart: "⚠ High correlation between [Feature A] and [Feature B] (r=0.84) — multicollinearity risk. Consider dropping one before regression." This is the analyst's voice — essential in any EDA report.
// Correlation matrix cell formula =ROUND(CORREL(EDAData[Score], EDAData[StudyHours]), 2) // R² for feature importance table =RSQ(EDAData[Score], EDAData[StudyHours]) → 0.65 = "65% of Score explained" =RSQ(EDAData[Score], EDAData[Attendance]) → compare all features =RSQ(EDAData[Score], EDAData[Income]) → likely low for income // Highest-impact feature (no MAXIFS needed — manual sort) // Sort R² table descending → top row = best predictor // Conditional formatting for data bars on R² column // Home → Conditional Formatting → Data Bars → Solid Fill → green // Set Max = 1.0 (so bars are proportional to perfect R²=1)
🧠
This IS feature selection: In production ML with scikit-learn, you'd run feature_importances_ on a Random Forest or calculate correlation with the target. What you just built in Excel is the same concept — ranking features by how much of the target's variance they explain.

28 – 42 min
📦 Box Plot Grid + Distribution Analysis
Compare all features side-by-side and answer EDA questions 1, 2, and 3
Practice
▼
A grid of box plots reveals outliers, spread, and group differences simultaneously. This is the most information-dense chart type for EDA — one box plot tells you min, Q1, median, Q3, max, and individual outliers all at once.
1
Box plot per feature: Create 3 box plots (Score, StudyHours, Attendance) side-by-side on one chart.
Select Score, StudyHours, Attendance columns → Insert → Statistic Chart → Box and Whisker.
Excel plots all three series on one chart — each box represents one feature's distribution.
2
Format for readability:
Right-click → Format Data Series → check ✓ Show Inner Points (shows all data dots), ✓ Show Mean Markers.
Make each series a different colour — right-click each box → Fill → pick green, blue, orange.
Title: "Feature Distribution Comparison". This single chart replaces 3 separate box plots.
3
Box plot by category (Score by Department):
This requires a separate layout. Create 4 columns: Score_Eng, Score_Mkt, Score_Sci, Score_Fin — each containing ONLY scores for that department (use filters or FILTER function if 365).
Select all 4 columns → Box and Whisker chart.
Now you can compare: do students in one department consistently score higher?
4
Score by Department — helper formula (365): =FILTER(EDAData[Score], EDAData[Department]="Eng") — creates a spill range of just Engineering scores. Repeat for each department. Use these ranges as chart source data.
5
EDA Question 3 answer — outlier summary table: For each feature build a row: Feature | Outlier Count | Outlier % | Min Outlier | Max Outlier. Use your IQR formulas from Day 3. Which feature has the most outliers? Are they the same rows across features?
6
Same-row outlier check: Add a column "Multi_Outlier": =IF(AND(Score_Outlier="OUTLIER", Income_Outlier="OUTLIER"), "BOTH", "Single"). A student who is an outlier on BOTH score AND income might represent a very different population — worth flagging for model review.
// Filter scores by department (Excel 365 dynamic array) =FILTER(EDAData[Score], EDAData[Department]="Eng") // Without 365 — use AVERAGEIF for each (less powerful) =AVERAGEIF(EDAData[Department], "Eng", EDAData[Score]) // Outlier count per feature (from Day 3 IQR flags) =COUNTIF(EDAData[Score_Outlier], "OUTLIER") // Cross-feature outlier check =SUMPRODUCT((EDAData[Score_Outlier]="OUTLIER")*(EDAData[Income_Outlier]="OUTLIER")) // Outlier impact: how much does mean change if we remove outliers? =AVERAGEIF(EDAData[Score_Outlier], "Normal", EDAData[Score]) → mean without outliers =AVERAGE(EDAData[Score]) → mean with outliers
⚠️
Box plots in Excel limitation: Excel's Box and Whisker chart does not easily support custom IQR bounds or showing individual outlier rows. For precise outlier investigation, use your manual IQR columns from Day 3. The box plot is for visual communication — the formulas are for precision.

📋 Interactive EDA Dashboard with Slicers
Combine all charts into one self-service dashboard stakeholders can explore
Project
▼
An EDA dashboard lets stakeholders explore the data without knowing Excel. Slicers turn category filters into one-click buttons. When a stakeholder clicks "Engineering", all charts update to show Engineering-only data. This is professional, production-grade data communication.
1
Create a new sheet "EDA_Dashboard". Set tab colour to green (right-click tab → Tab Color). Set zoom to 85% so more fits on screen. Set all cells to no fill (white background, no gridlines visible — View → uncheck Gridlines).
2
Dashboard title section (Row 1–3): Merge cells A1:L1. Type: "Student Performance — EDA Dashboard". Font: 20pt, bold. Subheading in row 2: "Exploratory Data Analysis | 80 Students | Data as of [date]". Add a thin bottom border under row 3.
3
Add KPI summary row (Row 4–7): 4 boxes side-by-side showing: Avg Score, Pass Rate %, Top Score, Outlier Count. Use formulas referencing your EDAData table. Format each as a card — coloured background, large number, small label below.
4
Place charts: Copy your 4 charts from Task 1 onto the dashboard. Arrange in a 2×2 grid. Resize all charts to the same width and height (hold Alt while dragging to snap to cell grid). Top row: Histogram + Scatter. Bottom row: Box Plot + Grouped Bar.
5
Add a Slicer: Click inside your EDAData Table → Insert tab → Slicer → select "Department" → OK. A slicer panel appears. Place it on the left of the dashboard. Slicer Design tab → set Slicer Style to match your colour scheme. Test clicking each department — do the KPIs update? (They will if formulas reference the Table.)
6
Connect slicer to a PivotTable (for charts to filter): If charts don't filter with the slicer, you need a PivotChart. Insert → PivotTable → from EDAData → place in dashboard sheet. Build grouped bar from PivotTable. Right-click slicer → Report Connections → check your PivotTable. Now the slicer filters the chart.
// KPI box formulas — reference Table so slicer-connected PivotTable updates them Avg Score = AVERAGE(EDAData[Score]) Pass Rate = COUNTIF(EDAData[Score],">=70")/ROWS(EDAData[Score]) Top Score = MAX(EDAData[Score]) Outliers = COUNTIF(EDAData[Score_Outlier],"OUTLIER") // Slicer steps: // 1. Click in Table → Insert → Slicer → Department → OK // 2. Slicer appears as floating panel — drag to position // 3. Slicer Design → choose a style matching your theme // 4. Multi-select: hold Ctrl while clicking slicer buttons // 5. Clear filter: click X button top-right of slicer
🎯
Pro dashboard tip: Lock your dashboard so users can't accidentally edit it. Review tab → Protect Sheet → allow only "Select unlocked cells". Users can click slicers and scroll but can't break formulas. Unprotect with your password when you need to edit.

📝 EDA Write-up + Sparklines + Final Findings
Document your 5 EDA findings and add sparklines for compact trends
Write-up
▼
An EDA without a written findings section is incomplete. Charts answer questions visually — but stakeholders need to know WHAT you found, WHAT it means, and WHAT to do next. This is the analyst's voice: the 8-minute write-up that makes your 52-minute analysis actionable.
1
Add Sparklines to your summary table: Select an empty column next to your feature stats table. Insert → Sparklines → Line (or Column). Select the data range for each feature's values. Sparklines appear as tiny inline charts — no separate chart needed. They show trend at a glance.
2
EDA Findings text box on dashboard: Insert → Text Box → draw a panel on the dashboard. Type your 5 findings — one per EDA question:
Q1 (Target): Score distribution is roughly normal, mean=74.2, slight right skew (SKEW=0.3). No class imbalance issue.
Q2 (Features): StudyHours is the strongest predictor (R²=0.68). Attendance is moderate (R²=0.41). Income has no relationship (R²=0.02).
Q3 (Outliers): 4 outliers detected in Score (IQR method). All 4 are high scorers — genuine extreme performers, not data errors.
Q4 (Multicollinearity): StudyHours and Attendance correlate at r=0.61 — moderate. Worth monitoring in regression but not critical.
Q5 (Categories): Engineering students average 79.3 vs Marketing at 68.1. Department is a significant predictor — include in model.
3
Recommendations section: Below findings, add: "Model Recommendations: (1) Include StudyHours + Attendance + Department_encoded. (2) Drop Income — no predictive power. (3) Consider log transform if using regression (slight skew). (4) No imputation needed — 0 missing values." This is a model card prototype.
4
Add a scatter matrix summary: Build a small 3×3 table of RSQ values for all feature pairs vs Score. Apply data bars. This is your feature importance scoreboard — the go-to reference when building the model on Day 6.
5
Save as Day5_Complete.xlsx. Your EDA Dashboard sheet should be fully self-contained: data story, charts, KPIs, slicer, findings text, and recommendations. This is the professional standard for presenting EDA to a data science team or business stakeholder.
// Add sparklines: Insert → Sparklines → Line // Data Range: your values row | Location Range: single cell for each // Sparkline Design → Show: ✓ High Point (green dot), ✓ Low Point (red dot) // Feature importance summary table // StudyHours vs Score: =RSQ(EDAData[Score], EDAData[StudyHours]) → e.g. 0.68 // Attendance vs Score: =RSQ(EDAData[Score], EDAData[Attendance]) → e.g. 0.41 // Income vs Score: =RSQ(EDAData[Score], EDAData[Income]) → e.g. 0.02 // Sort RSQ table: Data → Sort → RSQ column → Largest to Smallest // = your feature ranking / selection list for Day 6 regression
🎖️
The EDA write-up is not optional: In professional data science teams, the EDA document is reviewed before any model code is written. It proves you understand your data, prevents wasted modeling effort on useless features, and provides an audit trail for model decisions. Your Day 5 dashboard IS that document.

📊
Day 5 Pro Tip — EDA Generates Hypotheses, Not Answers
The goal of EDA is not to summarize the data — it's to generate hypotheses about what your model will find. Every chart should end with a question: "StudyHours has R²=0.68 with Score — will it remain the top predictor after controlling for Attendance?" EDA is how you have an intelligent conversation with your data before you train anything. The analyst who skips EDA is the analyst whose model fails in production.
