Abstract Base Classes (ABCs)

Enforcing that subclasses implement required methods

An abstract base class defines a CONTRACT — methods that every subclass MUST implement. It cannot be instantiated directly; it exists purely to be inherited from.

PYTHON
from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def area(self):
        pass   # no implementation — subclasses MUST override this

    @abstractmethod
    def perimeter(self):
        pass

# Shape()   ❌ TypeError: Can't instantiate abstract class Shape

class Rectangle(Shape):
    def __init__(self, width, height):
        self.width = width
        self.height = height

    def area(self):
        return self.width * self.height

    def perimeter(self):
        return 2 * (self.width + self.height)

# If Rectangle forgot to implement perimeter(), instantiating it would ALSO raise TypeError
r = Rectangle(4, 5)
print(r.area())   # 20
💡 Why Use ABCs Instead of Just Regular Inheritance?
Without ABC, if a subclass forgets to implement area(), you'd only find out at RUNTIME when someone calls it (an AttributeError or wrong behavior). With ABC, Python refuses to even CREATE an incomplete subclass instance — catching the mistake immediately, not later.

@dataclass — Eliminating Boilerplate

Auto-generating __init__, __repr__, and __eq__

PYTHON
# BEFORE — a "plain" class needs manual boilerplate
class PointOld:
    def __init__(self, x, y):
        self.x = x
        self.y = y
    def __repr__(self):
        return f"PointOld(x={self.x}, y={self.y})"
    def __eq__(self, other):
        return self.x == other.x and self.y == other.y

# AFTER — @dataclass generates ALL of that automatically
from dataclasses import dataclass, field

@dataclass
class Point:
    x: int
    y: int
    label: str = "origin"   # default value

p1 = Point(3, 4)
p2 = Point(3, 4)
print(p1)             # Point(x=3, y=4, label='origin') — __repr__ auto-generated
print(p1 == p2)      # True — __eq__ auto-generated, compares field values

# Mutable defaults need field(default_factory=...) — NEVER use a raw mutable default
@dataclass
class Cart:
    items: list = field(default_factory=list)   # NOT items: list = []

# frozen=True makes instances IMMUTABLE (like a tuple)
@dataclass(frozen=True)
class ImmutablePoint:
    x: int
    y: int
# ip.x = 5   ❌ FrozenInstanceError
⚠️ Never Use a Mutable Default Directly
items: list = [] would cause ALL instances to SHARE the same list object — a classic, dangerous Python bug. field(default_factory=list) ensures each instance gets its OWN fresh empty list.

classmethod, staticmethod & property

Three special method decorators every class should know

PYTHON
class Employee:
    company = "Acme Corp"   # CLASS attribute, shared by all instances

    def __init__(self, name, salary):
        self.name = name
        self._salary = salary   # leading underscore = "internal, don't touch directly"

    # INSTANCE method — needs self, operates on ONE object
    def give_raise(self, amount):
        self._salary += amount

    # CLASSMETHOD — receives the CLASS (cls), not an instance; used for alternative constructors
    @classmethod
    def from_string(cls, data_string):
        name, salary = data_string.split(",")
        return cls(name, float(salary))   # cls(...) == Employee(...)

    # STATICMETHOD — no self OR cls; just a regular function logically grouped in the class
    @staticmethod
    def is_valid_salary(amount):
        return amount > 0

    # PROPERTY — access a method like an attribute, no parentheses needed
    @property
    def salary(self):
        return self._salary

    @salary.setter
    def salary(self, value):
        if value < 0:
            raise ValueError("Salary cannot be negative")
        self._salary = value

e = Employee.from_string("Sam,50000")   # alternative constructor
print(Employee.is_valid_salary(-5))   # False — called on the CLASS, no instance needed
print(e.salary)                     # calls the getter — looks like an attribute, IS a method
e.salary = 55000                     # calls the setter — validates before assigning

Multiple Inheritance & MRO

Method Resolution Order — which parent's method wins?

PYTHON
class Flyer:
    def move(self):
        return "Flying"

class Swimmer:
    def move(self):
        return "Swimming"

# Multiple inheritance — Duck inherits from BOTH classes
class Duck(Flyer, Swimmer):
    pass

d = Duck()
print(d.move())   # "Flying" — Flyer comes FIRST in the inheritance list, so it takes priority

# See the exact resolution order Python uses to search for methods
print(Duck.__mro__)
# (<class 'Duck'>, <class 'Flyer'>, <class 'Swimmer'>, <class 'object'>)

# super() cooperatively calls the NEXT class in the MRO chain
class Base:
    def greet(self):
        print("Base greet")

class Child(Base):
    def greet(self):
        super().greet()   # calls Base's greet() FIRST
        print("Child greet")

Child().greet()   # "Base greet" then "Child greet"
⚠️ Order Matters in Multiple Inheritance
class Duck(Flyer, Swimmer) and class Duck(Swimmer, Flyer) behave DIFFERENTLY when both parents define the same method — Python searches LEFT TO RIGHT (following the MRO, computed via the C3 linearization algorithm). Always check ClassName.__mro__ if you're unsure which method will actually run.

Metaclasses — A Brief Introduction

Classes that create classes

Just as a class is a "blueprint" for creating objects, a metaclass is a blueprint for creating CLASSES themselves. This is advanced, rarely-needed territory — but understanding it deepens your grasp of Python's object model.

PYTHON
# Every class's type is 'type' — the default metaclass
print(type(int))      # <class 'type'>
print(type(Duck))    # <class 'type'> — Duck's type IS 'type'

# A custom metaclass — controls HOW classes using it are constructed
class UpperAttrMeta(type):
    def __new__(cls, name, bases, namespace):
        # uppercase all non-dunder attribute names at class-creation time
        new_namespace = {
            (key.upper() if not key.startswith('__') else key): value
            for key, value in namespace.items()
        }
        return super().__new__(cls, name, bases, new_namespace)

class MyClass(metaclass=UpperAttrMeta):
    x = 5   # will be renamed to X during class creation

print(MyClass.X)   # 5 — accessible as X, not x!
💡 "Metaclasses are deeper magic than 99% of users should ever worry about"
This quote (paraphrased from Tim Peters, a Python core contributor) is genuinely good advice. Frameworks like Django ORM use metaclasses internally, but as an application developer you'll rarely write your own. Understanding the CONCEPT (classes are objects too, created by a metaclass) is valuable; writing custom metaclasses is a rare, advanced need.

📋 Project Brief

Build an extensible payment processing system where new payment methods can be "plugged in" as subclasses, enforced by an abstract base class, using dataclasses for transaction records.

Define the ABC

from abc import ABC, abstractmethod
from dataclasses import dataclass, field
from datetime import datetime

class PaymentMethod(ABC):
    @abstractmethod
    def process(self, amount):
        pass

    @abstractmethod
    def fee_percentage(self):
        pass

Build 2 Concrete Payment Methods

Create CreditCard and BankTransfer classes inheriting from PaymentMethod. CreditCard has a 2.9% fee; BankTransfer has a flat $0.50 fee. Each process(amount) should return the amount after fees are deducted.
