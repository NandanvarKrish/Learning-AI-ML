The Iterator Protocol

What actually happens when you write `for x in something`

Every for loop in Python relies on two special methods: __iter__ and __next__. Understanding this protocol demystifies loops, generators, and many built-in functions.

🔁 The Two-Part Protocol
Iterable → an object with __iter__() that RETURNS an iterator (e.g., a list)
Iterator → an object with __next__() that returns the NEXT value, or raises StopIteration
A for-loop calls iter(obj) once, then next(iterator) repeatedly until StopIteration is raised.
PYTHON
# What a for-loop actually does, under the hood
numbers = [10, 20, 30]

# for x in numbers:  is roughly equivalent to:
iterator = iter(numbers)     # calls numbers.__iter__()
while True:
    try:
        x = next(iterator)   # calls iterator.__next__()
        print(x)
    except StopIteration:
        break

# Building a CUSTOM iterator class
class Countdown:
    def __init__(self, start):
        self.current = start

    def __iter__(self):
        return self   # the object itself IS the iterator

    def __next__(self):
        if self.current <= 0:
            raise StopIteration
        self.current -= 1
        return self.current + 1

for n in Countdown(5):
    print(n)   # 5 4 3 2 1
💡 Iterable vs Iterator — Not the Same Thing
A list is iterable (you can loop over it) but is NOT itself an iterator — calling iter() on it produces a separate iterator object. This is why you can loop over the same list multiple times: each for loop gets a FRESH iterator.

Generators — Lazy Evaluation with yield

Writing iterators without the boilerplate class

A generator function (any function containing yield) automatically creates an iterator for you — no manual __iter__/__next__ needed. Values are produced LAZILY, one at a time, only when requested.

PYTHON
# The SAME countdown, written as a generator — far less code
def countdown(start):
    while start > 0:
        yield start   # pauses here, returns start, resumes on next call
        start -= 1

for n in countdown(5):
    print(n)   # 5 4 3 2 1

# Calling a generator function does NOT run the code — it returns a generator object
gen = countdown(3)
print(gen)          # <generator object countdown at 0x...>
print(next(gen))    # 3 — runs until the first yield
print(next(gen))    # 2 — resumes from where it paused

# MEMORY EFFICIENCY: generators don't build the whole sequence in memory
def infinite_counter():
    n = 0
    while True:
        yield n
        n += 1
# range(10**12) as a list would exhaust memory; a generator handles it fine

# Real use case: reading a huge file LINE BY LINE without loading it all
def read_large_file(path):
    with open(path) as f:
        for line in f:
            yield line.strip()

Return a listEntire result stored at onceNeed random access, small data

Generator Expressions

PYTHON
# List comprehension — builds the WHOLE list in memory immediately
squares_list = [x**2 for x in range(1000000)]

# Generator expression — same syntax but with () instead of [] — LAZY, no memory blowup
squares_gen = (x**2 for x in range(1000000))

# Great for feeding directly into functions like sum() — never materializes the full list
total = sum(x**2 for x in range(100))

Useful Iterator Tools

itertools and built-ins that work with any iterable

PYTHON
import itertools

# zip — pairs up multiple iterables together
names = ["A","B","C"]
scores = [90,85,70]
for name, score in zip(names, scores):
    print(name, score)

# enumerate — get index + value together
for i, name in enumerate(names, start=1):
    print(i, name)

# itertools.count — infinite counter (careful with loops!)
for i in itertools.count(10, 2):   # start=10, step=2
    if i > 20: break
    print(i)   # 10 12 14 16 18 20

# itertools.chain — combine multiple iterables into one sequence
combined = itertools.chain([1,2], [3,4])
print(list(combined))   # [1, 2, 3, 4]

Decorators — Wrapping Functions

Adding behavior to a function without changing its code

A decorator is a function that takes another function and returns a modified version of it — used to add logging, timing, access control, and more, without touching the original function's body.

PYTHON
# The core idea: functions are objects — they can be passed as arguments and returned
def my_decorator(func):
    def wrapper(*args, **kwargs):
        print(f"Calling {func.__name__}...")
        result = func(*args, **kwargs)
        print(f"{func.__name__} finished.")
        return result
    return wrapper

def greet(name):
    print(f"Hello, {name}!")

greet = my_decorator(greet)   # manually wrapping
greet("Sam")

# The @ SYNTAX — identical effect, much cleaner
@my_decorator
def greet2(name):
    print(f"Hi, {name}!")

greet2("Priya")   # @my_decorator automatically wraps greet2

# A PRACTICAL decorator: timing how long a function takes
import time
def timer(func):
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        print(f"{func.__name__} took {time.time()-start:.4f}s")
        return result
    return wrapper

@timer
def slow_function():
    time.sleep(1)

slow_function()
⚠️ *args, **kwargs Make Decorators Universal
Without *args, **kwargs in the wrapper, your decorator would only work on functions with EXACTLY the parameters you hardcoded. Using them lets ONE decorator wrap ANY function, regardless of its signature.

functools.wraps — Preserving Function Identity

PYTHON
from functools import wraps

def my_decorator(func):
    @wraps(func)   # preserves func's __name__, __doc__, etc.
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper

@my_decorator
def greet(name):
    """Says hello."""
    print(f"Hello {name}")

print(greet.__name__)   # 'greet' — WITHOUT @wraps this would incorrectly show 'wrapper'
print(greet.__doc__)    # 'Says hello.' — docstring preserved too

# Decorators with THEIR OWN arguments — a decorator factory
def repeat(times):
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            for _ in range(times):
                func(*args, **kwargs)
        return wrapper
    return decorator

@repeat(3)
def say_hi():
    print("Hi!")

say_hi()   # prints "Hi!" three times

import random, time
from functools import wraps

# Simulate a large log file as a generator (no real file needed)
def generate_log_lines(n):
    levels = ["INFO","WARNING","ERROR"]
    for i in range(n):
        level = random.choices(levels, weights=[80,15,5])[0]
