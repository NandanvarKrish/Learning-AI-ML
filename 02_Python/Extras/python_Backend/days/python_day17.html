Lesson 1: What Are Special Methods?

Special methods, also called dunder methods (double underscore), let your objects work with Python's built-in operations. When you write a + b, len(obj), or print(obj), Python calls a special method behind the scenes. You define the method, and your objects behave like built-in types.

Analogy: Special methods are like teaching your object the language of Python. Once it understands +, len, and ==, it can join the conversation with lists, numbers, and strings.

You've already met __init__ (Day 15) and __str__. Today you'll learn the most useful others.

Lesson 2: __repr__ for Developers

__str__ is for people reading output. __repr__ is for developers, and it should ideally show code that would recreate the object. Python uses __repr__ when you view an object in the interactive shell, or inside a list.

class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __repr__(self):
        return f"Point({self.x}, {self.y})"

p = Point(3, 4)
print(p)           # no __str__, so falls back to __repr__
print([p, p])      # lists use __repr__ for their items
Point(3, 4) [Point(3, 4), Point(3, 4)]
Rule of thumb: Always define __repr__. Define __str__ only when you want a friendlier display for users.

Lesson 3: Comparison Methods

By default, two objects are only equal if they are the same object. Define __eq__ to compare by value, and __lt__ (less than) to allow sorting.

class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __eq__(self, other):
        return self.x == other.x and self.y == other.y

    def __lt__(self, other):
        return (self.x, self.y) < (other.x, other.y)

    def __repr__(self):
        return f"Point({self.x}, {self.y})"

print(Point(1, 2) == Point(1, 2))            # True
print(Point(1, 2) == Point(3, 4))            # False
print(sorted([Point(3, 1), Point(1, 5)]))    # uses __lt__
True False [Point(1, 5), Point(3, 1)]
Careful: If you define __eq__, Python sets __hash__ to None, so the object can no longer be used as a dictionary key or in a set. Define __hash__ too if you need that.

From __lt__, Python's functools.total_ordering decorator can fill in >, <=, and >= automatically, but you don't need it yet.

Lesson 4: Arithmetic Methods

Define __add__ to make + work, __sub__ for -, and __mul__ for *.

class Money:
    def __init__(self, amount):
        self.amount = amount

    def __add__(self, other):
        return Money(self.amount + other.amount)

    def __repr__(self):
        return f"Money({self.amount})"

wallet = Money(100) + Money(250)
print(wallet)
Money(350)

Operators should return a new object rather than changing the originals, which keeps your code predictable.

Good practice: Only overload an operator when the meaning is obvious. Adding two Money objects is clear. Using + to mean "send an email" is confusing.

Lesson 5: Making Objects Behave Like Containers

Three methods make your object work like a list or dictionary:

MethodLets you use
__len__len(obj)
__getitem__obj[index] and slicing
__iter__for item in obj
__contains__item in obj
class Playlist:
    def __init__(self, songs):
        self.songs = songs

    def __len__(self):
        return len(self.songs)

    def __getitem__(self, index):
        return self.songs[index]

    def __contains__(self, song):
        return song in self.songs

p = Playlist(["Song A", "Song B", "Song C"])
print(len(p))                  # 3
print(p[1])                    # Song B
print("Song C" in p)           # True
for song in p:                 # works because __getitem__ exists
    print(song)
3 Song B True Song A Song B Song C
Note: Defining __getitem__ alone is enough for for loops to work, because Python falls back to indexing. Defining __iter__ is the clearer and more modern choice.

Lesson 6: __iter__ Explicitly

For full control over iteration, return an iterator from __iter__. Here the playlist returns the iterator of its list directly.

class Playlist:
    def __init__(self, songs):
        self.songs = songs

    def __iter__(self):
        return iter(self.songs)

for song in Playlist(["Intro", "Chorus"]):
    print("Now playing:", song)
Now playing: Intro Now playing: Chorus

Lesson 7: Putting It Together

A small Temperature class that compares, sorts, adds, and reports its length as a readable string:

class Temperature:
    def __init__(self, celsius):
        self.celsius = celsius

    def __repr__(self):
        return f"Temperature({self.celsius}C)"

    def __eq__(self, other):
        return self.celsius == other.celsius

    def __lt__(self, other):
        return self.celsius < other.celsius

    def __add__(self, other):
        return Temperature(self.celsius + other.celsius)

readings = [Temperature(30), Temperature(12), Temperature(25)]
print(sorted(readings))
print(max(readings))
print(Temperature(10) + Temperature(5))
[Temperature(12C), Temperature(25C), Temperature(30C)] Temperature(30C) Temperature(15C)

Notice that max works because __lt__ is defined. Python uses the same comparison behind several built-in functions.

Common Mistakes on Day 17

  1. Forgetting __hash__ after __eq__: the object becomes unhashable, so it can't go in a set or as a dictionary key.
  2. Mutating in __add__: return a new object instead of changing self or other.
  3. Comparing with a non-matching type: other.x fails if other is a string. Check the type first with isinstance.
  4. Overloading for unclear meanings: operators should behave the way a reader would expect.
  5. Relying on __str__ alone: without __repr__, debugging output is hard to read.
