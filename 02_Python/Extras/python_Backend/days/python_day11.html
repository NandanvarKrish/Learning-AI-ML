Reading and Writing Files

Estimated time: about 1.5 hours · open, with, read, write, append, CSV, and saving data permanently

Lesson 1: Why Files?

Everything you've stored so far disappears when the program ends. The expense tracker from Day 7 lost its data when you closed it. Files let a program save data to the disk and load it back later.

Analogy: Variables are like notes on a whiteboard, wiped when the meeting ends. Files are like a notebook you keep on the shelf, so tomorrow you can open it and carry on.

Two words matter here. A file path says where a file lives, such as expenses.txt (same folder as the program) or C:/Users/Sam/data/expenses.txt. A mode says what you intend to do with it: read, write, or append.

Lesson 2: Opening and Reading a File

The open() function returns a file object. Always close the file when you're done so changes are saved and resources are freed.

f = open("notes.txt", "r")    # "r" means read
content = f.read()            # read everything as one string
f.close()                     # always close it

print(content)

This works, but if an error happens before close(), the file stays open. Python's with statement avoids this problem.

The with statement (the recommended way)

with open("notes.txt", "r") as f:
    content = f.read()
# the file is closed automatically here, even if an error happened

print(content)
Rule of thumb: Use with open(...) every time. You'll almost never need to write close() yourself.

Lesson 3: Writing and Appending

The "w" mode writes to a file and erases anything already there. The "a" mode adds to the end without erasing.

with open("log.txt", "w") as f:
    f.write("First line\n")       # write() does not add a newline for you
    f.write("Second line\n")

with open("log.txt", "a") as f:
    f.write("Third line added later\n")

with open("log.txt") as f:
    print(f.read())
First line Second line Third line added later
Dangerous: Opening a file with "w" deletes its previous contents immediately, even if you write nothing. Use "a" when you want to keep existing data.

Lesson 4: Paths and Checking Files

A relative path like data.txt is measured from the folder where you run the program. An absolute path starts from the root, such as C:/Users/Sam/data.txt on Windows or /home/sam/data.txt on Linux and Mac.

import os

print(os.getcwd())                 # the folder the program runs from
print(os.path.exists("data.txt"))  # True or False
print(os.path.join("data", "expenses.txt"))   # builds a path safely
/home/sam/project False data/expenses.txt
Why os.path.join: It uses the correct slash for the operating system. Writing "data\\expenses.txt" by hand works on Windows but breaks on other systems.

Notice the import os line. Modules such as os are covered fully on Day 13, but you can use them now.

Lesson 5: Handling Missing Files

Opening a missing file for reading raises FileNotFoundError. Catch it with try and except, which you saw on Day 7, so the program can continue with sensible defaults.

try:
    with open("expenses.txt") as f:
        data = f.read()
except FileNotFoundError:
    data = ""
    print("No saved file yet, starting fresh.")

print(f"Loaded {len(data)} characters")
No saved file yet, starting fresh. Loaded 0 characters

Lesson 6: Storing Structured Data with CSV

CSV (comma-separated values) is a simple format used by spreadsheets. Each line is one record, and commas separate the fields. Python's csv module handles the details, including quotes and commas inside values.

import csv

rows = [
    ["name", "amount", "category"],
    ["Lunch", "450", "food"],
    ["Bus Pass", "120", "travel"],
]

with open("expenses.csv", "w", newline="") as f:
    writer = csv.writer(f)
    writer.writerows(rows)

with open("expenses.csv", newline="") as f:
    reader = csv.reader(f)
    for row in reader:
        print(row)
['name', 'amount', 'category'] ['Lunch', '450', 'food'] ['Bus Pass', '120', 'travel']

The newline="" argument prevents extra blank lines on Windows. Notice that CSV reads everything back as text, so you need float() to do arithmetic on amounts.

Dictionaries with DictReader and DictWriter

import csv

with open("expenses.csv", newline="") as f:
    for row in csv.DictReader(f):
        print(row["name"], float(row["amount"]))
Lunch 450.0 Bus Pass 120.0

Using dictionaries with CSV makes the code easier to read, because you use column names instead of positions.

Lesson 7: Saving the Expense Tracker

Here's how the Day 7 expense tracker can save and load its data. Only the changed parts are shown. The rest of the program stays the same.

import csv
import os

FILENAME = "expenses.csv"

def load_expenses():
    """Return the saved expenses as a list of dictionaries."""
    if not os.path.exists(FILENAME):
        return []
    expenses = []
    with open(FILENAME, newline="") as f:
        for row in csv.DictReader(f):
            expenses.append({
                "name": row["name"],
                "amount": float(row["amount"]),
                "category": row["category"],
            })
    return expenses

def save_expenses(expenses):
    """Write all expenses to the CSV file, replacing the old contents."""
    with open(FILENAME, "w", newline="") as f:
        writer = csv.DictWriter(f, fieldnames=["name", "amount", "category"])
        writer.writeheader()
        writer.writerows(expenses)

expenses = load_expenses()
print(f"Loaded {len(expenses)} expenses")

# ...add_expense, view_expenses, etc. unchanged...

save_expenses(expenses)   # call before Exit
print("Saved.")
Loaded 0 expenses Saved.
Design point: The program loads data once at the start and saves once at exit. Saving after every change is safer if the program could crash, and you can add that as an extension.

Common Mistakes on Day 11

  1. Using "w" when you meant "a": the old contents are erased immediately.
  2. Forgetting newlines: write() adds only the text you give it. Add \n yourself.
  3. Treating read data as numbers: file contents and CSV values are strings. Convert with int() or float().
  4. Forgetting newline="" with csv: you may get blank lines between rows on Windows.
  5. Wrong path: a relative path depends on where you run the program. Check with os.getcwd().
  6. Not handling FileNotFoundError: the first run of a program often has no file yet.
