DJANGO DAY 16 of 30

Authentication and Login

Estimated time: about 1.5 hours · Django's User model, hashed passwords, authenticate and login, logout, protecting pages, signup, and linking users to your data

Lesson 1: Authentication vs Authorisation

Two ideas get mixed up often, so keep them separate:

QuestionNameExample
Who are you?AuthenticationEntering a username and password
What may you do?AuthorisationOnly staff may publish posts
Analogy: Authentication is showing your ID at the door. Authorisation is what the wristband lets you access once you're inside.

Django provides both through django.contrib.auth, which was already included in INSTALLED_APPS from Day 1. Today you focus on authentication: logging in, logging out, and protecting pages.

Lesson 2: The User Model and Hashed Passwords

Django ships with a User model that has a username, password, email, and flags such as is_staff and is_superuser. Never store passwords as plain text. Django stores a hash, a one-way scrambled version of the password.

>>> from django.contrib.auth.models import User

>>> u = User.objects.create_user(username="sam", email="sam@example.com",
...                              password="a-strong-pass-123")
>>> u.password == "a-strong-pass-123"
>>> u.check_password("a-strong-pass-123")
>>> u.check_password("wrong-guess")
False True False
Always use create_user() or set_password(): Setting user.password = "text" directly saves the text unhashed, and no one can log in with it. Use the helper methods every time.

Lesson 3: authenticate and login

authenticate() checks the credentials and returns the user, or None. login() attaches the user to the current session (Day 11):

>>> from django.contrib.auth import authenticate
>>> authenticate(username="sam", password="wrong-guess")
>>> authenticate(username="sam", password="a-strong-pass-123")
None <User: sam>
# blog/views.py
from django.contrib.auth import authenticate, login

def my_login(request):
    user = authenticate(request, username=request.POST["username"],
                        password=request.POST["password"])
    if user is not None:
        login(request, user)
        return redirect("post_list")
    return render(request, "registration/login.html", {"error": "Wrong details"})

In practice you rarely write this yourself. Django's built-in LoginView does it, and you only supply a template.

Lesson 4: Built-in Login and Logout Views

Connect the built-in views in mysite/urls.py, or in blog/urls.py:

# mysite/urls.py
from django.contrib.auth import views as auth_views

urlpatterns = [
    path("accounts/login/", auth_views.LoginView.as_view(
        template_name="registration/login.html"), name="login"),
    path("accounts/logout/", auth_views.LogoutView.as_view(), name="logout"),
    # ...other patterns...
]

Set where users go after logging in and out, in settings.py:

# mysite/settings.py
LOGIN_URL = "login"                # where protected pages send anonymous visitors
LOGIN_REDIRECT_URL = "post_list"   # where users land after logging in
LOGOUT_REDIRECT_URL = "post_list"  # where users land after logging out

The login template needs the form, the CSRF token, and a hidden next field, so users return to the page they wanted:

# templates/registration/login.html
{% extends "base.html" %}
{% block content %}
  <h1>Log in</h1>
  <form method="post">
    {% csrf_token %}
    {{ form.as_p }}
    <input type="hidden" name="next" value="{{ next }}">
    <button type="submit">Log in</button>
  </form>
{% endblock %}
Logout is POST only: Since Django 5.0, LogoutView accepts only POST requests. A logout link must be a form button, not a plain link, so that visiting an address can't log people out.
# in base.html
{% if user.is_authenticated %}
  <form method="post" action="{% url 'logout' %}" style="display:inline">
    {% csrf_token %}
    <button type="submit">Log out ({{ user.username }})</button>
  </form>
{% else %}
  <a href="{% url 'login' %}">Log in</a>
{% endif %}

Lesson 5: Protecting Pages

Use the login_required decorator for function views, or LoginRequiredMixin for class-based views (Day 8):

from django.contrib.auth.decorators import login_required

@login_required
def post_create(request):
    ...

# or, for a class-based view
from django.contrib.auth.mixins import LoginRequiredMixin

class PostCreateView(LoginRequiredMixin, CreateView):
    model = Post
    form_class = PostForm
    template_name = "blog/post_form.html"

An anonymous visitor who opens /posts/new/ is sent to the login page, with the original address kept:

302 redirect to /accounts/login/?next=/posts/new/

Inside a view, request.user holds the signed-in user, or an AnonymousUser. Check with request.user.is_authenticated.

Put protection in the view: Hiding a link in the template is not security, because anyone can type the address. The view must check access.

Lesson 6: Signup

Django's UserCreationForm handles username, password entry, and password confirmation. Log the user in straight after signup:

# blog/views.py
from django.contrib.auth import login
from django.contrib.auth.forms import UserCreationForm

def signup(request):
    if request.method == "POST":
        form = UserCreationForm(request.POST)
        if form.is_valid():
            user = form.save()
            login(request, user)
            return redirect("post_list")
    else:
        form = UserCreationForm()
    return render(request, "registration/signup.html", {"form": form})
Built-in password rules: UserCreationForm applies Django's password validators, such as minimum length and common-password checks, configured in AUTH_PASSWORD_VALIDATORS.

Lesson 7: Linking Users to Your Data

In the mini blog, an Author is not yet a login account. A OneToOneField from Author to User (Day 14) connects them, so the view can tell who is writing:

# blog/models.py
from django.conf import settings

class Author(models.Model):
    user = models.OneToOneField(
        settings.AUTH_USER_MODEL,
        on_delete=models.SET_NULL,
        null=True, blank=True,
        related_name="author",
    )
    name = models.CharField(max_length=100)
    email = models.EmailField(unique=True)
# blog/views.py
@login_required
def post_create(request):
    author = request.user.author          # the Author linked to this login
    ...
Always use settings.AUTH_USER_MODEL: Pointing directly at User works now, but projects often replace the user model later. Referencing the setting keeps the link correct.

Lesson 8: Checking Permissions

Being logged in does not mean you may do everything. Check permissions with has_perm:

>>> u.is_staff
>>> u.has_perm("blog.add_post")
False False

A new user has no permissions until you grant them. You'll manage groups and permissions on Day 17.

Common Mistakes on Day 16

  1. Setting passwords directly: use create_user() or set_password() so they are hashed.
  2. Using a link to log out: the POST-only LogoutView needs a form button.
  3. Hiding links instead of protecting views: anyone can type the address.
  4. Hard-coding /accounts/login/ in redirects: use the named route and LOGIN_URL.
  5. Forgetting {% csrf_token %} in login and signup forms: the submission fails with a 403.
  6. Accessing request.user.author for an anonymous user: protect the view with login_required first.

Practicals

Use your mini-blog project.

Practical 1: Create Users in the Shell

Create two users with create_user(). Confirm that authenticate() returns the user with the right password and None with a wrong one.

Practical 2: Login and Logout

Add the login and logout URLs, the login template, and the settings. Log in, confirm the navigation shows your username, then log out using the form button.

Practical 3: Protect the Create Page

Add login_required to the create view. Visit /posts/new/ while logged out and confirm you are sent to the login page, then back to the create page after logging in.

Practical 4: Signup

Build the signup view and template using UserCreationForm. Create a new account through the page and confirm you are logged in immediately.

Practical 5: Link Author to User

Add the user field to Author, migrate, and link one Author to one login. In post_create, set post.author = request.user.author and test that the new post belongs to that author.
