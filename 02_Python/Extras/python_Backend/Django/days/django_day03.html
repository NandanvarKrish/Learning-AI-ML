The Admin Panel and Relationships

Estimated time: about 1.5 hours · Creating a superuser, registering models in the admin, ForeignKey and on_delete, related names, and ManyToMany

Lesson 1: The Admin Panel

Django ships with a ready-made admin site at /admin/. It lets staff members create, read, update, and delete data through a web interface, without you writing a single form or page.

Analogy: The admin is the back office of a shop. Customers see the storefront (your site). Staff use the back office to manage stock and orders. You build the storefront; Django provides the back office.

The admin was already enabled on Day 1. The line path("admin/", admin.site.urls) in mysite/urls.py is what connects it.

Lesson 2: Creating a Superuser

A superuser is an account with full permission to use the admin. Create one from the terminal:

python manage.py createsuperuser
Username: admin Email address: admin@example.com Password: Password (again): Superuser created successfully.
Security: Choose a strong password. The superuser can see and change all data on the site. Never create a superuser with a shared or simple password on a live site.

Start the server with python manage.py runserver, then sign in at http://127.0.0.1:8000/admin/.

Lesson 3: Registering Models in the Admin

Models are hidden from the admin until you register them. Register them in blog/admin.py:

# blog/admin.py
from django.contrib import admin
from .models import Post

admin.site.register(Post)

Refresh the admin and you'll see a Posts section with an Add button. This is the quickest form of registration.

For more control, subclass ModelAdmin and use the @admin.register decorator, which you met on Day 20 when studying decorators:

# blog/admin.py
from django.contrib import admin
from .models import Post

@admin.register(Post)
class PostAdmin(admin.ModelAdmin):
    list_display = ("title", "author", "is_published", "created_at")
    list_filter = ("is_published", "author")
    search_fields = ("title", "body")
    list_editable = ("is_published",)
OptionWhat it adds to the admin list page
list_displayColumns shown in the table
list_filterA sidebar of filters
search_fieldsA search box that searches these fields
list_editableLets you edit values directly in the list

Lesson 4: Foreign Keys

A ForeignKey links one row to one row in another table. Each post has one author, and each author can have many posts.

# blog/models.py
from django.db import models

class Author(models.Model):
    name = models.CharField(max_length=100)
    email = models.EmailField(unique=True)

    def __str__(self):
        return self.name

class Post(models.Model):
    author = models.ForeignKey(
        Author,
        on_delete=models.CASCADE,
        related_name="posts",
    )
    title = models.CharField(max_length=200)
    body = models.TextField()
    created_at = models.DateTimeField(auto_now_add=True)
    is_published = models.BooleanField(default=False)

    def __str__(self):
        return self.title

After changing the models, run the migration commands from Day 2:

python manage.py makemigrations blog
python manage.py migrate
Migrations for 'blog': blog/migrations/0002_author_post_author.py + Create model Author + Add field author to post
Migration name: Django generates the name from your changes, so the exact text may differ. The important part is the "Create model Author" line.

Lesson 5: Using Relationships in Code

Relationships work in both directions. Follow a foreign key forward with the field name, and backward with the related_name.

>>> from blog.models import Author, Post
>>> a = Author.objects.create(name="Asha", email="asha@example.com")
>>> Post.objects.create(author=a, title="Model tips", body="Keep models small.")
>>> post = Post.objects.get(title="Model tips")
>>> post.author.name            # forward: post → author
>>> a.posts.all()               # backward: author → posts
>>> Post.objects.filter(author__name="Asha").count()
'Asha' <QuerySet [<Post: Model tips>]> 1

Notice author__name in the filter. Double underscores can follow a relationship, so you can filter by a field on the related model.

Why related_name? Without it, Django creates author.post_set. Setting related_name="posts" gives a clearer name, author.posts.

Lesson 6: The on_delete Options

The on_delete argument decides what happens to a post when its author is deleted. Choose it deliberately.

OptionBehaviour when the author is deletedTypical use
CASCADEDeletes the posts tooChild data that makes no sense alone, such as comments on a post
PROTECTStops the deletion with an errorData that must not be lost by accident, such as orders
SET_NULLSets the field to None (needs null=True)Posts that should survive, with no author
SET_DEFAULTSets a default valueReassigning to a placeholder user
DO_NOTHINGLeaves the rows alone, which can break integrityRarely used; avoid unless you know why
Caution: CASCADE is convenient but dangerous for important data. Deleting one author could silently remove years of records. Consider PROTECT or SET_NULL for anything valuable.

Lesson 7: ManyToMany Relationships

When one post can have many tags and one tag can belong to many posts, use ManyToManyField. Django creates the join table for you.

class Tag(models.Model):
    name = models.CharField(max_length=50, unique=True)

    def __str__(self):
        return self.name

class Post(models.Model):
    # ...other fields...
    tags = models.ManyToManyField(Tag, blank=True, related_name="posts")
>>> python = Tag.objects.create(name="python")
>>> web = Tag.objects.create(name="web")
>>> post.tags.add(python, web)
>>> post.tags.all()
>>> python.posts.all()
<QuerySet [<Tag: python>, <Tag: web>]> <QuerySet [<Post: Model tips>]>

blank=True lets the admin form save a post with no tags. Without it, the admin requires at least one tag.

Lesson 8: Inlines in the Admin

You can edit related objects on the same page. For example, an author's posts can be added inside the author's form:

# blog/admin.py
from django.contrib import admin
from .models import Author, Post

class PostInline(admin.TabularInline):
    model = Post
    extra = 1

@admin.register(Author)
class AuthorAdmin(admin.ModelAdmin):
    list_display = ("name", "email")
    inlines = [PostInline]

Each author's page now lists their posts, with a row to add a new one.

Common Mistakes on Day 3

  1. Forgetting to register the model: it won't appear in the admin until admin.site.register or @admin.register is used.
  2. Choosing CASCADE without thinking: deleting a parent can remove far more than you intended.
  3. Using SET_NULL without null=True: the migration fails, because the database can't store an empty value.
  4. Forgetting migrations after adding a ForeignKey: the new column is missing and queries fail.
  5. Expecting author.post_set after setting related_name: the name is now author.posts.

Practical 2: Add Authors and Posts

Practical 5: Choose a Delete Behaviour

Decide whether deleting an author should delete their posts, block the deletion, or keep the posts with no author. Change on_delete to match your decision, migrate, and explain your choice in one sentence.
