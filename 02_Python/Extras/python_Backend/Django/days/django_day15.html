Model Forms in Depth

Estimated time: about 1.5 hours · Widgets, labels, help text, customising fields in __init__, saving with commit=False, unique validation, and formsets

Lesson 1: Forms Describe Three Things

A form does three jobs, and each is controlled separately:

JobControlled byExample
What the field looks likeWidgetA large text area for the body
What the field means to the userLabel and help text"Publish now", with a hint underneath
What values are allowedField rules and validationTitle of at least 5 characters
Analogy: A form is like a printed application. The layout (widget), the printed question (label), and the rules about what answers are acceptable (validation) are three separate decisions that you can change independently.

Lesson 2: Widgets, Labels, and Help Text

Customise the presentation through Meta, without touching the model:

# blog/forms.py
from django import forms
from .models import Post, Tag

class PostForm(forms.ModelForm):
    class Meta:
        model = Post
        fields = ["title", "body", "cover", "is_published", "tags"]
        labels = {
            "is_published": "Publish now",
        }
        help_texts = {
            "title": "Keep it under 80 characters.",
        }
        widgets = {
            "title": forms.TextInput(attrs={"placeholder": "Post title", "class": "input"}),
            "body": forms.Textarea(attrs={"rows": 6}),
            "tags": forms.CheckboxSelectMultiple,
        }

Check the result in the shell, without rendering a page:

>>> form = PostForm()
>>> form.fields["title"].help_text
>>> form.fields["is_published"].label
>>> form.fields["title"].max_length
'Keep it under 80 characters.' 'Publish now' 200
Why 200 and not 80? The help text is only a hint for users. The real limit still comes from the model's max_length=200. If you want to enforce 80 characters, add a validation rule (Lesson 5).

Lesson 3: Customising Fields in __init__

Some choices depend on the situation, such as which tags a user may pick. Adjust the form's fields in __init__, after calling super():

class PostForm(forms.ModelForm):
    class Meta:
        model = Post
        fields = ["title", "body", "cover", "is_published", "tags"]

    def __init__(self, *args, **kwargs):
        super().__init__(*args, **kwargs)
        self.fields["tags"].queryset = Tag.objects.order_by("name")
        self.fields["tags"].required = False
        self.fields["title"].widget.attrs["autofocus"] = True

Notice that super().__init__ comes first. Fields are created there, so you can change them only afterwards.

Don't change the model's fields here: Changes made in __init__ affect only this form instance. The database rules, such as blank=True on the model, are not changed.

Lesson 4: Saving with commit=False

Sometimes a value comes from the view, not the user, such as the author or the current time. save(commit=False) builds the object without writing it, so you can add those values first:

# blog/views.py
def post_create(request):
    if request.method == "POST":
        form = PostForm(request.POST, request.FILES)
        if form.is_valid():
            post = form.save(commit=False)
            post.author = Author.objects.get(email="asha@example.com")  # set by the view
            post.save()
            form.save_m2m()    # ManyToMany data is saved after the object has a pk
            return redirect("post_list")
    else:
        form = PostForm()
    return render(request, "blog/post_form.html", {"form": form})

The shell shows the difference:

>>> form = PostForm({"title": "Draft from shell", "body": "Text", "author": asha.pk})
>>> form.is_valid()
>>> obj = form.save(commit=False)
>>> obj.pk
>>> obj.save()
>>> obj.pk is not None
True None True
Remember save_m2m(): Calling save(commit=False) does not save the ManyToMany selections, such as tags. Call form.save_m2m() after the object is saved, or the tags are lost.

Lesson 5: Custom Validation Rules

Field-level rules go in clean_<field> (Day 6). Here is a stricter title rule, plus a check across fields:

class PostForm(forms.ModelForm):
    # ...Meta and __init__ as before...

    def clean_title(self):
        title = self.cleaned_data["title"].strip()
        if len(title) < 5:
            raise forms.ValidationError("Title must be at least 5 characters.")
        if len(title) > 80:
            raise forms.ValidationError("Keep the title under 80 characters.")
        return title

    def clean(self):
        cleaned = super().clean()
        if cleaned.get("is_published") and not cleaned.get("tags"):
            self.add_error("tags", "Published posts need at least one tag.")
        return cleaned

add_error("tags", ...) attaches the error to a specific field, so the message appears next to the tags box instead of at the top of the form.

Where each rule belongs: Rules about one value go in clean_<field>. Rules involving several fields go in clean(), with add_error to point at the right field.

Lesson 6: Unique Checks in ModelForms

A ModelForm automatically checks the unique constraint you added on Day 10 (author plus title). Instead of a database error, the user sees a friendly message:

Post with this Author and Title already exists.

The check runs during is_valid(), so the object is never saved with a duplicate. The database constraint remains as the final safety net, for code that bypasses forms.

Two layers: The form gives a helpful message; the database constraint guarantees the rule. Use both.

Lesson 7: Editing Several Rows with Formsets

Sometimes a page edits many objects at once, such as all of an author's posts. A model formset creates one form per object:

from django.forms import modelformset_factory

PostFormSet = modelformset_factory(Post, fields=["title", "is_published"], extra=0)

formset = PostFormSet(request.POST or None, queryset=Post.objects.filter(author=asha))
if request.method == "POST" and formset.is_valid():
    formset.save()
  • extra=0 means no blank forms are added beyond the existing rows.
  • The formset manages a hidden ID field for each row, so each form updates the right object.
  • Use {{ formset.management_form }} in the template, or the formset won't know how many forms it contains.
Management form: Missing {{ formset.management_form }} is a common mistake. Without it, Django raises an error about missing management form data.

Common Mistakes on Day 15

  1. Forgetting super().__init__ before customising fields: the fields do not exist yet.
  2. Forgetting save_m2m() after commit=False: tags and other ManyToMany data are lost.
  3. Using a help text as a rule: it only describes the field; add validation to enforce it.
  4. Attaching multi-field errors to the whole form when they belong to one field: use add_error with the field name.
  5. Leaving out the management form in a formset template: the page errors on submission.
