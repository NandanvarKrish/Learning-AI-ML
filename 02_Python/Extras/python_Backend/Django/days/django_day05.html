Static and Media Files

Estimated time: about 1.5 hours · CSS, JavaScript, and images with the static tag, project and app static folders, collectstatic, and user uploads with MEDIA settings

Lesson 1: Static vs Media Files

Django separates two kinds of files that a page needs:

TypeWhat it isWho creates itExamples
Static filesPart of your code, the same for every visitorYou, the developerCSS, JavaScript, logos, icons
Media filesUploaded by users while the site runsYour site's visitorsProfile photos, PDFs, post images
Analogy: Static files are the furniture and décor that came with the building. Media files are the photos visitors pin to the walls.

Lesson 2: Where Static Files Live

Each app can keep its own static files in a static folder. Use a nested folder with the app name to avoid clashes:

blog/ └── static/ └── blog/ ├── style.css └── app.js

You can also keep project-wide files in a folder you choose. Tell Django about it in settings.py:

# mysite/settings.py
from pathlib import Path
BASE_DIR = Path(__file__).resolve().parent.parent

STATIC_URL = "static/"                        # the address prefix: /static/...
STATICFILES_DIRS = [BASE_DIR / "static"]      # extra project-wide folders
STATIC_ROOT = BASE_DIR / "staticfiles"        # where collectstatic gathers files
Note: BASE_DIR is usually already defined near the top of settings.py. Reuse it instead of defining it twice.

Lesson 3: The static Tag

Never write static paths by hand. The static tag builds the correct URL for you, and it keeps working if you change STATIC_URL later.

# blog/templates/base.html
{% load static %}
<!DOCTYPE html>
<html lang="en">
<head>
  <link rel="stylesheet" href="{% static 'blog/style.css' %}">
</head>
<body>
  <img src="{% static 'blog/logo.png' %}" alt="Logo">
  <script src="{% static 'blog/app.js' %}"></script>
</body>
</html>
<link rel="stylesheet" href="/static/blog/style.css"> <img src="/static/blog/logo.png" alt="Logo">
Don't forget {% load static %}: without it, Django raises TemplateSyntaxError for the static tag. Put it at the top of every template that uses static files.

Lesson 4: Serving Static Files in Development

When DEBUG is True, runserver serves static files automatically from the app folders and STATICFILES_DIRS. You don't need extra steps while you learn.

Restart the server after changing settings.py, and refresh the browser with a hard reload (Ctrl+Shift+R, or Cmd+Shift+R on a Mac) if the old CSS is cached.

Quick test: Visit http://127.0.0.1:8000/static/blog/style.css directly in the browser. If you see your CSS, the setup is correct.

Lesson 5: collectstatic for Production

In production, a web server such as Nginx serves static files for speed. It needs them gathered into one folder. The collectstatic command copies everything from all apps and STATICFILES_DIRS into STATIC_ROOT.

python manage.py collectstatic
142 static files copied to '/home/you/django-course/mysite/staticfiles'.

The number depends on your apps. Django's admin alone brings many files. Run collectstatic again whenever you change static files before deploying.

Don't edit the staticfiles folder by hand. It's a generated copy. Change the original file in your app's static folder and run collectstatic again.

Lesson 6: Media Files and User Uploads

Media files need two settings: the URL prefix and the folder on disk where uploads are saved.

# mysite/settings.py
MEDIA_URL = "media/"
MEDIA_ROOT = BASE_DIR / "media"

A model can then store an uploaded image. ImageField needs the Pillow library, so install it with pip install pillow.

# blog/models.py
class Post(models.Model):
    # ...existing fields...
    cover = models.ImageField(upload_to="covers/", blank=True)

Add this to mysite/urls.py so Django serves uploads while DEBUG is on:

from django.conf import settings
from django.conf.urls.static import static

urlpatterns = [
    # ...existing patterns...
] + static(settings.MEDIA_URL, document_root=settings.MEDIA_ROOT)

In a template, show an uploaded image safely. The if check avoids errors for posts without a cover:

{% if post.cover %}
  <img src="{{ post.cover.url }}" alt="{{ post.title }}">
{% endif %}
Security: Uploads come from strangers. Limit file types, check file sizes, and never serve uploads from the same folder as your code. On a live site, use cloud storage or a separate media server.

Lesson 7: Adding a Stylesheet to the Project

A small stylesheet makes a visible difference. Create blog/static/blog/style.css:

body {
  font-family: system-ui, sans-serif;
  max-width: 720px;
  margin: 2rem auto;
  padding: 0 1rem;
  color: #222;
}
nav a { margin-right: 1rem; }
h1 { color: #0C4B33; }

Link it from base.html with the static tag from Lesson 3. Every page that extends the base now gets the same styling.

Tip: Keep one shared stylesheet in the base template, and add page-specific CSS only when a page truly needs it. This keeps the site consistent.

Common Mistakes on Day 5

  1. Forgetting {% load static %}: the page fails with a template syntax error.
  2. Hard-coding /static/...: use the static tag so paths stay correct.
  3. Putting files in the wrong folder: each app's files belong in app/static/app/.
  4. Forgetting collectstatic before deployment: production shows missing styles and scripts.
  5. Mixing up MEDIA and STATIC: uploads go in MEDIA_ROOT, code assets in static folders.
  6. Trusting uploaded files: validate and restrict them.

Practicals

Continue in your mysite project.

Practical 1: Link a Stylesheet

Create blog/static/blog/style.css from Lesson 7 and link it in base.html with the static tag. Visit /posts/ and confirm the new styles appear.

Practical 2: Check the Generated Link

View the page source in your browser and find the link tag for your stylesheet. Write down the exact href Django generated.

Practical 3: Add a JavaScript File

Create blog/static/blog/app.js with a single line, such as console.log("Blog loaded");. Include it with the static tag, then open the browser console and confirm the message.

Practical 4: Run collectstatic

Set STATIC_ROOT, then run collectstatic. Open the generated staticfiles folder and confirm your style.css is there.

Practical 5: Upload a Cover Image

Add the cover field from Lesson 6, install Pillow, and run the migrations. In the admin, upload an image to a post, then display it on the detail page with the if check. Confirm that a post without a cover shows no broken image.
