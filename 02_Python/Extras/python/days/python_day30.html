Lesson 2: Project Structure

Create a project folder and separate the code by responsibility. Each file has one job, which makes the code easier to test and change.

task_manager/ ├── models.py # the Task class: one task and its rules ├── storage.py # reading and writing the JSON file ├── manager.py # the TaskManager class: add, complete, list ├── cli.py # the menu the user sees ├── test_manager.py # automated tests with pytest ├── .gitignore # files Git should ignore └── README.md # what the project is and how to run it
Design principle: Keep input/output (the menu) apart from logic (the manager). The logic can then be tested without typing anything.

Lesson 3: The Task Model

A Task knows its own data and checks its own rules: the title cannot be blank, and the due date must be a valid YYYY-MM-DD date.

# models.py
from datetime import date

class Task:
    def __init__(self, task_id, title, due=None, done=False):
        if not title.strip():
            raise ValueError("Title cannot be empty")
        if due is not None:
            date.fromisoformat(due)   # raises ValueError if the format is wrong
        self.id = task_id
        self.title = title.strip()
        self.due = due
        self.done = done

    def to_dict(self):
        return {"id": self.id, "title": self.title, "due": self.due, "done": self.done}

    @classmethod
    def from_dict(cls, data):
        return cls(data["id"], data["title"], data.get("due"), data.get("done", False))

    def __str__(self):
        mark = "x" if self.done else " "
        due = f" (due {self.due})" if self.due else ""
        return f"[{mark}] {self.id}. {self.title}{due}"

Notice the to_dict and from_dict pair. JSON can only hold plain data, so the object is converted to a dictionary before saving and rebuilt when loading.

Lesson 4: Storage

The storage module knows only about files and JSON. It doesn't know what a task is, which keeps it simple.

# storage.py
import json
from pathlib import Path

def load_tasks(path):
    file = Path(path)
    if not file.exists():
        return []                      # first run: no file yet
    with file.open(encoding="utf-8") as f:
        return json.load(f)

def save_tasks(path, records):
    with open(path, "w", encoding="utf-8") as f:
        json.dump(records, f, indent=2)
Watch out: If the JSON file is damaged, json.load raises json.JSONDecodeError. In a larger program you would catch that and warn the user. Think about where that handling belongs.

Lesson 5: The TaskManager Class

The manager owns the list of tasks and keeps the file up to date after every change.

# manager.py
from models import Task
from storage import load_tasks, save_tasks

class TaskManager:
    def __init__(self, path="tasks.json"):
        self.path = path
        self.tasks = [Task.from_dict(d) for d in load_tasks(path)]

    def _next_id(self):
        return max((t.id for t in self.tasks), default=0) + 1

    def add(self, title, due=None):
        task = Task(self._next_id(), title, due)
        self.tasks.append(task)
        self.save()
        return task

    def complete(self, task_id):
        for task in self.tasks:
            if task.id == task_id:
                task.done = True
                self.save()
                return task
        raise KeyError(task_id)

    def pending(self):
        return [t for t in self.tasks if not t.done]

    def save(self):
        save_tasks(self.path, [t.to_dict() for t in self.tasks])

The max(..., default=0) call from Day 9 gives the first ID as 1, even when the list is empty.

Lesson 6: The Command-Line Interface

The menu only handles input and output. It catches errors from the logic layer and shows a friendly message instead of a traceback.

# cli.py
from manager import TaskManager

def show_menu():
    print("\n1) Add   2) List pending   3) Complete   4) Quit")

def main():
    manager = TaskManager("tasks.json")
    while True:
        show_menu()
        choice = input("Choose: ").strip()

        if choice == "1":
            title = input("Title: ")
            due = input("Due (YYYY-MM-DD, blank for none): ").strip() or None
            try:
                print("Added:", manager.add(title, due))
            except ValueError as e:
                print("Error:", e)

        elif choice == "2":
            pending = manager.pending()
            if not pending:
                print("Nothing pending. Well done!")
            for task in pending:
                print(task)

        elif choice == "3":
            try:
                task_id = int(input("Task id: "))
                print("Completed:", manager.complete(task_id))
            except ValueError:
                print("Error: please enter a number")
            except KeyError as e:
                print("Error: no task with id", e.args[0])

        elif choice == "4":
            print("Goodbye!")
            break

        else:
            print("Please choose 1 to 4.")

if __name__ == "__main__":
    main()
1) Add 2) List pending 3) Complete 4) Quit Choose: 2 [ ] 2. Finish capstone

The sample output shows one menu choice. Your session will continue in a loop until you pick 4.

Lesson 7: Testing the Logic

Tests check that the logic behaves as promised, without typing into the menu. Use tmp_path from Day 26 so the tests never touch your real data.

# test_manager.py
import pytest
from manager import TaskManager

def test_ids_are_sequential(tmp_path):
    m = TaskManager(tmp_path / "t.json")
    a = m.add("One")
    b = m.add("Two")
    assert (a.id, b.id) == (1, 2)

def test_blank_title_rejected(tmp_path):
    m = TaskManager(tmp_path / "t.json")
    with pytest.raises(ValueError):
        m.add("   ")

def test_bad_due_date_rejected(tmp_path):
    m = TaskManager(tmp_path / "t.json")
    with pytest.raises(ValueError):
        m.add("Read", due="31/12/2026")

def test_complete_unknown_id(tmp_path):
    m = TaskManager(tmp_path / "t.json")
    with pytest.raises(KeyError):
        m.complete(99)

def test_tasks_persist_between_runs(tmp_path):
    path = tmp_path / "t.json"
    TaskManager(path).add("Persist me")
    assert len(TaskManager(path).tasks) == 1
pytest -q
..... [100%] 5 passed
Why tests matter: When you change the code later, the tests tell you within seconds whether you broke something. Professional projects depend on this.

Common Mistakes at This Stage

  1. Putting everything in one file: separate models, storage, logic, and the menu.
  2. Forgetting to save: call save() after every change that should persist.
  3. Testing with the real data file: always use tmp_path in tests.
  4. Silent failures: raise clear exceptions in the logic and handle them in the menu.
  5. Committing personal data: check git status before every commit.
