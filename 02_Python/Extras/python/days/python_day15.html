Classes and Objects

Estimated time: about 1.5 hours · Defining classes, __init__, instance and class attributes, methods, self

Lesson 1: Why Classes?

So far, related data and functions have lived separately. A contact is a dictionary, and the functions that work on it sit beside it. A class bundles data and the functions that act on that data into one blueprint. Each item created from the blueprint is an object.

Analogy: A class is a cookie cutter. The cutter describes the shape, and each cookie you press out is an object. Every cookie has the same shape, but each can have its own topping.

Python is an object-oriented language. You've already been using objects all along: a string, a list, and a dictionary are all objects, with methods like .upper() and .append().

name = "sam"
print(type(name))        # <class 'str'>
print(name.upper())      # methods belong to the object
<class 'str'> SAM

Lesson 2: Defining a Class

Use the class keyword, followed by a name in CapitalWords style. The indented block holds the methods.

class Dog:
    pass              # an empty class, not very useful yet

my_dog = Dog()        # creating an object is called instantiation
print(type(my_dog))
<class '__main__.Dog'>

Creating Dog() makes a new object. The class is the blueprint, and my_dog is one instance of it.

Lesson 3: __init__ and Attributes

The __init__ method runs automatically when you create an object. Use it to set up the object's attributes, which are the data it holds. The first parameter, self, refers to the object being created.

class Contact:
    def __init__(self, name, phone, email):
        self.name = name
        self.phone = phone
        self.email = email

ali = Contact("Ali Raza", "9876543210", "ali@example.com")
print(ali.name)
print(ali.phone)
Ali Raza 9876543210
Key idea: self.name = name means "store the value of the name parameter on this object, under the attribute name". Use self. inside the class whenever you want to keep data on the object.

Each object has its own data

sara = Contact("Sara Ahmed", "9123456780", "sara@example.com")
ali.email = "ali.new@example.com"     # change one object
print(ali.email)                      # changed
print(sara.email)                     # unchanged
ali.new@example.com sara@example.com
Common mistake: Forgetting self. Writing name = name inside __init__ does nothing useful, because the value is lost when the method ends.

Lesson 4: Methods

A method is a function defined inside a class. It always takes self as its first parameter, so it can read and change the object's data.

class Contact:
    def __init__(self, name, phone, email):
        self.name = name
        self.phone = phone
        self.email = email

    def describe(self):
        return f"{self.name} ({self.phone}) - {self.email}"

    def update_email(self, new_email):
        self.email = new_email

c = Contact("Ali Raza", "9876543210", "ali@example.com")
print(c.describe())
c.update_email("ali.raza@example.com")
print(c.describe())
Ali Raza (9876543210) - ali@example.com Ali Raza (9876543210) - ali.raza@example.com

Call a method with object.method(). Python fills in self for you automatically.

Analogy: Attributes are the facts about a car, such as colour and fuel level. Methods are the actions, such as start and honk. A method knows which car it belongs to because of self.

Lesson 5: Class Attributes and Instance Attributes

An instance attribute belongs to one object (set with self.). A class attribute is defined directly in the class body and is shared by every object.

class Contact:
    total_created = 0                  # class attribute, shared

    def __init__(self, name):
        self.name = name               # instance attribute, one per object
        Contact.total_created += 1

a = Contact("Ali")
b = Contact("Sara")
print(Contact.total_created)           # 2
print(a.name, b.name)                  # Ali Sara
2 Ali Sara
Tip: Use class attributes for values that all objects share, such as a counter or a fixed setting. Use instance attributes for data that differs between objects.

Lesson 6: Special Methods (Dunder Methods)

Methods with double underscores on both sides, such as __init__, are called special methods. Python calls them automatically in certain situations. A common one is __str__, which controls what print() shows.

class Contact:
    def __init__(self, name, phone):
        self.name = name
        self.phone = phone

    def __str__(self):
        return f"{self.name}: {self.phone}"

c = Contact("Ali Raza", "9876543210")
print(c)               # uses __str__
print(str(c))         # same result
Ali Raza: 9876543210 Ali Raza: 9876543210

Without __str__, printing an object shows something like <__main__.Contact object at 0x...>, which isn't helpful. Day 17 covers more special methods.

Lesson 7: Turning the Contact Book into Classes

Here's how the Day 14 contact book could look with a class. Each contact becomes an object, and it knows how to describe itself.

class Contact:
    def __init__(self, name, phone, email=""):
        self.name = name.strip().title()
        self.phone = phone
        self.email = email.strip().lower()

    def to_row(self):
        """Return the contact as a dictionary for the CSV file."""
        return {"name": self.name, "phone": self.phone, "email": self.email}

    def __str__(self):
        return f"{self.name:<20}{self.phone:<15}{self.email}"

contacts = [
    Contact("sam khan", "9876543210", "sam@example.com"),
    Contact("ali raza", "9123456780"),
]

for c in sorted(contacts, key=lambda c: c.name):
    print(c)
Ali Raza 9123456780 Sam Khan 9876543210 sam@example.com
Why this is nicer: The cleaning now happens automatically when a contact is created, and the display logic lives with the data it describes. Your menu code no longer has to remember to clean every value.

Common Mistakes on Day 15

  1. Forgetting self: attributes must be written as self.name, and methods must take self as the first parameter.
  2. Forgetting the parentheses on creation: Contact is the class, while Contact(...) creates an object.
  3. Confusing class and instance attributes: an attribute set with self. is per object. One set in the class body is shared.
  4. Missing a return in a method that should give a value: methods that return data must use return.
  5. Calling a method without parentheses: c.describe is the method object, while c.describe() runs it.
