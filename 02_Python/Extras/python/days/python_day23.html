Calling APIs with requests

Estimated time: about 1.5 hours · HTTP basics, GET and POST, status codes, headers, query parameters, error handling, timeouts

Lesson 1: What Is an API?

An API (Application Programming Interface) is a set of rules that lets one program ask another program for data or for an action. A weather service, a payment gateway, and a map provider each expose an API, usually over the web.

Analogy: An API is a restaurant menu and kitchen hatch. You don't go into the kitchen. You choose from the menu, hand over your order, and receive your food through the hatch.

Web APIs use HTTP, the same protocol your browser uses. Your Python program sends a request, and the server sends back a response, usually containing JSON, which you learned on Day 22.

Lesson 2: Installing and Importing requests

The requests package is the standard tool for HTTP in Python. You installed it on Day 13.

# In the terminal

Lesson 3: Making a GET Request

A GET request asks the server for data without changing anything. requests.get(url) sends the request and returns a response object.

import requests

response = requests.get("https://httpbin.org/get")
print(response.status_code)     # 200 means success
print(response.headers["Content-Type"])
200 application/json

The response object holds the status code, the headers, and the body. For JSON data, call .json() to convert the body into a Python dictionary or list.

data = response.json()
print(type(data))               # <class 'dict'>
print(data["url"])
<class 'dict'> https://httpbin.org/get
Note: The outputs above come from a public test service called httpbin. Results from a live API will differ, but the structure is the same.

Lesson 4: Status Codes

Every response has a three-digit status code. The first digit tells you the category.

RangeMeaningCommon examples
2xxSuccess200 OK, 201 Created
3xxRedirect301 Moved Permanently
4xxClient error (your request was wrong)400 Bad Request, 401 Unauthorised, 404 Not Found, 429 Too Many Requests
5xxServer error (the server failed)500 Internal Server Error, 503 Service Unavailable
response = requests.get("https://httpbin.org/status/404")
print(response.status_code)     # 404
print(response.ok)              # False: ok is True only for 2xx and 3xx
404 False
Good habit: Check the status before using the data. Use response.raise_for_status() to turn 4xx and 5xx responses into an exception you can catch.

Lesson 5: Query Parameters and Headers

Pass search terms or filters with params. The library builds the query string for you, and it handles special characters correctly.

import requests

params = {"q": "python books", "limit": 5}
response = requests.get("https://httpbin.org/get", params=params)
print(response.json()["args"])
{'limit': '5', 'q': 'python books'}

Many APIs need an API key or other information in the headers. Pass them as a dictionary.

headers = {
    "Accept": "application/json",
    "User-Agent": "my-python-course/1.0",
}
response = requests.get("https://httpbin.org/headers", headers=headers)
print(response.json()["headers"]["User-Agent"])
my-python-course/1.0
Security: Never put real API keys directly in your code, and never upload them to public repositories. Store them in environment variables, and read them with os.environ.

Lesson 6: POST Requests

A POST request sends data to the server, for example to create a record. Use json= to send a Python dictionary as JSON.

import requests

new_contact = {"name": "Sara", "phone": "9123456780"}
response = requests.post("https://httpbin.org/post", json=new_contact)
print(response.status_code)
print(response.json()["json"])
200 {'name': 'Sara', 'phone': '9123456780'}

GET reads data, and POST creates or submits it. Use GET for anything that doesn't change the server's data.

Lesson 7: Timeouts and Errors

A server may be slow or unreachable. Without a timeout, your program could wait forever. Always set one, and catch the errors that requests raises.

import requests

try:
    response = requests.get("https://httpbin.org/delay/10", timeout=3)
    response.raise_for_status()
    print(response.json())
except requests.exceptions.Timeout:
    print("The server took too long to respond.")
except requests.exceptions.HTTPError as e:
    print("Server returned an error:", e)
except requests.exceptions.RequestException as e:
    print("Network problem:", e)
The server took too long to respond.
Exception hierarchy: Timeout, HTTPError, and ConnectionError all inherit from RequestException. Catch the specific ones first, then the general one last, as you learned on Day 12.

Lesson 8: A Complete Example

Here's a function that fetches data safely, returning None on any failure. It combines everything from today.

import requests

def fetch_json(url, params=None):
    """Return the parsed JSON from url, or None if the request fails."""
    try:
        response = requests.get(url, params=params, timeout=5)
        response.raise_for_status()
        return response.json()
    except requests.exceptions.RequestException as e:
        print("Request failed:", e)
        return None

data = fetch_json("https://httpbin.org/get", {"q": "python"})
if data:
    print("Query was:", data["args"]["q"])
Query was: python

Returning None on failure keeps the calling code simple, and the function is easy to test. You'll reuse this pattern in the capstone project on Day 30.

Common Mistakes on Day 23

  1. No timeout: a slow server can freeze your program indefinitely.
  2. Ignoring status codes: an error page may still produce a response, so check .ok or call raise_for_status().
  3. Building URLs by hand: use params= so special characters are encoded correctly.
  4. Hardcoding API keys: store them in environment variables instead.
  5. Calling .json() on a non-JSON response: it raises an error. Check the Content-Type header first, or catch the exception.
  6. Making requests in a tight loop: many APIs limit how often you can call them (status 429). Pause between calls with time.sleep().

Practicals

Use the httpbin.org test service for these exercises, so you don't need an API key. Try each one before looking at any hints.

Practical 1: Your Request Details

Send a GET request to https://httpbin.org/get, then print the status code and the origin IP address from the JSON response.

Practical 2: Search with Parameters

Use params= to send a search term and a page number to https://httpbin.org/get. Print both values from the args key of the response.

Practical 3: Handle a 404

Request https://httpbin.org/status/404. Print a friendly message instead of crashing, using response.ok.

Practical 4: Send a Form

POST a dictionary of a contact (name, email) to https://httpbin.org/post using json=. Print the data the server echoed back.

Practical 5: Timeout Test

Request https://httpbin.org/delay/5 with a timeout of 2 seconds. Catch the Timeout exception and print a message. Then change the timeout to 10 seconds and confirm it succeeds.

Practical 6: Reusable Fetcher

Write fetch_json(url, params) as shown in Lesson 8, then use it to request https://httpbin.org/get with two parameters. Test it with an invalid URL to see the error message appear, and confirm the function returns None.
