SQLite and Databases

Estimated time: about 1.5 hours · Why databases, sqlite3, tables, INSERT, SELECT, UPDATE, DELETE, parameterised queries, transactions

Lesson 1: Why a Database?

You've saved data to CSV and JSON files. Those work for small amounts of data, but they struggle when many records change, when you need to find one record quickly, or when several parts of a program need to update the same data safely.

Analogy: A CSV file is like a paper notebook. You can read it, but finding one entry means flipping pages. A database is like a filing cabinet with labelled drawers and an index, so you can find, add, and change records quickly.

SQLite is a database that lives in a single file. Python includes it in the sqlite3 module, so you don't need to install anything.

Lesson 2: Connecting and Creating a Table

Connecting to a file creates the database if it doesn't exist. A cursor runs SQL commands, and commit() saves changes.

import sqlite3

conn = sqlite3.connect("library.db")
cur = conn.cursor()

cur.execute("""
    CREATE TABLE IF NOT EXISTS books (
        id INTEGER PRIMARY KEY,
        title TEXT NOT NULL,
        author TEXT,
        year INTEGER
    )
""")
conn.commit()
conn.close()
print("Table ready")

Tip: Triple quotes let you write SQL across several lines, which keeps it readable.

Lesson 3: Inserting Data Safely

Never build SQL by joining text yourself. Use placeholders (?) and pass the values separately. This protects against SQL injection, where a malicious input changes the meaning of your command.

import sqlite3

conn = sqlite3.connect("library.db")
cur = conn.cursor()

cur.execute(
    "INSERT INTO books (title, author, year) VALUES (?, ?, ?)",
    ("Dune", "Frank Herbert", 1965),
)
cur.executemany(
    "INSERT INTO books (title, author, year) VALUES (?, ?, ?)",
    [("Emma", "Jane Austen", 1815), ("Ulysses", "James Joyce", 1922)],
)
conn.commit()
conn.close()
Never do this: f"INSERT ... VALUES ('{title}')". If the title contains a quote or SQL commands, the statement breaks or does something unintended. Always use ? placeholders.

Lesson 4: Reading Data with SELECT

import sqlite3

conn = sqlite3.connect("library.db")
cur = conn.cursor()

cur.execute("SELECT id, title, year FROM books WHERE year < ? ORDER BY year", (1950,))
for row in cur.fetchall():
    print(row)

conn.close()
(2, 'Emma', 1815) (3, 'Ulysses', 1922)
MethodReturns
fetchone()The next row as a tuple, or None
fetchall()A list of all remaining rows

Note: Dune (1965) is excluded because the WHERE clause keeps only books published before 1950. The output assumes the rows from Lesson 3 were inserted into an empty table, so Dune has id 1, Emma id 2, and Ulysses id 3.

Set conn.row_factory = sqlite3.Row to access columns by name, such as row["title"], which is clearer than positions.

Lesson 5: Updating and Deleting

import sqlite3

conn = sqlite3.connect("library.db")
cur = conn.cursor()

cur.execute("UPDATE books SET year = ? WHERE title = ?", (1966, "Dune"))
cur.execute("DELETE FROM books WHERE id = ?", (2,))
conn.commit()
print("Rows changed:", cur.rowcount)
conn.close()
Rows changed: 1
Be careful: An UPDATE or DELETE without a WHERE clause affects every row in the table. Always check your WHERE condition before running it.

Lesson 6: Using with for Connections

Like files on Day 11, connections can be used with with, which commits on success and rolls back on error.

import sqlite3

with sqlite3.connect("library.db") as conn:
    conn.execute("INSERT INTO books (title, author, year) VALUES (?, ?, ?)",
                 ("Hamlet", "William Shakespeare", 1603))
# committed automatically if no error occurred
Important: The with statement on a connection does not close it. Call conn.close() yourself when you finish, or use contextlib.closing.

Lesson 7: Transactions and Errors

A transaction groups several changes so they all happen or none do. If an error occurs before commit(), rollback() undoes the changes.

import sqlite3

conn = sqlite3.connect("library.db")
try:
    conn.execute("UPDATE books SET year = ? WHERE id = ?", (1900, 1))
    conn.execute("INSERT INTO books (title, year) VALUES (?, ?)", (None, 2000))
    conn.commit()
except sqlite3.IntegrityError as e:
    conn.rollback()
    print("Nothing was saved:", e)
finally:
    conn.close()
Nothing was saved: NOT NULL constraint failed: books.title

The first update was rolled back as well, because both changes belong to one transaction. This is the same try, except, finally pattern you learned on Day 12.

Lesson 8: Connecting Databases to Your Projects

Here's the library storage rewritten to use SQLite, with a small function for each action. The menu code from Day 21 can stay the same, because only the storage changes.

import sqlite3

DB = "library.db"

def add_book(title, author, year):
    with sqlite3.connect(DB) as conn:
        conn.execute("INSERT INTO books (title, author, year) VALUES (?, ?, ?)",
                     (title, author, year))

def list_books():
    with sqlite3.connect(DB) as conn:
        return conn.execute("SELECT title, author, year FROM books ORDER BY title").fetchall()

add_book("Dune", "Frank Herbert", 1965)
for title, author, year in list_books():
    print(f"{title} by {author} ({year})")
Dune by Frank Herbert (1965)

Notice that the database file is opened only when it's needed, and each function is short and focused.

Common Mistakes on Day 28

  1. Building SQL with f-strings: use ? placeholders to prevent SQL injection and quoting errors.
  2. Forgetting commit(): changes are lost if they are not committed.
  3. UPDATE or DELETE without WHERE: this changes every row.
  4. Leaving connections open: close them, or use a with block with a clear scope.
  5. Passing values as a single string: placeholders expect a tuple, such as (title,) for one value.
  6. Assuming fetchall() returns objects: it returns tuples unless you set a row factory.
