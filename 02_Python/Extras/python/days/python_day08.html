DAY 8 of 30

Functions: Reusable Code

Estimated time: about 1.5 hours · Defining functions, parameters, return values, default arguments, docstrings

Lesson 1: Why Functions?

A function is a named block of code you can run whenever you need it. Instead of copying the same lines in five places, you write them once and call the name five times. If the logic changes, you edit one place.

Analogy: A function is like a coffee machine. You press one button (call the function), and it performs the same steps every time. You can give it options (parameters) and it gives you back a result (return value). 
def greet():
    print("Hello from a function!")

greet()
greet()
Hello from a function! Hello from a function!

The def keyword defines the function. The indented lines form its body, and they only run when the function is called with greet(). Defining a function does nothing on its own.

Common mistake: Forgetting the parentheses. greet refers to the function object, while greet() runs it. Writing just greet does nothing visible.

Lesson 2: Parameters and Arguments

Parameters are the names listed in the function definition. Arguments are the actual values you pass in when you call it.

def greet_person(name):          # 'name' is a parameter
    print(f"Hello, {name}!")

greet_person("Sam")              # "Sam" is an argument
greet_person("Ali")
Hello, Sam! Hello, Ali!

Multiple parameters

def describe(name, age, city):
    print(f"{name} is {age} years old and lives in {city}.")

describe("Sara", 22, "Ahmedabad")
describe(city="Surat", name="Ravi", age=30)   # keyword arguments
Sara is 22 years old and lives in Ahmedabad. Ravi is 30 years old and lives in Surat.

Keyword arguments name each value explicitly, so their order doesn't matter. They make calls easier to read.

Tip: Choose parameter names that describe the data. def area(width, height) is much clearer than def area(a, b).

Lesson 3: Return Values

return sends a result back to the caller. Without return, a function returns None automatically. A function with return stops immediately at that line.

def add(a, b):
    return a + b

result = add(4, 6)
print(result)                 # 10
print(add(add(1, 2), 10))     # 13: you can use results directly
10 13

print() versus return

def show_total(x):
    print(x * 2)          # shows the value, does not give it back

def double(x):
    return x * 2          # gives the value back for further use

show_total(5)             # prints 10, but the value is lost
value = double(5)         # value is now 10
print(value + 1)          # 11
10 11
Key idea: Use print to show something to the user. Use return when another part of the program needs the result. Good functions usually return values, and the calling code decides what to show.

Returning multiple values

def min_max(numbers):
    return min(numbers), max(numbers)   # returns a tuple (Day 6)

low, high = min_max([4, 9, 1, 7])
print(low, high)
1 9

Lesson 4: Default Arguments

A parameter can have a default value. If the caller doesn't supply it, the default is used.

def greet(name, greeting="Hello"):
    return f"{greeting}, {name}!"

print(greet("Sam"))                 # Hello, Sam!
print(greet("Sam", "Good morning")) # Good morning, Sam!
Hello, Sam! Good morning, Sam!
Rule: Parameters with defaults must come after parameters without defaults. def f(a=1, b) is a SyntaxError.

The mutable default trap

Never use a list or dictionary as a default. It is created once and shared between calls, which causes surprising bugs.

def add_item(item, items=None):   # safe pattern
    if items is None:
        items = []
    items.append(item)
    return items

print(add_item("pen"))    # ['pen']
print(add_item("book"))   # ['book']  -- a fresh list each time
['pen'] ['book']

Use None as the default, then create the list inside the function. You'll see this pattern in many libraries.

Lesson 5: Writing Docstrings

A docstring is a short description placed as the first line inside a function. Python stores it, and tools and other developers can read it.

def celsius_to_fahrenheit(c):
    """Convert a temperature from Celsius to Fahrenheit."""
    return c * 9 / 5 + 32

print(celsius_to_fahrenheit(100))
print(celsius_to_fahrenheit.__doc__)
212.0 Convert a temperature from Celsius to Fahrenheit.

Write docstrings for any function that other people (or future you) will use. Describe what it does, not how.

Lesson 6: Scope (Local and Global Variables)

Variables created inside a function are local. They exist only while the function runs. Variables created outside any function are global.

message = "global"          # global

def show():
    message = "local"       # a new local variable, separate from the global
    print(message)

show()                      # local
print(message)              # global
local global
Analogy: A local variable is like a note on your desk. Only people in your office can see it. A global variable is a notice on the building's main board, visible to everyone.
Good practice: Pass data into a function with parameters and get results back with return. Avoid changing global variables from inside functions, because it makes programs hard to follow and debug.

Lesson 7: Putting It Together

Here's a small example combining parameters, defaults, return values, and a docstring. Read it, predict the output, then run it.

def calculate_bill(price, quantity, tax_rate=0.18):
    """Return the total bill including tax."""
    subtotal = price * quantity
    total = subtotal + subtotal * tax_rate
    return round(total, 2)

print(calculate_bill(100, 3))         # uses default 18% tax
print(calculate_bill(100, 3, 0.05))   # custom 5% tax
354.0 315.0

Common Mistakes on Day 8

  1. Forgetting parentheses: greet does not run the function. Use greet().
  2. Using print where you need return: the caller gets None and cannot use the value.
  3. Expecting code after return to run: return ends the function immediately.
  4. Mutable default arguments: use None and create the list inside the function.
  5. Wrong argument count: calling add(1) when the function needs two raises TypeError.
  6. Relying on global variables: pass what the function needs as parameters.
