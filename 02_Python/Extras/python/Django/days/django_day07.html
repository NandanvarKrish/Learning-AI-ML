Project Overview

This week you learned the building blocks of a Django site. Today you combine them into a small blog where visitors can read published posts, and where you can create, edit, and delete posts through the site.

Analogy: Each day you learned a single tool, such as a hammer or a saw. Today you build a bookshelf with all of them. The result matters more than any one cut.

Create a fresh project so the week's work stays separate from your earlier practice:

Step 2: Models

Use the author and post models from Day 3, with the same fields. This is the data layer for the whole project:

# blog/models.py
from django.db import models

class Author(models.Model):
    name = models.CharField(max_length=100)
    email = models.EmailField(unique=True)

    def __str__(self):
        return self.name

class Post(models.Model):
    author = models.ForeignKey(Author, on_delete=models.CASCADE, related_name="posts")
    title = models.CharField(max_length=200)
    body = models.TextField()
    cover = models.ImageField(upload_to="covers/", blank=True)
    created_at = models.DateTimeField(auto_now_add=True)
    is_published = models.BooleanField(default=False)

    class Meta:
        ordering = ["-created_at"]

    def __str__(self):
        return self.title
python manage.py makemigrations blog
python manage.py migrate
python manage.py createsuperuser
Before going further: Create one author and two posts in the admin, one published and one as a draft. You'll use these to test every page.

Step 4: Forms

# blog/forms.py
from django import forms
from .models import Post

class PostForm(forms.ModelForm):
    class Meta:
        model = Post
        fields = ["author", "title", "body", "cover", "is_published"]

    def clean_title(self):
        title = self.cleaned_data["title"].strip()
        if len(title) < 5:
            raise forms.ValidationError("Title must be at least 5 characters.")
        return title
Why cover is in the list: It's optional thanks to blank=True, so the form accepts posts with no image. Use enctype="multipart/form-data" on the template's form tag so uploads work (see Step 7).

Step 5: Views

Write each view as a small function that handles one job. The list shows only published posts, while the detail page refuses unpublished posts:

# blog/views.py
from django.shortcuts import get_object_or_404, redirect, render
from .forms import PostForm
from .models import Post

def post_list(request):
    posts = Post.objects.filter(is_published=True)
    return render(request, "blog/post_list.html", {"posts": posts})

def post_detail(request, post_id):
    post = get_object_or_404(Post, pk=post_id, is_published=True)
    return render(request, "blog/post_detail.html", {"post": post})

def post_create(request):
    if request.method == "POST":
        form = PostForm(request.POST, request.FILES)
        if form.is_valid():
            form.save()
            return redirect("post_list")
    else:
        form = PostForm()
    return render(request, "blog/post_form.html", {"form": form})

def post_edit(request, post_id):
    post = get_object_or_404(Post, pk=post_id)
    if request.method == "POST":
        form = PostForm(request.POST, request.FILES, instance=post)
        if form.is_valid():
            form.save()
            return redirect("post_detail", post_id=post.id)
    else:
        form = PostForm(instance=post)
    return render(request, "blog/post_form.html", {"form": form, "post": post})

def post_delete(request, post_id):
    post = get_object_or_404(Post, pk=post_id)
    if request.method == "POST":
        post.delete()
        return redirect("post_list")
    return render(request, "blog/post_confirm_delete.html", {"post": post})
Important: File uploads arrive in request.FILES, not request.POST. Forms with an image must receive both, as shown above.
Delete is a POST: A GET request only shows the confirmation page. Only the POST actually deletes. This stops a link or image from deleting a post by accident.

Step 6: URLs

# blog/urls.py
from django.urls import path
from . import views

urlpatterns = [
    path("posts/", views.post_list, name="post_list"),
    path("posts/new/", views.post_create, name="post_create"),
    path("posts/<int:post_id>/", views.post_detail, name="post_detail"),
    path("posts/<int:post_id>/edit/", views.post_edit, name="post_edit"),
    path("posts/<int:post_id>/delete/", views.post_delete, name="post_delete"),
]
# miniblog/urls.py
from django.conf import settings
from django.conf.urls.static import static
from django.contrib import admin
from django.urls import include, path

urlpatterns = [
    path("admin/", admin.site.urls),
    path("", include("blog.urls")),
] + static(settings.MEDIA_URL, document_root=settings.MEDIA_ROOT)
Named routes: Every link in the templates uses {% url 'name' %}. If you ever change an address, the links still work.

Step 7: Templates and Static Files

Build the shared layout first. Every page extends it:

# templates/base.html
{% load static %}
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>{% block title %}Mini Blog{% endblock %}</title>
  <link rel="stylesheet" href="{% static 'blog/style.css' %}">
</head>
<body>
  <nav>
    <a href="{% url 'post_list' %}">All posts</a>
    <a href="{% url 'post_create' %}">New post</a>
    <a href="/admin/">Admin</a>
  </nav>
  <main>{% block content %}{% endblock %}</main>
  <footer>Mini Blog &copy; 2026</footer>
</body>
</html>

The list page loops over posts and handles the empty case:

# blog/templates/blog/post_list.html
{% extends "base.html" %}
{% block content %}
  <h1>Latest posts</h1>
  {% for post in posts %}
    <article>
      <h2><a href="{% url 'post_detail' post.id %}">{{ post.title }}</a></h2>
      <p>By {{ post.author.name }} on {{ post.created_at|date:"d M Y" }}</p>
      <p>{{ post.body|truncatewords:25 }}</p>
    </article>
  {% empty %}
    <p>No published posts yet.</p>
  {% endfor %}
{% endblock %}

The detail page includes the cover image, edit and delete links, and the body:

# blog/templates/blog/post_detail.html
{% extends "base.html" %}
{% block title %}{{ post.title }}{% endblock %}
{% block content %}
  <h1>{{ post.title }}</h1>
  <p>By {{ post.author.name }} on {{ post.created_at|date:"d M Y" }}</p>
  {% if post.cover %}
    <img src="{{ post.cover.url }}" alt="{{ post.title }}">
  {% endif %}
  <div>{{ post.body|linebreaks }}</div>
  <p>
    <a href="{% url 'post_edit' post.id %}">Edit</a> |
    <a href="{% url 'post_delete' post.id %}">Delete</a>
  </p>
{% endblock %}

The form template handles both creating and editing, and it needs enctype for uploads:

# blog/templates/blog/post_form.html
{% extends "base.html" %}
{% block content %}
  <h1>{% if post %}Edit post{% else %}New post{% endif %}</h1>
  <form method="post" enctype="multipart/form-data">
    {% csrf_token %}
    {{ form.as_p }}
    <button type="submit">Save</button>
  </form>
{% endblock %}

The delete confirmation page sends a POST, with a token:

# blog/templates/blog/post_confirm_delete.html
{% extends "base.html" %}
{% block content %}
  <h1>Delete "{{ post.title }}"?</h1>
  <p>This cannot be undone.</p>
  <form method="post">
    {% csrf_token %}
    <button type="submit">Yes, delete it</button>
    <a href="{% url 'post_detail' post.id %}">Cancel</a>
  </form>
{% endblock %}

Step 8: Test by Hand

Check each item before you call the project finished. Real testing finds more problems than reading code does.

  • Visit /posts/ and confirm only the published post appears.
  • Visit the detail page for the draft post and confirm you get a 404 page.
  • Create a new post with a title shorter than 5 characters and confirm the error appears.
  • Create a valid post with a cover image and confirm the image appears on its detail page.
  • Edit a post and confirm the same post is updated, not duplicated.
  • Delete a post, confirm the page, and confirm it no longer appears in the list.
  • Visit /posts/1/delete/ without submitting and confirm nothing is deleted.
  • Check the admin still shows every post, including drafts.
Debug tip: When something breaks, read the traceback from the bottom up. The last line names the error, and the lines above show where in your code it happened.

Step 9: Save to Git

Put the finished project under version control, as you learned on Day 29. Keep personal data and uploads out of the repository:

printf "venv/\n__pycache__/\n*.pyc\ndb.sqlite3\nmedia/\nstaticfiles/\n" > .gitignore
git init
git add .

Common Mistakes at This Stage

  1. Forgetting request.FILES: the cover upload is silently ignored.
  2. Missing enctype="multipart/form-data": the browser sends only the file name, or nothing.
  3. Deleting with GET: always use a POST form for destructive actions.
  4. Showing drafts on public pages: filter with is_published=True in every public view.
  5. Hard-coding addresses: use {% url %} everywhere.
