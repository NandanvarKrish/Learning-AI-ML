Search and Filtering

Estimated time: about 1.5 hours · GET forms, reading query parameters, combining search with filters, safe sorting, keeping filters across pages, and when to use full-text search

Lesson 1: Search Is a GET Request

Searching doesn't change any data, so it should use GET. The search terms travel in the address, such as /search/?q=django&tag=python. That makes results bookmarkable and shareable, and it's the reason search forms use method="get".

Analogy: A search is like asking a librarian a question. Nothing is borrowed or changed, so you can repeat the question as often as you like. A POST is more like checking out a book, which changes records.
Rule of thumb: Use GET for anything that only reads, and POST for anything that changes data (Day 6). Never delete or change records through a GET request.

Lesson 2: Reading Query Parameters

Values from the address are available in request.GET, a dictionary-like object. Always give get() a default, because the user may not have typed anything:

>>> # for the address /search/?q=django
>>> request.GET.get("q", "")
>>> request.GET.get("tag")
>>> request.GET.get("q", "").strip()
'django' None 'django'

Missing parameters return the default you give, or None when you give none. Treat every query parameter as untrusted input, the same way you treat form data.

Lesson 3: Searching Text

Combine several fields with Q objects (Day 9). icontains gives a case-insensitive match anywhere in the text:

>>> from django.db.models import Q

>>> term = "django"
>>> Post.objects.filter(
...     Q(title__icontains=term) | Q(body__icontains=term)
... ).order_by("title")
<QuerySet [<Post: Django forms made easy>, <Post: Model tips>]>

The output depends on your data. Here, one post has the word in its title and another has it only in its body.

Safe by default: The ORM turns the search term into a parameter, so text like '; DROP TABLE is treated as plain text. Don't build search SQL with f-strings, even when it seems simple.

Lesson 4: Filters from Dropdowns

Filters such as a tag or author are chosen from a list. Skip the filter when its parameter is empty, so the same view handles every combination:

# blog/views.py
from django.db.models import Q
from django.views.generic import ListView
from .models import Post, Tag

class PostSearchView(ListView):
    model = Post
    template_name = "blog/post_search.html"
    context_object_name = "posts"
    paginate_by = 5

    SORT_OPTIONS = {
        "newest": "-created_at",
        "oldest": "created_at",
        "title": "title",
    }

    def get_queryset(self):
        qs = Post.objects.filter(is_published=True).select_related("author")

        term = self.request.GET.get("q", "").strip()
        if term:
            qs = qs.filter(Q(title__icontains=term) | Q(body__icontains=term))

        tag = self.request.GET.get("tag", "")
        if tag:
            qs = qs.filter(tags__name=tag).distinct()

        sort = self.request.GET.get("sort", "newest")
        return qs.order_by(self.SORT_OPTIONS.get(sort, "-created_at"))

    def get_context_data(self, **kwargs):
        context = super().get_context_data(**kwargs)
        context["tags"] = Tag.objects.order_by("name")
        context["q"] = self.request.GET.get("q", "")
        params = self.request.GET.copy()
        params.pop("page", None)
        context["query_string"] = params.urlencode()
        return context
Whitelist sort options: The SORT_OPTIONS dictionary accepts only the names you list. Passing a raw parameter to order_by() would let visitors order by any field, including ones you meant to hide.
Why .distinct() here: A post with two matching tags is not an issue for a single tag filter, but it becomes one if you later allow several tags at once. Adding it now prevents duplicates later.

Lesson 5: The Search Form

The template shows the form and keeps the user's choices filled in after the search runs:

# blog/templates/blog/post_search.html
{% extends "base.html" %}
{% block content %}
  <form method="get">
    <input type="search" name="q" value="{{ q }}" placeholder="Search posts">
    <select name="tag">
      <option value="">All tags</option>
      {% for t in tags %}
        <option value="{{ t.name }}" {% if request.GET.tag == t.name %}selected{% endif %}>{{ t.name }}</option>
      {% endfor %}
    </select>
    <select name="sort">
      <option value="newest" {% if request.GET.sort == "newest" %}selected{% endif %}>Newest</option>
      <option value="oldest" {% if request.GET.sort == "oldest" %}selected{% endif %}>Oldest</option>
      <option value="title" {% if request.GET.sort == "title" %}selected{% endif %}>Title</option>
    </select>
    <button type="submit">Search</button>
  </form>

  <p>{{ posts|length }} result(s) on this page.</p>
  {% for post in posts %}
    <article>
      <h2><a href="{% url 'post_detail' post.pk %}">{{ post.title }}</a></h2>
      <p>{{ post.body|truncatewords:20 }}</p>
    </article>
  {% empty %}
    <p>No posts match your search.</p>
  {% endfor %}

  {% if is_paginated %}
    {% if page_obj.has_previous %}
      <a href="?page={{ page_obj.previous_page_number }}&{{ query_string }}">Previous</a>
    {% endif %}
    {% if page_obj.has_next %}
      <a href="?page={{ page_obj.next_page_number }}&{{ query_string }}">Next</a>
    {% endif %}
  {% endif %}
{% endblock %}
Keeping filters across pages: The query_string variable holds every filter except page. Without it, clicking Next would drop the search term and tag.

Lesson 6: Testing Search

Search logic is easy to test with the Django test client (Day 13), so test each filter alone and then together:

class PostSearchTests(TestCase):
    @classmethod
    def setUpTestData(cls):
        author = Author.objects.create(name="Asha", email="asha@example.com")
        Post.objects.create(author=author, title="Django forms", body="Forms", is_published=True)
        Post.objects.create(author=author, title="Python basics", body="Loops", is_published=True)
        Post.objects.create(author=author, title="Draft django", body="Hidden", is_published=False)

    def test_search_matches_title_case_insensitively(self):
        response = self.client.get(reverse("post_search"), {"q": "DJANGO"})
        self.assertContains(response, "Django forms")
        self.assertNotContains(response, "Python basics")

    def test_drafts_never_appear(self):
        response = self.client.get(reverse("post_search"), {"q": "django"})
        self.assertNotContains(response, "Draft django")

    def test_invalid_sort_falls_back_to_newest(self):
        response = self.client.get(reverse("post_search"), {"sort": "drop_table"})
        self.assertEqual(response.status_code, 200)
Test the hidden rules: The most important test here is that drafts never appear in search. A search bug that leaks drafts is easy to miss if you only test the happy path.

Lesson 7: Beyond icontains

icontains scans every row, which is fine for small sites. Larger sites need more:

ApproachGood for
icontains with QSmall tables and simple matching (what you built today)
Database indexes on searched fieldsSpeeding up exact and prefix matches
PostgreSQL full-text search (SearchVector, SearchQuery)Ranking results by relevance, stemming words, and handling many languages
Dedicated search engines (Elasticsearch, Meilisearch)Very large catalogues with typo tolerance and facets
django-filter packageBuilding many filter forms without writing each one by hand
Start simple: Build the plain version first, measure, and add more power only when real users need it.

Common Mistakes on Day 19

  1. Using POST for search: results can't be bookmarked, and the browser asks to resubmit on refresh.
  2. Passing raw parameters to order_by: whitelist allowed sort fields.
  3. Forgetting to keep filters in pagination links: the next page loses the search.
  4. Showing drafts in search: filter with is_published=True before applying search terms.
  5. Assuming an empty search means all results: decide whether empty input shows everything, nothing, or the latest posts, and test that choice.

Practical 2: Tag Filter

Practical 3: Sorting

Add the sort dropdown with the whitelist. Try ?sort=title and ?sort=unknown, and confirm the second falls back to newest.

Set paginate_by = 2, create enough matching posts for two pages, and confirm the Next link keeps the search term and tag.

Practical 5: Tests

Write the three tests from Lesson 6 and run them. Then add one test that a search for a tag returns only that tag's posts.
