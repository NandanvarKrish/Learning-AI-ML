Templates

Estimated time: about 1.5 hours · The Django template language, variables, filters, loops, conditions, template inheritance, include, and rendering real data

Lesson 1: What Templates Do

A template is an HTML file with placeholders. The view supplies the data, and Django fills the placeholders to produce the final page. HTML handles the layout; Python handles the data.

Analogy: A template is a letter with blanks, such as "Dear ___, your order of ___ has shipped." The blanks are filled in for each customer. The letter's design stays the same every time.

Up to now your views returned plain strings. Templates let you build proper pages.

Lesson 2: Variables, Filters, and Tags

The template language has three building blocks:

SyntaxNameExample
{{ ... }}Variable{{ post.title }}
{% ... %}Tag (logic){% for post in posts %}
{# ... #}Comment (not sent to the browser){# remove later #}
|Filter (changes a value){{ post.title|upper }}

Useful filters:

{{ post.title|upper }}              {# AUTHOR MODEL TIPS #}
{{ post.body|truncatechars:20 }}    {# Keep models sm... #}
{{ post.author.name|default:"Unknown" }}
{{ post.created_at|date:"d M Y" }}  {# formatted date #}
{{ posts|length }}                  {# number of items #}
Automatic escaping: Django escapes HTML by default. If a title contains <b>, it appears as text, not bold. This protects your site from script injection (XSS). Only use |safe on content you fully trust.

Lesson 3: Loops and Conditions

{% if posts %}
  <ul>
  {% for post in posts %}
    <li>{{ forloop.counter }}. {{ post.title }} by {{ post.author.name }}</li>
  {% empty %}
    <li>Nothing here yet.</li>
  {% endfor %}
  </ul>
{% else %}
  <p>No posts available.</p>
{% endif %}
  • forloop.counter counts from 1, and forloop.first and forloop.last are True for the first and last items.
  • {% empty %} runs when the list has nothing in it, which avoids an extra if.
  • Conditions can use ==, !=, >, in, and, or, and not.
Limit of templates: The template language is deliberately simple. It can't do arbitrary Python. Put complicated logic in the view or the model, not the template.

Lesson 4: Rendering a Template from a View

Templates live in an app's templates folder. Create this structure inside the blog app:

blog/ └── templates/ └── blog/ └── post_list.html

The nested blog/ folder prevents name clashes with templates from other apps. Django finds templates automatically because APP_DIRS is enabled in settings.

Write a view that gives the template its data:

# blog/views.py
from django.shortcuts import render
from .models import Post

def post_list(request):
    posts = Post.objects.filter(is_published=True)
    return render(request, "blog/post_list.html", {"posts": posts})

The third argument to render() is the context: a dictionary whose keys become variable names in the template.

Add the URL in blog/urls.py:

path("posts/", views.post_list, name="post_list"),

A simple template with one list:

# blog/templates/blog/post_list.html
<h1>Posts</h1>
<ul>
{% for post in posts %}
  <li>{{ post.title }} by {{ post.author.name }}</li>
{% empty %}
  <li>No published posts yet.</li>
{% endfor %}
</ul>

If the database holds one published post, "Model tips" by "Asha", the page at /posts/ contains:

<h1>Posts</h1> <ul> <li>Model tips by Asha</li> </ul>

The output shows the HTML the browser receives. The exact whitespace may differ from your template, which is normal.

Lesson 5: Template Inheritance

Most pages share a header, navigation, and footer. Write them once in a base template, then let each page extend it.

# blog/templates/base.html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>{% block title %}My Blog{% endblock %}</title>
</head>
<body>
  <nav><a href="/">Home</a> | <a href="/posts/">Posts</a></nav>
  <main>
    {% block content %}{% endblock %}
  </main>
  <footer>&copy; My Blog</footer>
</body>
</html>
# blog/templates/blog/post_list.html
{% extends "base.html" %}

{% block title %}Posts{% endblock %}

{% block content %}
  <h1>Posts</h1>
  {% for post in posts %}
    <p>{{ post.title }}</p>
  {% endfor %}
{% endblock %}

{% extends %} must be the first tag in the child template. Anything outside a {% block %} in the child is ignored.

Where to put base.html: Keeping it in the project-level templates folder is common. Then add that folder to TEMPLATES[0]["DIRS"] in settings.py, as [BASE_DIR / "templates"].

Lesson 6: include and url

Use {% include %} to reuse a small piece, such as a post card:

# blog/templates/blog/_post_card.html
<article>
  <h2>{{ post.title }}</h2>
  <p>{{ post.body|truncatewords:15 }}</p>
</article>

# in post_list.html
{% for post in posts %}
  {% include "blog/_post_card.html" %}
{% endfor %}

Never hard-code links such as /posts/. Use the url tag with the name you gave the route. If the address changes later, every link still works.

<a href="{% url 'post_list' %}">All posts</a>
<a href="{% url 'greet' name='Sam' %}">Say hello</a>
<a href="/posts/">All posts</a> <a href="/greet/Sam/">Say hello</a>
Common error: A misspelled name in {% url %} raises NoReverseMatch. Check that the name= in urls.py matches exactly.

Lesson 7: Putting It Together

A complete detail page shows the template language working together:

# blog/views.py
def post_detail(request, post_id):
    post = get_object_or_404(Post, pk=post_id, is_published=True)
    return render(request, "blog/post_detail.html", {"post": post})

get_object_or_404 returns the post, or a standard "Page not found" response if it doesn't exist. This is far safer than Post.objects.get(), which would crash the page. Don't forget to import it: from django.shortcuts import get_object_or_404, render.

# blog/templates/blog/post_detail.html
{% extends "base.html" %}
{% block title %}{{ post.title }}{% endblock %}
{% block content %}
  <h1>{{ post.title }}</h1>
  <p>By {{ post.author.name }} on {{ post.created_at|date:"d M Y" }}</p>
  <div>{{ post.body|linebreaks }}</div>
  <p><a href="{% url 'post_list' %}">Back to all posts</a></p>
{% endblock %}
Note: linebreaks turns newlines in the body into paragraphs. It also escapes the text, so the content stays safe.

Common Mistakes on Day 4

  1. Putting the template in the wrong folder: it must be inside app/templates/app/ (or a folder listed in DIRS), or Django reports "TemplateDoesNotExist".
  2. Writing {% extends %} after other content: it must be the first tag.
  3. Using |safe on user input: it turns off escaping and opens the door to script injection.
  4. Hard-coding URLs: use {% url %} so links survive route changes.
  5. Doing heavy logic in templates: filter and calculate in the view or model.

Practicals

Continue in your mysite project. Visit each page in the browser after you build it.

Practical 1: Your First Template

Create blog/templates/blog/post_list.html and the post_list view from Lesson 4. Visit /posts/ and confirm the published posts appear.

Practical 2: Base Layout

Create base.html with a navigation bar and footer. Make post_list.html extend it, and confirm the navigation shows on the posts page.

Practical 3: Filters and Empty State

Show each post's title in uppercase using a filter, and show its body truncated to 30 characters. Use {% empty %} to display a message when there are no posts. Test the empty message by unpublishing every post in the admin.

Practical 4: Detail Page

Build the post_detail view and template from Lesson 7. Add a link from each item in the list to its detail page, using {% url 'post_detail' post.id %} with a matching route.

Practical 5: Escaping Test

Create a post whose title is <b>Bold?</b>. Look at the page and explain, in one sentence, why the tags appear as text instead of making the title bold.
