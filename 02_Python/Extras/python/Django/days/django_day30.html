Lesson 1: Welcome to the Capstone

Thirty days ago you had no Django project. Today you bring every idea together. The capstone is not a new topic. It is a checklist of what you already know, arranged into one working product.

Analogy: Each day gave you a tool. Today you build the house. You don't need new tools, but you need to know which tool goes where, in what order.

You will build a small web app of your choice. The examples below use a Bookmark Manager, where users save links, tag them, search them, and share a public list. Any app with similar parts works.

Lesson 5: The Core Model

Start with the data. The model below uses several ideas from the course: a custom queryset, a many-to-many relation, a constraint, and an index:

# bookmarks/models.py
from django.conf import settings
from django.db import models
from django.urls import reverse

class BookmarkQuerySet(models.QuerySet):
    def public(self):
        return self.filter(is_public=True)

class Tag(models.Model):
    name = models.SlugField(max_length=40, unique=True)

    def __str__(self):
        return self.name

class Bookmark(models.Model):
    owner = models.ForeignKey(settings.AUTH_USER_MODEL,
                              on_delete=models.CASCADE, related_name="bookmarks")
    url = models.URLField(max_length=500)
    title = models.CharField(max_length=200)
    note = models.TextField(blank=True)
    tags = models.ManyToManyField(Tag, blank=True, related_name="bookmarks")
    is_public = models.BooleanField(default=False)
    created_at = models.DateTimeField(auto_now_add=True)

    objects = BookmarkQuerySet.as_manager()

    class Meta:
        ordering = ["-created_at"]
        constraints = [
            models.UniqueConstraint(fields=["owner", "url"], name="unique_bookmark_per_owner"),
        ]
        indexes = [
            models.Index(fields=["is_public", "-created_at"], name="public_recent_idx"),
        ]

    def get_absolute_url(self):
        return reverse("bookmarks:detail", args=[self.pk])
Decisions baked in: on_delete=CASCADE removes a user's bookmarks with the account. The unique constraint stops duplicate saves per owner. The index supports the public list from Day 29.

Lesson 6: Views and Permissions

Use class-based views for the pages, and reuse the ownership rule from Day 17 and Day 26:

# bookmarks/views.py
from django.contrib.auth.mixins import LoginRequiredMixin
from django.db.models import Q
from django.views.generic import ListView, DetailView, CreateView
from django.http import JsonResponse
from django.db import connection
from .models import Bookmark
from .forms import BookmarkForm

class MyBookmarks(LoginRequiredMixin, ListView):
    template_name = "bookmarks/list.html"
    paginate_by = 10

    def get_queryset(self):
        qs = Bookmark.objects.filter(owner=self.request.user)
        q = self.request.GET.get("q", "").strip()
        if q:
            qs = qs.filter(Q(title__icontains=q) | Q(note__icontains=q))
        return qs.prefetch_related("tags")

class PublicList(ListView):
    template_name = "bookmarks/public.html"
    paginate_by = 10

    def get_queryset(self):
        return Bookmark.objects.public().select_related("owner").prefetch_related("tags")

class BookmarkDetail(DetailView):
    model = Bookmark
    template_name = "bookmarks/detail.html"

    def get_queryset(self):
        # Owners see private bookmarks too; everyone else sees public ones only
        qs = Bookmark.objects.all()
        if self.request.user.is_authenticated:
            return qs.filter(Q(is_public=True) | Q(owner=self.request.user))
        return qs.filter(is_public=True)

class BookmarkCreate(LoginRequiredMixin, CreateView):
    model = Bookmark
    form_class = BookmarkForm
    template_name = "bookmarks/form.html"

    def form_valid(self, form):
        form.instance.owner = self.request.user      # set by the server
        return super().form_valid(form)

def health(request):
    try:
        with connection.cursor() as cursor:
            cursor.execute("SELECT 1")
        return JsonResponse({"status": "ok"})
    except Exception:
        return JsonResponse({"status": "error"}, status=503)
Hide, don't just block: The detail view filters the queryset, so someone else's private bookmark returns 404, not a hint that it exists. This matches the advice from Day 25.

Lesson 7: The API

A mobile app needs the same data through the API. Reuse the serializer, the ownership permission, and the token and throttle setup from Days 24 to 27:

# bookmarks/api.py
from rest_framework import permissions, serializers, viewsets
from rest_framework.throttling import ScopedRateThrottle
from .models import Bookmark
from .permissions import IsOwnerOrReadOnly

class BookmarkSerializer(serializers.ModelSerializer):
    owner = serializers.HiddenField(default=serializers.CurrentUserDefault())
    tags = serializers.SlugRelatedField(many=True, read_only=True, slug_field="name")

    class Meta:
        model = Bookmark
        fields = ["id", "owner", "url", "title", "note", "tags", "is_public", "created_at"]

class BookmarkViewSet(viewsets.ModelViewSet):
    serializer_class = BookmarkSerializer
    permission_classes = [permissions.IsAuthenticated, IsOwnerOrReadOnly]
    throttle_classes = [ScopedRateThrottle]
    throttle_scope = "bookmarks"

    def get_queryset(self):
        return Bookmark.objects.filter(owner=self.request.user).prefetch_related("tags")
HiddenField for ownership: CurrentUserDefault sets the owner from the token, so clients can't post as someone else. It's the API version of form_valid above.

Lesson 8: Tests That Protect the Rules

Test the rules that matter most. These four checks guard the app's core promises:

from django.contrib.auth.models import User
from django.test import TestCase
from django.urls import reverse
from bookmarks.models import Bookmark

class PrivacyTests(TestCase):
    @classmethod
    def setUpTestData(cls):
        cls.asha = User.objects.create_user("asha", password="x-pass-123")
        cls.ravi = User.objects.create_user("ravi", password="y-pass-456")
        cls.private = Bookmark.objects.create(owner=cls.asha, url="https://a.example",
                                              title="Secret", is_public=False)
        cls.public = Bookmark.objects.create(owner=cls.asha, url="https://b.example",
                                             title="Shared", is_public=True)

    def test_anonymous_cannot_see_private(self):
        response = self.client.get(reverse("bookmarks:detail", args=[self.private.pk]))
        self.assertEqual(response.status_code, 404)

    def test_other_user_cannot_see_private(self):
        self.client.force_login(self.ravi)
        response = self.client.get(reverse("bookmarks:detail", args=[self.private.pk]))
        self.assertEqual(response.status_code, 404)

    def test_owner_sees_private(self):
        self.client.force_login(self.asha)
        response = self.client.get(reverse("bookmarks:detail", args=[self.private.pk]))
        self.assertEqual(response.status_code, 200)

    def test_public_list_hides_private(self):
        response = self.client.get(reverse("bookmarks:public"))
        self.assertContains(response, "Shared")
        self.assertNotContains(response, "Secret")

Write these first: Privacy tests protect users from the worst bugs. If you add one test today, make it the one that checks a private bookmark stays private.

Lesson 9: Ship It

Shipping follows the path from Days 21, 22, 28 and 29. Work through this checklist in order:

  • Settings split into base, dev, and prod, with secrets read from the environment
  • DEBUG = False and ALLOWED_HOSTS set in production
  • python manage.py check --deploy run and its warnings reviewed
  • Dockerfile and .dockerignore written, with no secrets copied into the image
  • Docker Compose stack with Postgres and a named volume for data
  • Migrations applied inside the container
  • Gunicorn behind Nginx (or a managed platform) with HTTPS
  • Health endpoint responding at /health/
  • Error tracking enabled through an environment variable
  • CI pipeline green on the main branch
  • Backups tested by restoring them to a second database
Release order from Day 22: Run migrations before restarting the new code, and keep the old version running until the new one passes its health check.

Lesson 10: Review Your Work

Before calling the project done, review it the way a teammate would:

  • Every view that changes data requires login or a permission check
  • Every queryset that shows user data is filtered by owner or public status
  • No secret, password, or token appears in Git history or in templates
  • List pages use pagination, and the queries are counted in at least one test
  • Forms and the API validate input, and return clear errors
  • The README explains how to run the app locally and in Docker
Reviewing is a skill: Read your own code as if you had never seen it. The places you feel unsure are where bugs usually hide.

Common Mistakes on Day 30

  1. Building too many features at once: finish the five core features before adding any extras.
  2. Skipping the privacy tests: they catch the bugs users are most affected by.
  3. Trusting client-supplied owners: set ownership on the server, in form_valid or HiddenField.
  4. Deploying with DEBUG = True: run check --deploy before every release.
  5. Forgetting to test a restore: a backup you have never restored is only a hope.
  6. Waiting for perfect code before shipping: a working, tested, deployed app teaches you more than a perfect app on your laptop.

Practicals

Build your own capstone app. The Bookmark Manager is an example; a recipe book, a habit tracker, or a small inventory app works just as well.

Practical 1: Plan

Complete the table in Lesson 2 for your app. List five core features and the features you will leave for later.

Practical 2: Core Model and Admin

Write your models with at least one ForeignKey, one ManyToMany, and a constraint. Register them in the admin and add some sample data.

Practical 3: Pages and Auth

Build list, detail, create, and edit pages with class-based views. Add sign-up and login, and protect the private pages.

Practical 4: Privacy and API

Write the four privacy tests from Lesson 8. Add an API with a serializer, token authentication, and an ownership permission.

Practical 5: Ship

Containerise the app with Docker Compose, add the health endpoint and CI workflow, and deploy it to a server or a managed platform. Share the link with someone who can test it.
