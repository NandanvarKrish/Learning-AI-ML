The Card Catalog:
Understanding Python Dictionaries

Before search engines, libraries found any book in seconds using a card catalog — one label, one card, no scanning the whole shelf. Python's dictionary works the same way, and it's the idea we'll use to understand every part of it.

What you'll walk away with: how dictionaries store and find data, every core operation and method, dict comprehensions, nested dictionaries, why keys must be "hashable," a full real-world build (a contact book program) done step by step, and a 15-question quiz to check what stuck.

Topic 01

What a dictionary actually is

A Python dictionary stores data as key → value pairs. Instead of finding something by counting position (like a list: "give me item #3"), you find it by name: "give me the value stored under this key."

Real-world analogy In a library card catalog, every book has an index card filed under its title. You never walk every shelf looking for "1984" — you go straight to the "1" drawer, flip to the "1984" card, and it tells you exactly where the book sits. The title is the key, the card's info is the value, and the whole cabinet is the dictionary. 
# A dictionary of book locations, like catalog cards
catalog = {
    "1984": "Fiction, Shelf 4B",
    "Sapiens": "History, Shelf 2A",
    "Dune": "Sci-Fi, Shelf 5C"
}

# Straight to the card — no searching shelf by shelf
print(catalog["Dune"])   # Sci-Fi, Shelf 5C

Key properties, in plain terms

Keys are unique

A catalog only has one card per title. Adding a second card for "1984" doesn't create a duplicate — it overwrites the first.

Keys must be immutable

Card labels can't change shape mid-search. Strings, numbers, and tuples work as keys; lists don't.

Order is preserved

Since Python 3.7, dictionaries remember the order you added things — like cards staying in the order they were filed.

Mutable overall

You can add, remove, or update cards anytime, even though each key itself must stay fixed.

Topic 02

Creating dictionaries

There are several ways to open a fresh "drawer," depending on what data you're starting with.

Real-world analogy Sometimes you start a new catalog drawer empty and file cards one by one. Sometimes a librarian hands you a stack of cards already paired up, and you drop them all into the drawer at once. Both are valid ways to build the same catalog.

Literal syntax — the most common way

student = {"name": "Maya", "grade": 10, "passed": True}

The dict() constructor

student = dict(name="Maya", grade=10, passed=True)

# from a list of (key, value) pairs — like pairing loose cards
pairs = [("a", 1), ("b", 2)]
d = dict(pairs)   # {'a': 1, 'b': 2}

Starting empty

empty_drawer = {}          # most common
also_empty = dict()      # same result, slightly slower to type

fromkeys() — same starting value for every card

Useful when you want several keys to all start out identical, like resetting every student's attendance to zero at term start.

attendance = dict.fromkeys(["Maya", "Leo", "Sam"], 0)
# {'Maya': 0, 'Leo': 0, 'Sam': 0}
Topic 03

Reading, adding, updating, deleting

Real-world analogy Reading a card is fine — but what if the card doesn't exist? A careless librarian who assumes every title has a card will panic when one's missing. A careful one checks first, or has a standard "not found" response ready.

Reading a value

catalog = {"1984": "Shelf 4B"}

catalog["1984"]            # 'Shelf 4B'  — crashes with KeyError if missing
catalog.get("1984")        # 'Shelf 4B'  — safe, returns None if missing
catalog.get("Emma", "Not filed") # fallback value instead of None

.get() is the "safe" read — like a librarian who says "no card for that title" instead of freezing when a book isn't catalogued.

Adding or updating

# adding a brand-new card, or overwriting an existing one
catalog["Dune"] = "Shelf 5C"
catalog["1984"] = "Shelf 4C"   # moved shelves — card updated in place

# merging many cards at once
catalog.update({"Sapiens": "Shelf 2A", "Emma": "Shelf 4A"})

Deleting

del catalog["Dune"]              # removes the card, errors if missing
catalog.pop("Sapiens")            # removes AND hands you the value back
catalog.pop("Ghost", "none")     # safe pop with a fallback
catalog.clear()                    # empties the whole drawer

setdefault() — file it only if it's missing

# if "Emma" has no card yet, file one; otherwise leave it alone
catalog.setdefault("Emma", "Unfiled")
Topic 04

The methods worth knowing well

These three are how you pull data out of the drawer in bulk — all the titles, all the shelf numbers, or every card as a pair.

.keys()

Every card's title — like reading just the tabs on the front of each card.

.values()

Every card's content, ignoring the titles — just the shelf numbers.

.items()

Every full card, title and content together, as (key, value) pairs.

len(d)

How many cards are in the drawer.

catalog = {"1984": "4B", "Dune": "5C"}

catalog.keys()    # dict_keys(['1984', 'Dune'])
catalog.values()  # dict_values(['4B', '5C'])
catalog.items()   # dict_items([('1984', '4B'), ('Dune', '5C')])
len(catalog)     # 2

"Dune" in catalog   # True — checks keys, not values, and it's fast
Real-world analogy in is like glancing at the drawer's tab index instead of flipping through every card — because the catalog is organized by key, checking "do we have this title?" is nearly instant no matter how big the drawer is.
Topic 05

Looping through a dictionary

Looping is like a librarian doing a full inventory sweep, card by card, in the order they were filed.

catalog = {"1984": "4B", "Dune": "5C", "Sapiens": "2A"}

# just the titles
for title in catalog:
    print(title)

# title + shelf, the natural way to read a full card
for title, shelf in catalog.items():
    print(f"{title} is on shelf {shelf}")

# just the shelf numbers
for shelf in catalog.values():
    print(shelf)
Watch out Never add or delete cards from the drawer while you're sweeping through it — Python raises a RuntimeError because the inventory count shifts mid-count. Build a list of changes first, then apply them after the loop finishes.
Topic 06

Dict comprehensions

A comprehension is a one-line assembly line: it takes a stack of raw material and files a card for each item automatically, following a rule you give it.

# squares of 1 through 5, filed as {number: square}
squares = {n: n**2 for n in range(1, 6)}
# {1: 1, 2: 4, 3: 9, 4: 16, 5: 25}

# only file cards that pass a condition
words = ["fig", "apple", "kiwi", "banana"]
long_words = {w: len(w) for w in words if len(w) > 4}
# {'apple': 5, 'banana': 6}

# flip an existing catalog — value becomes the new key
shelf_of = {"1984": "4B", "Dune": "5C"}
book_on = {shelf: title for title, shelf in shelf_of.items()}
# {'4B': '1984', '5C': 'Dune'}
Real-world analogy Instead of a librarian filing 500 cards one at a time by hand, a comprehension is the machine that reads a shelving list and stamps out every card in one pass, skipping any that don't meet the filing rule.
Topic 07

Nested dictionaries

A value doesn't have to be simple — it can be a whole dictionary of its own. That's how you model something with several fields, like a full patron or student record.

Real-world analogy Some catalog cards aren't a single line — they're a small folder: title, author, year, and condition, all filed under one book. A nested dictionary is that folder-within-a-drawer. 
library = {
    "1984": {"author": "Orwell", "year": 1949, "copies": 3},
    "Dune":  {"author": "Herbert", "year": 1965, "copies": 5}
}

# reach into a nested field
library["1984"]["author"]      # 'Orwell'

# update one field deep inside
library["Dune"]["copies"] -= 1

# walk every book and its details
for title, info in library.items():
    print(f"{title} by {info['author']} ({info['year']})")

Nesting can go as deep as the real thing you're modeling needs — a library system, a shelf, a book, a copy's condition — but past two or three levels, it usually reads better as small classes instead.

Topic 08

Why lookups are instant: hashability

A dictionary isn't secretly scanning every card when you look something up — it jumps straight to the right spot. That's the whole point of the card-catalog design, and it's why keys have a restriction.

Real-world analogy A library catalog is organized by a rule: the first letter of the title decides which drawer it's in. Python does the same thing with a hash function — it runs the key through a formula that spits out a "drawer number," so it never has to search, it just goes straight there. That's why lookups stay fast even with a million entries. 
# hashable — fine as keys
d = {"text": 1, 42: "num", (1,2): "tuple key"}

# unhashable — lists can change shape, so they can't be filed by a fixed rule
d[[1,2]] = "oops"   # TypeError: unhashable type: 'list'

This is also why a key, once used to file a card, must stay the same "shape" forever — a string or number's hash never changes, but a list's would, and that would put the card in the wrong drawer.

Why this makes dictionaries fast

  • List lookup: checking if something is present means checking every item — slower as the list grows.
  • Dict lookup: the hash tells Python exactly where to look — roughly the same speed whether there are 10 entries or 10 million.
Topic 09 · Build something real

Project: a Contact Book manager

We'll build a small command-line contact book — the kind of thing a phone's Contacts app does underneath. It uses almost every dictionary skill from this page: creation, safe access, updates, deletion, looping, nesting, and comprehensions.

The brief Store each contact's name as the key, and a nested dictionary of phone, email, and city as the value. Support adding, updating, searching, deleting, and generating a filtered directory — say, "everyone in Mumbai."
1

Set up the contact book

Start with an empty dictionary. Each contact will be a nested dictionary of details.

contact_book = {}
2

Add a contact

Write a function that files a new "card" — the person's name maps to their details.

def add_contact(book, name, phone, email, city):
    book[name] = {
        "phone": phone,
        "email": email,
        "city": city
    }
    print(f"Added {name}.")

add_contact(contact_book, "Maya Rao", "98765xxxxx", "maya@mail.com", "Mumbai")
add_contact(contact_book, "Leo Diaz", "91234xxxxx", "leo@mail.com", "Pune")
3

Look someone up — safely

Use .get() so an unknown name doesn't crash the whole program.

def find_contact(book, name):
    contact = book.get(name)
    if contact is None:
        print(f"No contact named {name}.")
    else:
        print(f"{name}: {contact['phone']}, {contact['email']}, {contact['city']}")

find_contact(contact_book, "Maya Rao")
4

Update one field without touching the rest

Someone changed cities — reach into the nested dict and update just that key.

def update_city(book, name, new_city):
    if name in book:
        book[name]["city"] = new_city
        print(f"{name} moved to {new_city}.")
    else:
        print("Contact not found.")

update_city(contact_book, "Leo Diaz", "Bangalore")
5

Delete a contact

.pop() removes them and confirms who was removed, without crashing if they were never there.

def delete_contact(book, name):
    removed = book.pop(name, None)
    if removed:
        print(f"Removed {name}.")
    else:
        print("Nothing to remove — not found.")
6

Build a filtered directory with a comprehension

Generate a mini phonebook of just the people in one city — a single line does what would otherwise be a multi-line loop.

def contacts_in_city(book, city):
    return {name: info["phone"] for name, info in book.items() if info["city"] == city}

print(contacts_in_city(contact_book, "Mumbai"))
# {'Maya Rao': '98765xxxxx'}
7

Print the full directory

Loop through everything with .items() for a full readable listing — the "inventory sweep" from Topic 05.

def print_directory(book):
    for name, info in book.items():
        print(f"{name} — {info['city']} — {info['phone']}")

print_directory(contact_book)
What you just practiced Creation ({}), nested structure, safe reads (.get()), targeted updates, safe deletes (.pop()), comprehensions, and full iteration (.items()) — the entire toolkit, applied to one coherent, realistic program.
