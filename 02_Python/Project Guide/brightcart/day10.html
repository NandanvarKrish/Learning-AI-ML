Tools and functions

Learn each one, then use it in the steps below.

subprocess.run
Runs one script from another, so the whole pipeline runs in order from one command.
subprocess.run([sys.executable, 'day03.py'])
sys.exit(1)
Stops the pipeline with an error code when a stage fails, so a broken report is never produced.
if result.returncode != 0: sys.exit(1)
Pathlib: Path(__file__).resolve().parents[1]
Finds the project folder from the script's own location, so the project runs on any computer.
ROOT = Path(__file__).resolve().parents[1]
pd.DateOffset(months=12)
Calendar arithmetic for 'the last 12 months'.
df['order_date'] > max_date - pd.DateOffset(months=12)
Writing Markdown with f-strings
Builds a summary whose numbers come from the calculations, not from typing.
f'Net revenue: {value:,.0f}'

Concepts

The ideas behind today's work.

Reproducibility
A project is only useful if someone else can run it and get your numbers. Fixed seeds, relative paths, one command to run everything, and a README do this.
From numbers to words
An executive summary states the result, the number behind it, and what to do about it. Avoid jargon. Every number must match a file in the outputs folder.
Honest reporting
Report the limits: one sample, association is not cause, and the data was cleaned in specific ways. A good report says what it cannot tell you.
Submission
Submission is the package a reviewer receives: code, data, notes, outputs and a clear README. Anything missing makes the work hard to check, so the package matters as much as the analysis.

Reference solution and expected output

Try the task yourself first. Then compare your results with the reference below. Your numbers must match the expected output.

solutions/day10.py
"""Day 10 capstone: one script that runs the whole Brightcart pipeline and writes the report.

Run from the project folder:   python solutions/day10.py
It runs the Day 3 cleaning, Day 4 features, Day 5 monthly series, Day 6 customers and
Day 9 tests, then writes outputs/kpis.csv, outputs/charts/ and outputs/executive_summary.md.
"""
import subprocess
import sys
from pathlib import Path

import pandas as pd

ROOT = Path(__file__).resolve().parents[1]
SOL = ROOT / "solutions"
OUT = ROOT / "outputs"
(OUT / "charts").mkdir(parents=True, exist_ok=True)

# 1. Run the pipeline stages in order. A stage that fails stops the build.
for stage in ["day03.py", "day04.py", "day05.py", "day06.py", "day07.py", "day08.py", "day09.py"]:
    result = subprocess.run([sys.executable, str(SOL / stage)], capture_output=True, text=True, cwd=ROOT)
    if result.returncode != 0:
        print(f"STAGE FAILED {stage}\n{result.stderr}")
        sys.exit(1)
print("CHECK stages_ok", 7)

# 2. Load the checkpoints the stages produced.
CLEAN = ROOT / "data" / "clean"
df = pd.read_csv(CLEAN / "orders_enriched.csv", parse_dates=["order_date"])
monthly = pd.read_csv(CLEAN / "monthly_revenue.csv", parse_dates=["month_end"])
rfm = pd.read_csv(CLEAN / "rfm.csv")

# 3. KPI table: one row per headline number, so the report can be checked by anyone.
last_12 = df[df["order_date"] > df["order_date"].max() - pd.DateOffset(months=12)]
prev_12 = df[(df["order_date"] <= df["order_date"].max() - pd.DateOffset(months=12))
             & (df["order_date"] > df["order_date"].max() - pd.DateOffset(months=24))]
kpis = pd.DataFrame([
    ("Net revenue, last 12 months", last_12["net_revenue"].sum()),
    ("Net revenue, previous 12 months", prev_12["net_revenue"].sum()),
    ("Orders, last 12 months", len(last_12)),
    ("Gross margin %, all orders", df["margin"].sum() / df["net_revenue"].sum() * 100),
    ("Return rate %, all orders", df["returned_flag"].mean() * 100),
    ("Average delivery days", df["delivery_days"].mean()),
    ("Active customers", df["customer_id"].nunique()),
    ("Champion customers (RFM)", int((rfm["segment"] == "Champions").sum())),
], columns=["kpi", "value"])
kpis["value"] = kpis["value"].round(2)
kpis.to_csv(OUT / "kpis.csv", index=False)
growth = (kpis.loc[0, "value"] / kpis.loc[1, "value"] - 1) * 100
print("CHECK kpi_rows", len(kpis))
print("CHECK revenue_growth_pct", round(growth, 2))

# 4. Copy the charts from the chart day into outputs/charts.
for png in (ROOT / "outputs").glob("d0*.png"):
    (OUT / "charts" / png.name).write_bytes(png.read_bytes())

# 5. Executive summary: numbers come from the calculations above, not typed by hand.
best_month = monthly.loc[monthly["revenue"].idxmax(), "month_end"].strftime("%B %Y")
summary = f"""# Brightcart analysis: executive summary

## Headline numbers
- Net revenue in the last 12 months: {kpis.loc[0, 'value']:,.0f}
- Net revenue in the previous 12 months: {kpis.loc[1, 'value']:,.0f}
- Year-on-year change: {growth:+.1f} percent
- Gross margin: {kpis.loc[3, 'value']:.1f} percent
- Return rate: {kpis.loc[4, 'value']:.1f} percent of orders

## What the data says
- Best month for revenue: {best_month}.
- Electronics is the largest category and has the highest return rate.
- Discounts of 15 percent or more do not produce a statistically significant change in returns (permutation test, see Day 9).
- Average delivery is about {kpis.loc[5, 'value']:.1f} days, with a few very late deliveries removed as errors.

## Data quality
- Duplicate rows, orphan customers, zero quantities and missing values were removed or filled. See the Day 3 cleaning report.

## Method
Python 3 with NumPy, pandas, Matplotlib and Seaborn. All numbers come from solutions/day03.py to day09.py.
"""
(OUT / "executive_summary.md").write_text(summary)
print("CHECK summary_lines", len(summary.splitlines()))

How to submit

What to hand in, how to package it, and how to check it first.

What to submit

Folder layout
brightcart_<yourname>/
  README.md          how to run the project, in plain steps
  data/              the raw files you were given, plus data/README.md (do not edit the raw files)
  data/clean/        checkpoint files produced by the pipeline
  solutions/         your code for Days 1 to 10
  notes/             your notes for each day (day07_charts.md, day09_tests.md and so on)
  outputs/           kpis.csv, charts/ and executive_summary.md
  report/            optional PDF or Word copy of your executive summary

How to package it

  1. Keep the raw data in data/ unchanged. Your cleaning code must read from it, not overwrite it.
  2. Write README.md with three sections: what the project is, how to install the libraries, and the single command that runs everything.
  3. Make sure every path in your code is relative to the project folder. Remove any path such as C:\Users\... from your code.
  4. Run the project from a fresh copy. If it fails on a new computer, the README is incomplete.
  5. Name the zip file brightcart_<yourname>.zip, with no spaces, and attach it to your submission.
  6. Add a short cover note with: your name, the hours you spent each day, the hardest day and why, and one finding you are most confident about.

Submit the zip exactly where your course tells you: the course portal, a shared folder, or an email to your instructor. If no place was given, email the zip with the subject line 'Brightcart project - <your name>'.

Before you submit, check that:

  • The project runs from scratch with one command
  • No absolute paths and no personal information inside the code
  • Every number in the summary matches outputs/kpis.csv
  • Every chart has a title, labels and units
  • The limits of the analysis are stated
  • The zip opens and the README matches the folder

Common mistakes

  • Editing the raw files in data/ (always work from a copy or a checkpoint)
  • Numbers in the summary that were typed by hand and do not match the outputs
  • A README that says 'run the code' without the command
  • Charts without units, or bars that do not start at zero
  • Missing the cover note, so the reviewer cannot tell what you did
