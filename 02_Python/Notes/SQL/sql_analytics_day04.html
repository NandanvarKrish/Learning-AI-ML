Aggregates: One Number for Many Rows

Summaries with no GROUP BY

An aggregate function collapses many rows into one value. COUNT, SUM, AVG, MIN and MAX each take a set of rows and return a single result. Without a GROUP BY, the whole filtered table is one group.

One summary row for the whole table

One row, four numbers. The WHERE clause runs first, so these are completed rides only: 377 trips, 6 stations, a revenue of 23476.00 (cancelled rides carry no fee) and an average of 28.4 minutes.

SQL
SELECT COUNT(*) AS trips, COUNT(DISTINCT start_station) AS stations, ROUND(SUM(fee_inr),2) AS revenue, ROUND(AVG(minutes),1) AS avg_minutes FROM trips WHERE status = 'completed'

GROUP BY: One Row per Group

Revenue and counts by station

GROUP BY splits the rows into groups, one for each distinct value of the listed column, and the aggregates run per group. Every column in the SELECT list must either be in the GROUP BY or be inside an aggregate function.

syntax
SELECT group_column, AGG(column)
FROM   table
WHERE  row_filter        -- rows, before grouping
GROUP BY group_column
HAVING group_filter      -- groups, after aggregation
ORDER BY ...;

Revenue and departures per station

Six groups, one per start station, ordered by revenue. HARBOUR leads with 67 departures and 5176.00 in fares. The six departure counts add up to all 400 trips, because every trip has exactly one start station.

SQL
SELECT start_station, COUNT(*) AS departures, ROUND(SUM(fee_inr),2) AS revenue FROM trips GROUP BY start_station ORDER BY revenue DESC

HAVING vs WHERE

Rows are filtered before grouping; groups after

WHERE decides which rows enter the groups. HAVING decides which groups survive. You cannot use an aggregate in WHERE, because the aggregate does not exist yet at that point.

Busy stations only

Four stations reach 67 departures. CENTRAL and MARKET have 66 each and are removed. The HAVING test uses the group count, which WHERE cannot see.

SQL
SELECT start_station, COUNT(*) AS departures FROM trips GROUP BY start_station HAVING COUNT(*) >= 67 ORDER BY departures DESC, start_station
start_stationdepartures
HARBOUR67
RIVERSIDE67
STADIUM67
UNIVERSITY67

Filter the rows, then the groups

Here the rows are filtered first (completed only), then the groups are filtered by size. Both clauses are needed, each doing one job.

SQL
SELECT start_station, COUNT(*) AS completed_trips FROM trips WHERE status = 'completed' GROUP BY start_station HAVING COUNT(*) >= 60 ORDER BY completed_trips DESC, start_station

COUNT(*), COUNT(col), COUNT(DISTINCT)

Three counts, three questions

There are three kinds of count, and they answer different questions. COUNT(*) counts rows. COUNT(column) counts rows where that column is not NULL. COUNT(DISTINCT column) counts unique non-NULL values.

Three counts, three meanings

400 rows, 400 with an end station, 6 distinct start stations. On this data the first two match because no end station is missing. If a column had NULLs, COUNT(column) would be smaller than COUNT(*), and that gap is itself a finding.

SQL
SELECT COUNT(*) AS all_rows, COUNT(end_station) AS with_end_station, COUNT(DISTINCT start_station) AS distinct_start_stations FROM trips

Averages and the Zero Trap

Who is in the population?

An average includes every row it is given. If the rows you average include zeros that are not real prices, the average is pulled down. Cancelled rides have a fee of 0.00, so the question of which rows to include changes the answer.

The same average, two populations

Cancelled rides average 0.00 because they were never charged. Completed rides average 62.27. Averaging over all 400 rows would give 58.69, which understates what a rider actually pays.

SQL
SELECT status, COUNT(*) AS trips, ROUND(SUM(fee_inr),2) AS fares, ROUND(AVG(fee_inr),2) AS avg_fee FROM trips GROUP BY status ORDER BY status
statustripsfaresavg_fee
completed37723476.0062.27
cancelled230.000.00

Eleven classic and twelve electric rides were cancelled. These are counts, not rates. A rate needs the total for each type as well (the capstone does this).

Scenario 2 — Finance: revenue and average fare per station

Average fare uses completed rides only: total fare divided by the number of completed rides. SUM(status = 'completed') counts only the completed rows, so cancelled rides add nothing to the denominator, and their zero fee adds nothing to the total.

SQL
SELECT start_station, COUNT(*) AS departures, ROUND(SUM(fee_inr),2) AS revenue, ROUND(SUM(fee_inr) / SUM(status = 'completed'), 2) AS avg_completed_fare FROM trips GROUP BY start_station ORDER BY revenue DESC

Common Mistakes

Fix these before they reach a report

MistakeWhat goes wrongFix
WHERE with an aggregateError: invalid use of a group functionMove the test to HAVING
A column in SELECT that is not in GROUP BYSome systems reject it; MariaDB's default may pick an arbitrary valueAdd the column to GROUP BY or drop it
Averaging rows that are not real valuesCancelled zeros drag the average down (58.69 instead of 62.27)Filter to the population you mean, then average
COUNT(column) when you meant rowsNULL values are skipped and the count is too smallUse COUNT(*) for rows
Dividing a total by all rows when you meant completed rowsThe average is understatedDivide by the count of the rows that actually carry the value
Forgetting ORDER BY on a grouped reportGroups come back in an order you cannot rely onAdd ORDER BY, plus a unique tie-breaker
Aggregating a join before checking the grainTotals double-count when one row matches many (Day 5)Check row counts before and after joins
