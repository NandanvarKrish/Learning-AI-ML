📖 Lesson

Error Handling — Make Programs Robust

When Python encounters an error, it raises an exception. Without handling it, the program crashes immediately. With try/except, you catch the error, handle it gracefully, and keep running.

▶
try
Code that might fail. Always runs first.
→
🛡️
except
Runs ONLY if an error occurred in try.
→
✅
finally
ALWAYS runs — error or not. Cleanup.
Python — Basic try/except
# Without error handling — CRASHES on bad input # age = int(input("Age: ")) ← crashes if user types "abc" # WITH error handling — handles gracefully try: age = int(input("Enter your age: ")) print(f"Age: {age}") except ValueError: print("❌ Please enter a number!") # Multiple except blocks try: data = [10, 20, 30] result = data[5] # IndexError val = 10 / 0 # ZeroDivisionError except IndexError: print("Index out of range") except ZeroDivisionError: print("Cannot divide by zero") except Exception as e: print(f"Unexpected: {e}") # catch-all finally: print("This ALWAYS runs") # cleanup
⚠️ Common Python Exceptions

🛡️ Raising Your Own Errors

Use raise to trigger an error deliberately when data is invalid. Catch bad data at the point of entry — before it corrupts your entire pipeline.

Python — raise custom errors
def validate_marks(marks): if not isinstance(marks, (int, float)): raise TypeError(f"marks must be a number, got {type(marks)}") if marks < 0 or marks > 100: raise ValueError(f"marks must be 0-100, got {marks}") return "A" if marks >= 80 else "B" if marks >= 60 else "F" # Test it for test in [85, 150, "abc", 45]: try: print(f"{test} → {validate_marks(test)}") except (ValueError, TypeError) as e: print(f"❌ {test}: {e}")
📂 Error Handling with Files
Python — File error handling
# Safe file reading — never crashes def safe_read(filepath): try: with open(filepath) as f: return f.read() except FileNotFoundError: print(f"File not found: {filepath}") return None except PermissionError: print(f"No permission to read: {filepath}") return None # Process records — skip bad ones def process_dataset(records): results = [] errors = 0 for i, r in enumerate(records): try: marks = float(r["marks"]) status = "pass" if marks >= 50 else "fail" results.append({"name":r["name"], "status":status}) except (KeyError, ValueError) as e: print(f"Row {i} skipped: {e}") errors += 1 print(f"Processed: {len(results)} ok, {errors} errors") return results # Mixed good/bad data data = [ {"name":"Ali", "marks":"88"}, {"name":"Sara", "marks":"N/A"}, # bad! {"name":"Usman"}, # missing key! {"name":"Zara", "marks":"72"}, ] process_dataset(data)
💡The golden rules of error handling:
1. Always catch specific exceptions — never bare except:
2. Use finally for cleanup (closing files, logging)
3. Validate data at entry with raise — don't let bad data go deep
4. Log errors — don't silently swallow them
🌍 Real World Example

How Production ML Pipelines Stay Alive

In production, data arrives from real users — messy, incomplete, wrong. A single unhandled error in a bare function crashes the entire pipeline. Error handling keeps all 9,999 good records processing even when one is corrupted.

Python — Production-grade data processor
import csv, json def load_and_process(filepath): results = [] log = [] try: with open(filepath) as f: for i, row in enumerate(csv.DictReader(f)): try: marks = float(row["marks"]) if not (0 <= marks <= 100): raise ValueError(f"marks {marks} out of range") results.append({ "name" : row["name"], "marks" : marks, "grade" : "A" if marks>=80 else "B" if marks>=60 else "F" }) except (ValueError, KeyError) as e: log.append(f"Row {i+1} error: {e}") except FileNotFoundError: print(f"❌ File not found: {filepath}") return [], [] finally: print(f"✅ Done: {len(results)} processed, {len(log)} errors") return results, log
