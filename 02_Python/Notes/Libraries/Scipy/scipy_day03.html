scipy.optimize.minimize() — Finding the Best Value

The general-purpose function minimizer

minimize() finds the input value(s) that produce the SMALLEST output of a function you define. Nearly every optimization problem — machine learning training, resource allocation, curve fitting — reduces to "minimize this function."

PYTHON
from scipy import optimize
import numpy as np

# Minimize a simple function: f(x) = (x-3)^2 + 5  →  minimum is at x=3
def f(x):
    return (x - 3)**2 + 5

result = optimize.minimize(f, x0=0)   # x0 = initial guess to start searching from
print(result.x)        # the x-value that minimizes f  → ~3.0
print(result.fun)      # the minimum function value    → ~5.0
print(result.success)  # whether the optimizer converged successfully

# Multi-variable minimization — the Rosenbrock "banana" function (classic optimization test)
def rosenbrock(params):
    x, y = params
    return (1-x)**2 + 100*(y - x**2)**2

result = optimize.minimize(rosenbrock, x0=[0,0])
print(result.x)   # converges to [1, 1], the true minimum

# With bounds — constrain the search to a specific range
result = optimize.minimize(f, x0=0, bounds=[(-10,1)])   # force x to stay in [-10, 1]
print(result.x)   # finds the best value WITHIN the bound → 1.0 (closest allowed to the true min of 3)

# Choosing a method (algorithm) explicitly
result = optimize.minimize(rosenbrock, x0=[0,0], method='Nelder-Mead')
💡 Only Minimize? What About Maximizing?
SciPy's optimize module ONLY provides minimization. To MAXIMIZE a function, minimize its NEGATIVE: optimize.minimize(lambda x: -f(x), x0). This simple trick means you never need a separate "maximize" function.

curve_fit() — Fitting Custom Models to Data

When your relationship isn't a standard distribution or simple regression

curve_fit() finds the BEST parameters for ANY custom function you define, to match observed data — more flexible than Seaborn's regplot() which only fits polynomials.

PYTHON
from scipy.optimize import curve_fit
import matplotlib.pyplot as plt

# Define ANY custom mathematical model — here, exponential decay
def exp_decay(x, a, b, c):
    return a * np.exp(-b * x) + c

# Generate noisy sample data following this shape
np.random.seed(0)
x_data = np.linspace(0, 4, 50)
y_data = exp_decay(x_data, 2.5, 1.3, 0.5) + np.random.normal(0, 0.2, 50)

# Fit the model — returns optimal parameters AND their covariance (uncertainty)
popt, pcov = curve_fit(exp_decay, x_data, y_data, p0=[1,1,1])   # p0 = initial parameter guesses
a_fit, b_fit, c_fit = popt
print(f"Fitted: a={a_fit:.2f}, b={b_fit:.2f}, c={c_fit:.2f}")

# Standard errors of the fitted parameters (uncertainty estimate)
perr = np.sqrt(np.diag(pcov))
print(f"Uncertainty: ±{perr}")

# Visualize the fit
plt.scatter(x_data, y_data, alpha=0.6, label='Data')
plt.plot(x_data, exp_decay(x_data, *popt), 'r-', linewidth=2, label='Fitted curve')
plt.legend()
⚠️ Good Initial Guesses (p0) Matter
curve_fit() uses iterative optimization internally — a poor initial guess (p0) can cause it to converge to a wrong local optimum, fail to converge, or take much longer. Always provide a reasonable p0 based on a rough visual inspection of your data whenever possible.

Root Finding — Solving Equations Numerically

Where does a function equal zero?

PYTHON
# Find where f(x) = 0 — e.g., x^3 - x - 2 = 0
def g(x):
    return x**3 - x - 2

# General-purpose root finder — needs an initial guess
result = optimize.root(g, x0=1)
print(result.x)   # ~1.5214

# brentq() — often faster/more reliable IF you can bracket the root
# (know a range [a,b] where the function changes sign)
root_value = optimize.brentq(g, a=1, b=2)   # g(1) is negative, g(2) is positive → root is between
print(root_value)

# Real-world use: solve "at what price does supply equal demand?"
def supply_minus_demand(price):
    supply = 50 * price - 100
    demand = 500 - 30 * price
    return supply - demand

equilibrium_price = optimize.brentq(supply_minus_demand, a=0, b=50)
print(f"Equilibrium price: {equilibrium_price:.2f}")
FunctionRequiresBest For
optimize.root()Initial guess (x0)General-purpose, multi-dimensional systems
optimize.brentq()A bracket [a,b] where sign changesSingle-variable, very reliable when applicable

linprog() — Linear Programming

Optimal resource allocation under linear constraints

Linear programming finds the best allocation of resources to minimize (or maximize) a linear objective, subject to linear constraints — classic operations research.

PYTHON
from scipy.optimize import linprog

# Example: A factory makes 2 products. Maximize profit given resource constraints.
# Profit: 3x + 5y (x=units of Product A, y=units of Product B)
# scipy's linprog MINIMIZES by default, so negate for maximization: minimize -3x - 5y
c = [-3, -5]   # coefficients of the (negated) objective function

# Constraints in the form: A_ub @ x <= b_ub
# Constraint 1: 1x + 0y <= 4   (Product A machine-hours limit)
# Constraint 2: 0x + 2y <= 12  (Product B machine-hours limit)
# Constraint 3: 3x + 2y <= 18  (shared raw material limit)
A_ub = [[1,0], [0,2], [3,2]]
b_ub = [4, 12, 18]

result = linprog(c, A_ub=A_ub, b_ub=b_ub, bounds=[(0,None), (0,None)])   # x,y >= 0

print(f"Optimal units — Product A: {result.x[0]:.1f}, Product B: {result.x[1]:.1f}")
print(f"Maximum profit: {-result.fun:.2f}")   # negate back since we minimized -profit
⚠️ linprog() Only MINIMIZES — Negate for Maximization Problems
Like minimize(), linprog() only minimizes. For a maximization problem (like maximizing profit), NEGATE the objective coefficients, solve, then negate the RESULT back to get the true maximum value.

Interpolation — Filling Gaps Between Known Points

Estimating values you didn't directly measure

PYTHON
from scipy.interpolate import interp1d, CubicSpline

# Suppose you have temperature readings only at certain hours
hours = np.array([0, 4, 8, 12, 16, 20, 24])
temps = np.array([15, 13, 18, 25, 23, 18, 15])

# LINEAR interpolation — straight lines connecting each pair of points
linear_interp = interp1d(hours, temps, kind='linear')
print(linear_interp(10))   # estimated temperature at hour 10

# CUBIC interpolation — smooth curve through all points (more realistic for natural phenomena)
cubic_interp = interp1d(hours, temps, kind='cubic')
print(cubic_interp(10))

# CubicSpline — a dedicated, often smoother/more robust spline class
spline = CubicSpline(hours, temps)
fine_hours = np.linspace(0, 24, 200)   # 200 smoothly spaced points
smooth_temps = spline(fine_hours)

# Plot comparison
plt.scatter(hours, temps, color='black', zorder=5, label='Measured')
plt.plot(fine_hours, linear_interp(fine_hours), '--', label='Linear')
plt.plot(fine_hours, smooth_temps, label='Cubic Spline')
plt.legend()

# Handling values OUTSIDE the known range (extrapolation)
safe_interp = interp1d(hours, temps, kind='linear', fill_value='extrapolate')
# Without fill_value='extrapolate', requesting x outside [0,24] raises a ValueError
MethodShape Between PointsBest For
kind='linear'Straight line segmentsSimple, fast, safe default
kind='cubic'Smooth curved segmentsNaturally smooth phenomena (temperature, physical measurements)
CubicSplineSmooth, continuous 2nd derivativeScientific/engineering data needing smooth derivatives too
⚠️ Interpolation vs Extrapolation
Interpolation (estimating WITHIN the range of known x-values) is generally reliable. Extrapolation (estimating OUTSIDE that range) is much riskier — the fitted curve's behavior beyond your data is unverified and can produce wildly unrealistic results, especially with higher-order/cubic methods.

Solve the Production Mix Problem

from scipy.optimize import linprog, minimize, curve_fit, brentq
from scipy.interpolate import CubicSpline
import numpy as np
import matplotlib.pyplot as plt

# A factory makes Chairs (x) and Tables (y).
# Profit: ₹40/chair, ₹90/table. Maximize profit.
# Constraints:
#   Wood:   4x + 8y <= 400   (units of wood available)
#   Labor:  3x + 2y <= 180   (labor hours available)
#   Chairs demand cap: x <= 80
c = [-40, -90]
A_ub = [[4,8], [3,2], [1,0]]
b_ub = [400, 180, 80]

result = linprog(c, A_ub=A_ub, b_ub=b_ub, bounds=[(0,None),(0,None)])
print(f"Chairs: {result.x[0]:.1f}, Tables: {result.x[1]:.1f}")
print(f"Max profit: ₹{-result.fun:.2f}")

Phase 2 — Sensor Calibration Curve Fitting

~30 min▼
1
Fit a Calibration Model
STARTER CODE
# A pressure sensor's raw voltage output relates to actual pressure via
# a known saturating (logistic-like) curve: P = L / (1 + exp(-k*(V - V0)))
def calibration_curve(V, L, k, V0):
    return L / (1 + np.exp(-k * (V - V0)))

np.random.seed(4)
voltage = np.linspace(0, 10, 40)
true_pressure = calibration_curve(voltage, 100, 1.2, 5)
measured_pressure = true_pressure + np.random.normal(0, 3, len(voltage))

popt, pcov = curve_fit(calibration_curve, voltage, measured_pressure, p0=[100,1,5])
print(f"Fitted: L={popt[0]:.1f}, k={popt[1]:.2f}, V0={popt[2]:.2f}")

Plot the raw data points against the fitted calibration curve. Use the fitted model to predict pressure at V=7.5V.

Find the Voltage for a Target Pressure

Using brentq(), find what voltage produces EXACTLY 50 units of pressure (solve calibration_curve(V, *popt) - 50 = 0 for V).
