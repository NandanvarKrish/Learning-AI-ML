scipy.linalg vs numpy.linalg

When to reach for SciPy's version instead

NumPy has its own numpy.linalg module. scipy.linalg offers a SUPERSET of that functionality — always safe to use, sometimes faster (uses optimized LAPACK/BLAS routines), and includes advanced decompositions NumPy lacks.

🧮 When to Prefer scipy.linalg
✅ scipy.linalg is ALWAYS at least as capable as numpy.linalg
✅ Needed for: LU decomposition, Schur decomposition, matrix exponentials, Cholesky variants
✅ Often faster for large matrices due to optimized backend libraries
Rule of thumb: if you're already using SciPy elsewhere in a project, use scipy.linalg consistently rather than mixing with numpy.linalg.
PYTHON
from scipy import linalg
import numpy as np

A = np.array([[4,3], [6,3]])

# Determinant
print(linalg.det(A))

# Inverse
print(linalg.inv(A))

# Norm — magnitude of a vector or matrix
v = np.array([3,4])
print(linalg.norm(v))   # 5.0 — Euclidean length

Solving Linear Systems — Ax = b

The most common linear algebra task in practice

PYTHON
# Solve a system of linear equations:
#   2x + 3y = 8
#   5x + 4y = 13
A = np.array([[2,3], [5,4]])
b = np.array([8, 13])

# linalg.solve() is PREFERRED over manually computing inv(A) @ b
x = linalg.solve(A, b)
print(x)   # [x, y] solution

# Verify: A @ x should equal b
print(np.allclose(A @ x, b))   # True

# Least-squares solution — for OVERDETERMINED systems (more equations than unknowns)
# Common in fitting a line: y = mx + c, given many (x,y) data points
A_over = np.array([[1,1], [2,1], [3,1], [4,1]])   # [x, 1] columns for y=mx+c
b_over = np.array([2.1, 3.9, 6.2, 7.8])

result = linalg.lstsq(A_over, b_over)
m, c = result[0]   # slope, intercept — same idea as manual linear regression!
print(f"y = {m:.2f}x + {c:.2f}")
⚠️ Never Solve Ax=b via inv(A) @ b
Computing linalg.inv(A) @ b works mathematically but is SLOWER and LESS NUMERICALLY STABLE than linalg.solve(A, b), which uses specialized, more accurate algorithms internally. Always prefer solve() for solving systems — reserve inv() for when you genuinely need the inverse matrix itself.

Matrix Decompositions

Breaking a matrix into simpler, more useful pieces

PYTHON
# Eigenvalues & eigenvectors — used in PCA, stability analysis, and more
A = np.array([[4,-2], [1,1]])
eigenvalues, eigenvectors = linalg.eig(A)
print(eigenvalues)     # complex numbers in general, real if symmetric

# SVD (Singular Value Decomposition) — the workhorse behind PCA, recommender systems, compression
M = np.random.rand(4, 3)
U, s, Vt = linalg.svd(M)
print(f"U shape: {U.shape}, singular values: {s}, Vt shape: {Vt.shape}")

# LU decomposition — factor A into Lower * Upper triangular matrices (used internally by solve())
P, L, U = linalg.lu(A)

# Cholesky decomposition — for SYMMETRIC POSITIVE-DEFINITE matrices only (e.g., covariance matrices)
cov_matrix = np.array([[4,2], [2,3]])
L_chol = linalg.cholesky(cov_matrix, lower=True)
print(np.allclose(L_chol @ L_chol.T, cov_matrix))   # True — L @ L.T reconstructs the original
DecompositionCommon Use
EigendecompositionPCA, stability analysis, understanding matrix transformations
SVDPCA, dimensionality reduction, recommender systems, image compression
LUEfficiently solving multiple systems with the same A but different b
CholeskyFast, stable factorization for covariance/positive-definite matrices

scipy.signal — Filtering Noisy Data

Removing noise while preserving the true underlying signal

PYTHON
from scipy import signal
import numpy as np

# Generate a noisy signal: true sine wave + random noise
t = np.linspace(0, 1, 500)
true_signal = np.sin(2*np.pi*5*t)          # 5 Hz sine wave
noisy_signal = true_signal + np.random.normal(0, 0.3, len(t))

# SAVITZKY-GOLAY filter — smooths while preserving peak shapes better than simple moving average
smoothed = signal.savgol_filter(noisy_signal, window_length=31, polyorder=3)

# BUTTERWORTH low-pass filter — removes high-frequency noise, keeps low-frequency trend
b, a = signal.butter(N=4, Wn=0.1, btype='low')   # N=filter order, Wn=cutoff frequency (normalized 0-1)
filtered = signal.filtfilt(b, a, noisy_signal)     # filtfilt = zero-phase filtering (no time shift introduced)

# MEDIAN filter — great for removing sharp spike/outlier noise specifically
despiked = signal.medfilt(noisy_signal, kernel_size=5)

# Find PEAKS in a signal — critical for detecting events (heartbeats, spectral peaks)
peaks, properties = signal.find_peaks(noisy_signal, height=0.5, distance=20)
print(f"Found {len(peaks)} peaks at indices: {peaks}")
FilterBest For
savgol_filterSmoothing while preserving peak height/shape (spectroscopy, sensor data)
butter + filtfiltRemoving specific frequency ranges (low-pass, high-pass, band-pass)
medfiltRemoving sharp spikes/outliers without blurring edges

Fourier Transform — Time Domain to Frequency Domain

What frequencies make up a signal?

The Fast Fourier Transform (FFT) decomposes a signal into the sum of sine/cosine waves at different frequencies, revealing WHICH frequencies are present and how strong each is.

PYTHON
from scipy.fft import fft, fftfreq
import matplotlib.pyplot as plt

# A signal made of TWO combined frequencies: 5 Hz and 20 Hz
sample_rate = 500          # samples per second
duration = 2                # seconds
t = np.linspace(0, duration, sample_rate*duration, endpoint=False)
signal_data = np.sin(2*np.pi*5*t) + 0.5*np.sin(2*np.pi*20*t)

# Compute the FFT
N = len(signal_data)
yf = fft(signal_data)
xf = fftfreq(N, 1/sample_rate)[:N//2]   # only need the positive-frequency half

magnitude = 2.0/N * np.abs(yf[0:N//2])

plt.plot(xf, magnitude)
plt.xlabel('Frequency (Hz)')
plt.ylabel('Magnitude')
# Result: TWO clear spikes at 5 Hz and 20 Hz — revealing the hidden component frequencies!
🌊 Reading an FFT Spectrum
X-axis → frequency (Hz) — what rate of oscillation
Y-axis → magnitude — how STRONG that frequency's contribution is
Spikes → dominant/significant frequency components in the original signal
A signal that LOOKS like noise in the time domain can reveal clear, meaningful structure once viewed in the frequency domain.
💡 Real-World FFT Uses
Audio processing (identifying musical notes/pitch), vibration analysis (detecting machine faults from characteristic frequencies), ECG/EEG analysis (heart rate, brainwave bands), and removing periodic noise (like 50/60Hz electrical hum) from sensor data.

Spectral Analysis & the Spectrogram

How frequency content CHANGES over time

PYTHON
from scipy import signal

# A signal whose frequency CHANGES over time (a "chirp") — FFT alone can't show WHEN each frequency occurs
t = np.linspace(0, 10, 5000)
chirp_signal = signal.chirp(t, f0=1, f1=20, t1=10, method='linear')   # frequency sweeps 1Hz → 20Hz

# Spectrogram — shows frequency content AS IT CHANGES over time (time AND frequency together)
frequencies, times, Sxx = signal.spectrogram(chirp_signal, fs=500)

plt.pcolormesh(times, frequencies, 10*np.log10(Sxx+1e-10), shading='auto')
plt.ylabel('Frequency (Hz)')
plt.xlabel('Time (s)')
plt.colorbar(label='Power (dB)')
# Shows a diagonal line RISING over time — visualizing the frequency sweep directly!

# Power Spectral Density — how signal power is distributed across frequency (averaged over time)
freqs, psd = signal.welch(noisy_signal, fs=500)
plt.semilogy(freqs, psd)   # log scale often clearer for PSD
💡 FFT vs Spectrogram — When Frequencies Change Over Time
A plain FFT gives ONE overall frequency breakdown for an entire signal — it can't tell you WHEN a particular frequency occurred if the signal's content changes over time. A spectrogram solves this by computing many small FFTs over sliding time windows, showing frequency content AS A FUNCTION OF TIME — essential for music, speech, and any signal with evolving frequency content.
