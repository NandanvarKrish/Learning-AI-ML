ax.annotate() — Pointing Out What Matters

Drawing attention to a specific data point

ax.annotate(text, xy=(x,y), xytext=(x2,y2), arrowprops=dict(...))
Adds a text label with an arrow pointing to a specific point on the chart.
xy = the point being pointed AT  |  xytext = where the TEXT itself sits  |  arrowprops = arrow styling dict
💼 Real-world use

Marking "Product launch" on a revenue trend line at the exact month sales spiked — turning a plain chart into a chart that TELLS A STORY.

PYTHON
fig, ax = plt.subplots(figsize=(9,5))
ax.plot(months, revenue, marker='o')

ax.annotate('Product Launch 🚀',
            xy=('Apr', revenue[3]),          # the point on the chart
            xytext=('Feb', revenue[3]+20),      # where the text label sits
            arrowprops=dict(facecolor='black', arrowstyle='->'),
            fontsize=11)
ax.text(x, y, string)
Places plain text at a coordinate — no arrow, simpler than annotate().
💼 Real-world use

Adding "Data source: Internal CRM, updated weekly" as a small footnote in the corner of a report chart.

ax.twinx() — Two Different Scales, One Chart

Comparing metrics with very different ranges

ax2 = ax.twinx()
Creates a SECOND y-axis sharing the same x-axis, so two very differently-scaled metrics can share one chart.
💼 Real-world use

Comparing "Revenue in ₹ Lakhs" (ranges 0-500) against "Website Visitors" (ranges 0-50,000) on ONE chart — plotting both on the same y-axis would flatten one of them visually. Twin axes solve this.

PYTHON
fig, ax1 = plt.subplots(figsize=(9,5))

ax1.plot(months, revenue, color='#C2410C', marker='o')
ax1.set_ylabel('Revenue (₹L)', color='#C2410C')
ax1.tick_params(axis='y', labelcolor='#C2410C')

ax2 = ax1.twinx()   # NEW y-axis sharing ax1's x-axis
ax2.plot(months, visitors, color='#0284C7', linestyle='--')
ax2.set_ylabel('Website Visitors', color='#0284C7')
ax2.tick_params(axis='y', labelcolor='#0284C7')
⚠️ Color-Code Each Axis to Avoid Confusion
With two y-axes, always match each line's color to its corresponding y-axis label color (as shown above) — otherwise viewers can't tell which line belongs to which scale.

Exporting for Real Reports

Getting charts out of Python and into a deliverable

fig.savefig(path, dpi=300, bbox_inches='tight', facecolor='white')
The production-grade export call for a client-ready chart.
facecolor='white' ensures no transparent/black background if opened outside a notebook
💼 Real-world use

Exporting a chart to paste directly into a PowerPoint deck or PDF report for a client meeting — 300 DPI is the standard for print-quality.

PYTHON
fig.savefig('q3_dashboard.png', dpi=300, bbox_inches='tight', facecolor='white')
fig.savefig('q3_dashboard.pdf')   # vector format — scales to any size with no quality loss

FuncAnimation — A Quick Taste

Making a chart move (useful for presentations)

animation.FuncAnimation(fig, update_func, frames=N, interval=ms)
Repeatedly calls update_func to redraw the chart, creating motion.
💼 Real-world use

A "growth reveal" animation for a startup pitch deck — the revenue line draws itself in as the presenter talks, more engaging than a static chart.

PYTHON
import matplotlib.animation as animation

fig, ax = plt.subplots(figsize=(8,5))
ax.set_xlim(0, len(months)); ax.set_ylim(0, max(revenue)*1.1)
line, = ax.plot([], [], color='#C2410C', linewidth=2.5)

def update(frame):
    line.set_data(range(frame), revenue[:frame])   # reveal one more point each frame
    return line,

ani = animation.FuncAnimation(fig, update, frames=len(months)+1, interval=300)
ani.save('growth_reveal.gif', writer='pillow')   # export as a shareable GIF
💡 You'll Rarely NEED Animation for Business Reporting
Most business charts are static — annotations, twin axes, and clean styling cover 95% of real needs. FuncAnimation is worth knowing exists for presentations/social content, but isn't a daily-use tool the way the other functions in this course are.
