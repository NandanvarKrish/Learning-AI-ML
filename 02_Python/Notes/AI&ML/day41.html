Lambda Functions, map() & filter()

~2 hours · Short throwaway functions, applied across whole lists at once

01 Why this matters for AI/ML

Once you reach Pandas in a few weeks, you'll constantly write things like df["price"].apply(lambda x: x * 1.1) — a lambda function applied across an entire column at once. Today's map/filter pattern is the pure-Python foundation for that exact idiom, which is genuinely one of the most common lines of code in real data cleaning work.

02 Lambda functions — quick, anonymous functions

square = lambda x: x * x print(square(5)) # 25

A lambda is a small, unnamed function written in one line: lambda parameters: expression. It's equivalent to:

def square(x): return x * x

The key restriction: a lambda can only contain a single expression — no multiple lines, no loops, no if/elif/else chains inside it (a simple conditional expression is allowed, but full statements are not). Lambdas are meant for short, throwaway logic, not complex functions.

03 map() — apply a function to every item

prices = [100, 250, 80, 500] doubled = list(map(lambda x: x * 2, prices)) print(doubled) # [200, 500, 160, 1000]

map(function, list) applies the function to EVERY element and gives back the transformed results. Note the list() wrapper — in real Python, map() returns a special "map object" (a lazy iterator), not a list directly, so you need to wrap it in list() to see or use the actual values.

04 filter() — keep only matching items

prices = [100, 250, 80, 500] expensive = list(filter(lambda x: x > 150, prices)) print(expensive) # [250, 500]

filter(function, list) keeps only the elements where the function returns True — exactly the same "condition-based keep" logic as Day 35's append-in-a-loop pattern, just written more compactly.

05 Real-world example (currency conversion + filtering)

Business example

usd_prices = [10, 25, 8, 50, 15] exchange_rate = 83 inr_prices = list(map(lambda x: x * exchange_rate, usd_prices)) print(inr_prices) # [830, 2075, 664, 4150, 1245] premium_items = list(filter(lambda x: x > 2000, inr_prices)) print(premium_items) # [2075, 4150]

This two-step pattern — transform everything with map, then narrow down with filter — is extremely common in real data pipelines, and reads almost like a sentence: "convert all prices, then keep only the expensive ones."

06 Second example (sorting by a custom key)

A genuinely essential real-world pattern

products = [ {"name": "Pen", "price": 20}, {"name": "Bag", "price": 899}, {"name": "Notebook", "price": 60} ] sorted_products = sorted(products, key=lambda p: p["price"]) print(sorted_products) # sorted from cheapest to most expensive

sorted(list, key=...) lets you sort by ANY custom rule — here, by the "price" field inside each dictionary — instead of Python's default ordering. This is precisely how you'll sort real records (by date, by score, by relevance) throughout your data work.

07 Common mistakes to avoid

Mistake 1 — Forgetting to wrap map()/filter() in list(). Printing a bare map(...) shows something like <map object at 0x...>, not the actual values — always wrap with list() to see or use the results.

Mistake 2 — Trying to put multiple statements inside a lambda. Lambdas support exactly one expression — if your logic needs multiple steps or a loop, write a regular def function instead.

Mistake 3 — Overusing lambda for genuinely complex logic. A deeply nested lambda hurts readability — if you find yourself squinting at a lambda, it's a sign to name it as a proper function instead.

Mistake 4 — Forgetting sorted() returns a NEW list. Unlike Day 35's .sort() (which sorts in place and returns None), sorted() returns a brand new sorted list, leaving the original untouched — genuinely useful to keep both versions when needed.
