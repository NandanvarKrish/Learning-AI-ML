File Handling

~2 hours · Reading and writing real files — where every dataset starts

01 Why this matters for AI/ML

Before you can train any model, you have to load data — and that data lives in files. Every CSV dataset you'll open with Pandas in a few weeks is, underneath, exactly this: a text file being read line by line. Understanding file handling directly demystifies what pd.read_csv() is actually doing for you later.

02 Opening a file

file = open("data.txt", "r") content = file.read() print(content) file.close()
"r"Read (default) — file must exist
"w"Write — creates new or ERASES existing content
"a"Append — adds to the end, keeps existing content

The mode matters enormously. Opening an existing file in "w" mode instantly erases everything already in it — a genuinely costly mistake if you meant to append instead.

03 The `with` statement — the correct way to open files

with open("data.txt", "r") as file: content = file.read() print(content) # file is automatically closed here, even if an error happened above

Always prefer with over manually calling open() and .close(). The with block guarantees the file gets closed properly the moment the block ends — even if an error occurs partway through. Forgetting .close() with the manual approach is a real, common bug (it can leave files locked or changes unsaved) — with eliminates that risk entirely and is considered standard best practice.

04 Reading — three ways

with open("data.txt", "r") as file: whole_thing = file.read() # one big string, entire file with open("data.txt", "r") as file: all_lines = file.readlines() # a list, one string per line with open("data.txt", "r") as file: for line in file: # loop through line by line print(line.strip()) # .strip() removes the trailing newline

Note: each line read this way keeps its trailing newline character (\n) attached — this is why you'll almost always see .strip() called immediately after reading a line, using exactly Day 42's string method.

05 Writing

with open("output.txt", "w") as file: file.write("Hello, file!\n") file.write("Second line\n")

You must add \n yourself — unlike print(), .write() does NOT automatically add a newline after each call. Forgetting this results in all your text running together on one line.

06 Real-world example (saving processed results)

A genuinely common real task

clean_names = ["Asha", "Rohan", "Priya", "Meera"] with open("clean_names.txt", "w") as file: for i in range(len(clean_names)): file.write(clean_names[i] + "\n")

This is precisely how you'd save cleaned/processed data (from Day 42's cleaning example) back to disk — a completely ordinary step in any real data pipeline, before or after using a tool like Pandas.

07 Second example (reading and parsing a data file)

Directly extends yesterday's line-splitting skill

with open("customers.txt", "r") as file: for line in file: fields = line.strip().split(",") name = fields[0] age = int(fields[1]) print(f"{name} is {age} years old")

Read line by line, strip the trailing newline, split on commas, convert types — this exact sequence is, structurally, a hand-built CSV reader. It's precisely what a library function does automatically, just visible step by step here.

08 Common mistakes to avoid

Mistake 1 — Opening in "w" mode when you meant "a". This silently destroys existing file content — always double check the mode before writing.

Mistake 2 — Forgetting to add "\n" when writing lines. Without it, every .write() call runs together into one unreadable line.

Mistake 3 — Forgetting .strip() when reading lines. Each line read via a loop keeps its trailing newline — comparing or printing without stripping it can cause subtle bugs.

Mistake 4 — Manually managing open()/close() instead of using `with`. If an error happens between open() and close(), the file may never get properly closed — `with` handles this safety automatically.

Note: a file that doesn't exist (opened in "r" mode) raises a FileNotFoundError — handling that gracefully is exactly what tomorrow's exception handling (try/except) covers.
