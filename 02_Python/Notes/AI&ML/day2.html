Functions, f(x) & Plotting by Hand

~2 hours · Builds directly on Day 1's equations

01 Why this matters for AI/ML

An ML model is a function. Give it an input (house size, image pixels, your search query), it gives you an output (predicted price, "cat" or "dog", the next word). Everything from "linear regression" to "GPT" is, at its core, a very complicated f(x). Today you learn what that notation actually means and how to reason about it — in plain, visual terms.

02 What is a function?

A function is a rule that takes an input and produces exactly one output. We write it as:

f(x) = 2x + 3

Read this as: "f of x equals 2x plus 3." It means: "take whatever number x is, double it, then add 3." The letter f is just the function's name (like naming a machine), and x is the input you feed into it.

Think of it like a machine: you drop a number in one end (input), the machine processes it using a fixed rule, and a result comes out the other end (output). Same input → always the same output. That consistency is what makes it a "function" and not just a random guess.

See it evaluated for a few values of x

For f(x) = 2x + 3:

x (input)0123-1
f(x) (output)35791

Notice: every time x goes up by 1, f(x) goes up by 2 — that "2" is the same number multiplying x in the rule. That consistent rate of change is what you'll later call the slope.

03 Real-world example (mobile recharge plan)

Everyday example

Your mobile operator charges a fixed monthly plan fee of ₹99, plus ₹1 per GB of extra data you use beyond your limit. This is a function of how much extra data (x, in GB) you use:

f(x) = 99 + 1x

If you use 10 extra GB this month: f(10) = 99 + 10 = ₹109. If you use 0 extra GB: f(0) = ₹99 (just the base fee).

Notice this is the exact same structure as yesterday's "fixed cost + rate × units." A function is just that same idea, given a formal name and notation so we can talk about it precisely — and, importantly, plug in any x we want to instantly get an answer, without re-deriving the equation each time.

04 Plotting a function by hand

To plot f(x) = 2x + 3, you turn it into points on a graph. Each x-value and its f(x) becomes a coordinate pair (x, y):

x-2-1012
f(x)-11357
Point(-2,-1)(-1,1)(0,3)(1,5)(2,7)

Steps to plot by hand on graph paper:

1. Draw an x-axis (horizontal) and y-axis (vertical), crossing at (0,0).

2. Pick 4–5 values of x (e.g., -2, -1, 0, 1, 2).

3. Calculate f(x) for each — build a table like above.

4. Plot each (x, f(x)) as a dot.

5. Since this is a linear function, connect the dots — you'll get a straight line.

Do this on paper right now for f(x) = 2x + 3 before moving on. Actually drawing the axes and plotting dots builds spatial intuition that reading alone never will.

05 Second real-world example (simple interest)

Finance example — familiar from commerce

You deposit ₹10,000 in a savings account earning simple interest of ₹500 per year. Your balance as a function of years (x) elapsed:

f(x) = 10000 + 500x

After 3 years: f(3) = 10000 + 1500 = ₹11,500. Plot this function (x = years on the horizontal axis, f(x) = balance on the vertical axis) and you get the classic "growing savings" line you've probably seen in a finance textbook — except now you know it's just a function being evaluated and plotted.

06 Common mistakes to avoid

Mistake 1 — Confusing f(x) with f times x. f(x) does NOT mean "f multiplied by x." It means "the function f, evaluated at the input x." This confuses almost everyone at first — it's just notation, not multiplication.

Mistake 2 — Plotting too few points for a curve. For straight lines, 2 points are technically enough, but use 4–5 to catch calculation errors. For curves (later, non-linear functions), you'll need many more points.

Mistake 3 — Mixing up which axis is which. By convention, x (input) is always horizontal, f(x)/y (output) is always vertical.

Mistake 4 — Forgetting order of operations. In f(x) = 2x + 3, always multiply before adding — f(4) is 2×4+3 = 11, not 2×(4+3) = 14.

09 Quick Self-Check (8 questions)

Looking ahead: Every ML model you'll build is a function — input goes in, prediction comes out. "Training" a model literally means the computer searching for the best m and c (and, later, thousands of similar numbers) so that f(x) matches real-world outcomes as closely as possible.
