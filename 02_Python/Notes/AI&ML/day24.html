Gradients & Gradient Descent

~2 hours · The exact algorithm that trains almost every ML model

01 Why this matters for AI/ML

Today's topic isn't preparation for something later — it IS the thing. Gradient descent, built entirely from yesterday's derivative concept, is the algorithm that trains linear regression, logistic regression, and every neural network you'll build in this entire plan. Understanding it well here means Phase 3 and 4 will feel like applying a familiar idea, not learning something brand new.

02 From derivative to gradient

Yesterday's derivative worked for functions with ONE input variable, like f(x). Real ML models have functions with many input variables — a "weight" for every feature. A gradient is simply the extension of the derivative idea to functions with multiple variables: it's a vector containing the partial derivative with respect to each variable.

∇f(x,y) = [ ∂f/∂x, ∂f/∂y ]

A "partial derivative" (written ∂ instead of d) means: take the derivative with respect to ONE variable, while treating every other variable as a constant that doesn't change.

03 Worked example

f(x,y) = x² + y²

Partial derivative with respect to x (treat y as a constant, so y² contributes 0): ∂f/∂x = 2x

Partial derivative with respect to y (treat x as a constant, so x² contributes 0): ∂f/∂y = 2y

So the gradient: ∇f(x,y) = [2x, 2y]. At the point (3,4): ∇f(3,4) = [6, 8]

What does this gradient vector mean?

The gradient [6,8] points in the direction of steepest increase of the function at that point — like an arrow pointing straight uphill on a landscape. This is the crucial idea for the next section.

04 Gradient descent — the actual algorithm

Since the gradient points toward the steepest increase, to minimize a function (like an error/cost function), you move in the opposite direction — "descending" the gradient:

new_x = old_x − (learning_rate × gradient)

You repeat this step over and over: calculate the gradient, take a small step in the opposite direction, recalculate, step again — gradually walking downhill toward the minimum (lowest error).

The fog-on-a-mountain analogy: imagine you're standing on a hillside in thick fog, trying to reach the valley floor. You can't see the whole landscape, but you can feel the slope right under your feet. So you take a step in the steepest downhill direction, feel the new slope, take another step, and repeat. That's gradient descent — no global view needed, just repeated local information.

05 The learning rate matters enormously

The most important practical detail

Too small a learning rate: tiny steps, converges correctly but painfully slowly — could take enormous amounts of time/computation.

Too large a learning rate: huge steps that overshoot the minimum, potentially bouncing back and forth or even diverging further away instead of converging.

Just right: steady, efficient steps that settle into the minimum in a reasonable number of iterations.

Try this directly in the interactive tool below — it's one of the most common things you'll tune by hand once you start training real models in Phase 3.

06 Common mistakes to avoid

Mistake 1 — Moving in the direction of the gradient instead of against it. The gradient points toward increase — to minimize, you MUST subtract it (move opposite), not add it.

Mistake 2 — Assuming a single derivative is the same as a gradient. A gradient is a vector (one value per input variable); a derivative alone is a single scalar, only meaningful for one-variable functions.

Mistake 3 — Ignoring the learning rate's role. The same gradient value can lead to totally different outcomes (smooth convergence vs. wild divergence) purely based on the learning rate chosen.

Mistake 4 — Expecting gradient descent to always find the absolute best answer. For complicated, bumpy (non-convex) functions, gradient descent can get stuck in a "local" low point that isn't the true lowest point overall — a real limitation you'll encounter again in Phase 4's neural networks.
