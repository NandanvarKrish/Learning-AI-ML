Lists — Creating, Indexing & Slicing

~2 hours · Where loops finally get real data to work with

01 Why this matters for AI/ML

A list is Python's way of storing many values together, in order. Before you ever touch a "real" dataset, you'll build and manipulate lists constantly — and once you reach NumPy/Pandas in a couple weeks, you'll find their arrays and DataFrames are essentially souped-up, faster versions of exactly this same idea.

02 Creating a list

daily_sales = [1200, 1500, 900, 1800, 2000] names = ["Asha", "Ravi", "Meera"] mixed = [1, "hello", 3.5, True] # lists can mix types too

A list is written with square brackets, values separated by commas. Unlike many languages, Python lists can hold mixed types in the same list, though in practice (and especially in data work) you'll usually keep one type per list.

daily_sales[0] # 1200 (first element) daily_sales[2] # 900 (third element) daily_sales[-1] # 2000 (last element — negative indexing counts from the end) daily_sales[-2] # 1800 (second to last)

Negative indexing is a genuinely useful Python feature — -1 always means "the last item," regardless of how long the list is, so you don't need to know the length to grab the last element.

04 Slicing — accessing a range of elements

daily_sales[1:3] # [1500, 900] — index 1 up to (not including) index 3 daily_sales[:2] # [1200, 1500] — from the start up to index 2 daily_sales[2:] # [900, 1800, 2000] — from index 2 to the end daily_sales[::2] # [1200, 900, 2000] — every 2nd element daily_sales[::-1] # [2000, 1800, 900, 1500, 1200] — reversed!

Slicing syntax is list[start:stop:step] — any part can be omitted to use a sensible default (start of list, end of list, or step of 1). The stop index is always excluded — exactly the same "exclusive stop" rule you already learned for range() on Day 30.

05 len() — how many elements

len(daily_sales) # 5

This is used constantly, especially combined with range() for looping through a list by index: for i in range(len(daily_sales)):

06 Real-world example (weekly sales, revisited)

Now with real list operations instead of the Day 30 preview

daily_sales = [1200, 1500, 900, 1800, 2000, 1100, 1700] first_half = daily_sales[:4] # first 4 days second_half = daily_sales[4:] # remaining days best_day = max(daily_sales) # highest value in the list worst_day = min(daily_sales) # lowest value print(daily_sales[-1]) # last day's sales print(len(daily_sales)) # 7 (total days recorded)

Slicing a week into "first half / second half" like this is exactly the kind of operation you'll do constantly when splitting a dataset into training and testing portions in Phase 3.

07 Common mistakes to avoid

Mistake 1 — Forgetting indexing starts at 0. The "first" element is list[0], not list[1] — a very common off-by-one trap.

Mistake 2 — IndexError from going out of range. If a list has 5 elements (indices 0-4), list[5] causes an error — there is no 6th element.

Mistake 3 — Expecting slicing's stop index to be included. Just like range(), list[1:3] gives indices 1 and 2 only, NOT index 3.

Mistake 4 — Confusing an index with a value. daily_sales[2] means "the element AT position 2" (which is 900), not "the number 2."
