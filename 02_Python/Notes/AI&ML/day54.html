Missing & Imbalanced Data

~2 hours · The two data problems you'll meet in almost every real dataset

01 Why this matters for AI/ML

Real datasets are never perfectly clean. Missing values (blank cells) and imbalanced classes (one outcome vastly outnumbering another, like fraud cases vs. normal transactions) are two of the most common real-world data problems — and both can silently break or mislead a model if you don't handle them deliberately.

02 Missing data — detecting it

import pandas as pd df = pd.read_csv("customers.csv") print(df.isnull()) # True/False for every cell print(df.isnull().sum()) # count of missing values PER COLUMN

Missing values in Pandas show up as NaN ("Not a Number"). .isnull().sum() is almost always the first thing you run on a new dataset — it tells you immediately which columns have gaps, and how many.

03 Two strategies: dropna() and fillna()

df_clean = df.dropna() # remove any row with a missing value df_filled = df.fillna(0) # replace missing values with 0 df_filled2 = df["age"].fillna(df["age"].mean()) # fill with the column's mean (Day 6!)

dropna() is simple but throws away data — sometimes acceptable, sometimes wasteful if it removes a large chunk of your dataset. fillna() keeps every row but requires you to choose a sensible replacement value — filling a numeric column with its own mean (exactly Day 6's concept) is a common, reasonable default.

04 Real-world example (filling missing ages)

A genuinely typical cleaning step

df = pd.read_csv("customers.csv") print(df.isnull().sum()) # name 0 # age 3 # order_value 0 mean_age = df["age"].mean() df["age"] = df["age"].fillna(mean_age) print(df.isnull().sum()) # age 0 — all filled

Three customers had no recorded age — rather than losing those rows entirely, filling with the average age keeps the data usable while making a reasonable, clearly-stated assumption.

05 Imbalanced data — the classification trap

One of the most important lessons before Phase 3

Imagine a fraud detection dataset: 950 normal transactions, 50 fraudulent ones. A "lazy" model that always predicts "not fraud", never actually checking anything, would still be 95% accurate — because it's right on all 950 normal cases and only wrong on the 50 fraud cases.

accuracy = 950 / 1000 = 0.95 # 95% "accurate" — but completely useless!

This is exactly why accuracy alone is a dangerous, misleading metric on imbalanced data. A model can look great on paper while never actually catching the thing you built it for. You'll formally meet better metrics (precision, recall) in Phase 3 — for now, the key lesson is: always check your class balance before trusting an accuracy number.

06 Checking for imbalance

print(df["fraud"].value_counts()) # False 950 # True 50

.value_counts() is the standard, fast way to check how many rows fall into each category — run this on any classification target column before doing anything else.

07 A preview of fixes (covered fully in Phase 3)

Oversampling — duplicate (or synthetically generate) more examples of the minority class.

Undersampling — remove some examples of the majority class to balance things out.

Class weights — tell the model to "pay more attention" to mistakes on the minority class during training.

You don't need to implement these yet — just recognize the vocabulary and the underlying problem they solve, since you'll meet them properly once you start training classifiers.

08 Common mistakes to avoid

Mistake 1 — Filling missing values with 0 without thinking about meaning. An age of 0, or a price of 0, might be nonsensical for your data — 0 is a value with real meaning, not a neutral placeholder.

Mistake 2 — Calling dropna() without checking how much data you'd lose. Always check df.isnull().sum() and the row count before and after — dropping 40% of your rows might be a serious problem.

Mistake 3 — Trusting accuracy alone on an imbalanced dataset. As shown above, a 95%-accurate model can be worthless — always check the class balance first.

Mistake 4 — Forgetting to check value_counts() before modeling. Skipping this step means you might not even realize your data is imbalanced until your model mysteriously fails on the minority class in production.
