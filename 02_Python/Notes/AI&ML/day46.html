Constructors (__init__)

~2 hours · Setting up an object's attributes automatically, at creation time

01 Why this matters for AI/ML

When you write model = LinearRegression(fit_intercept=True) in Phase 3, that's a constructor in action — the model object is configured immediately at creation, not built empty and filled in line by line afterward. Today you learn exactly how that pattern works.

02 The __init__ method

__init__ is a special method that runs automatically the moment an object is created — its job is to set up the object's starting attributes.

class Dog: def __init__(self, name, age): self.name = name self.age = age my_dog = Dog("Bruno", 3) # __init__ runs immediately print(my_dog.name) # Bruno print(my_dog.age) # 3

Compare this to yesterday's approach — my_dog.name = "Bruno" written as a separate line after creation. With __init__, you supply the values directly when creating the object, and they're guaranteed to be set immediately — no risk of forgetting to assign something before using it.

03 Why this is safer than yesterday's approach

Yesterday, this was completely possible (and a real bug risk):

class Item: def show(self): print(self.name) x = Item() x.show() # AttributeError! forgot to set x.name first

With a constructor requiring name as a parameter, this mistake becomes essentially impossible — you cannot create the object at all without supplying the required values, since Python enforces it the moment you call ClassName(...).

04 Default values in __init__

class Customer: def __init__(self, name, is_premium=False): self.name = name self.is_premium = is_premium c1 = Customer("Asha") # is_premium defaults to False c2 = Customer("Rohan", True) # explicitly overridden

Exactly Day 39's default argument rule applies here too — __init__ is just a method, following all the same parameter rules you already know.

05 Real-world example (Customer class, properly built)

The clean version of yesterday's Customer example

class Customer: def __init__(self, name, age, order_value): self.name = name self.age = age self.order_value = order_value def apply_discount(self, percent): return self.order_value - (self.order_value * percent / 100) customer1 = Customer("Rohan", 28, 1200) print(customer1.name) # Rohan print(customer1.apply_discount(20)) # 960.0

One line creates a fully-configured object — no risk of a half-built customer missing a required field partway through your program.

06 Second example (BankAccount class)

Reconnects to Day 31's withdrawal loop example

class BankAccount: def __init__(self, owner, balance=0): self.owner = owner self.balance = balance def deposit(self, amount): self.balance = self.balance + amount def withdraw(self, amount): if amount > self.balance: print("Insufficient funds") else: self.balance = self.balance - amount account = BankAccount("Priya", 5000) account.deposit(1500) account.withdraw(2000) print(account.balance) # 4500

This is the classic OOP teaching example for good reason — an account's balance and the operations on it (deposit, withdraw) genuinely belong bundled together, exactly what a class is for.

07 Common mistakes to avoid

Mistake 1 — Forgetting self as __init__'s first parameter. Same rule as every other method — self always comes first.

Mistake 2 — Misspelling __init__ (wrong number of underscores). It's exactly two underscores on each side — _init_ or __init won't be recognized as the constructor and simply becomes an ordinary, never-automatically-called method.

Mistake 3 — Calling ClassName() without the arguments __init__ requires. If __init__ has required (non-default) parameters, you must supply them when creating the object, or you'll get a TypeError.

Mistake 4 — Forgetting to prefix attributes with self. inside __init__. Writing name = name (missing self.) creates a local variable that disappears when __init__ finishes — it does NOT become an attribute on the object.
