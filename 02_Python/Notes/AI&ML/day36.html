Tuples & Sets

~2 hours · Two more collection types, each with different rules

01 Why this matters for AI/ML

Lists aren't always the right tool. Tuples represent fixed, unchanging records (like a pixel's RGB value or a coordinate pair) — you'll see them constantly as function return values in real libraries. Sets are the fastest way to deduplicate data and check membership — genuinely useful for real data cleaning tasks like "how many unique customers are in this list of 10,000 orders?"

02 Tuples — immutable, ordered

point = (3, 7) rgb = (255, 0, 128) print(point[0]) # 3 — indexing works just like lists point[0] = 10 # ERROR! Tuples cannot be changed after creation

Tuples use parentheses instead of square brackets. Everything about reading a tuple works exactly like a list (indexing, slicing, len()) — the difference is entirely about immutability: once created, a tuple can never be modified. No append, no remove, no changing an element.

Gotcha: a single-element tuple needs a trailing comma.

not_a_tuple = (5) # this is just the integer 5! actual_tuple = (5,) # this IS a tuple with one element

Without the comma, Python just treats the parentheses as regular math grouping, not a tuple — an easy, common mistake.

03 Sets — unordered, no duplicates

unique_ids = {101, 102, 103, 102, 101} print(unique_ids) # {101, 102, 103} — duplicates automatically removed! print(102 in unique_ids) # True — very fast membership check

Sets use curly braces. Two defining features: duplicates are automatically removed, and membership testing with in is extremely fast — much faster than checking "is x in this list?" for large collections, which matters once you're working with real-sized data.

Sets have no order and no indexing — you can't do my_set[0], since there's no defined "first" element in a set.

04 Quick comparison

List
[1,2,3]
Ordered · Mutable · Duplicates OK · Indexed
Tuple
(1,2,3)
Ordered · Immutable · Duplicates OK · Indexed
Set
{1,2,3}
Unordered · Mutable · No duplicates · Not indexed

05 Real-world example (RGB pixel — reconnects Day 18)

Ties back to the image-as-matrix example

pixel = (220, 45, 60) # (Red, Green, Blue) — a fixed, 3-value record def brightness(p): return (p[0] + p[1] + p[2]) / 3

A pixel's color is a perfect example of data that should NEVER accidentally change mid-calculation — using a tuple instead of a list is a small but real safeguard: nothing in your code can accidentally overwrite the Red value while you're working with Green and Blue.

06 Second example (deduplicating customers)

A genuinely common real data-cleaning task

order_customer_ids = [501, 502, 501, 503, 502, 501, 504] unique_customers = set(order_customer_ids) print(unique_customers) # {501, 502, 503, 504} print(len(unique_customers)) # 4 — exactly 4 unique customers placed these 7 orders

Converting a list to a set with set() is one of the fastest, most idiomatic ways to answer "how many unique X are there?" — you'll use this exact pattern regularly once working with real transaction or log data.

07 Common mistakes to avoid

Mistake 1 — Trying to modify a tuple. my_tuple[0] = 5 raises a TypeError — tuples are immutable by design, this isn't a bug to work around.

Mistake 2 — Forgetting the trailing comma for a single-element tuple. (5) is just the number 5, not a tuple — you need (5,).

Mistake 3 — Expecting a set to preserve insertion order or support indexing. Sets don't guarantee order and can't be indexed with my_set[0] — if order matters, use a list.

Mistake 4 — Confusing an empty {} with an empty set. In Python, {} actually creates an empty dictionary (tomorrow's topic), not an empty set — use set() to make a genuinely empty set.
