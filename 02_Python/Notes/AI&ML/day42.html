String Manipulation

~2 hours · Slicing, formatting, and methods for cleaning real text

01 Why this matters for AI/ML

Real-world text data is messy — inconsistent capitalization, stray whitespace, mixed formats. Before any NLP model can process text, or before any dataset with text columns can be analyzed, it needs cleaning — and that cleaning is built almost entirely from today's string methods.

02 Strings work like lists (indexing & slicing)

word = "Python" print(word[0]) # P print(word[-1]) # n print(word[0:3]) # Pyt print(word[::-1]) # nohtyP — reversed!

Every indexing and slicing rule from Day 34 applies identically to strings — a string is really just a sequence of characters, same as a list is a sequence of values.

03 Key string methods

.upper() / .lower()
Convert case
.strip()
Removes leading/trailing whitespace
.replace(old, new)
Replaces all occurrences
.split(sep)
Splits into a list of pieces
"sep".join(list)
Joins a list into one string
.startswith(x) / .endswith(x)
Check the start/end
name = " asha " print(name.strip()) # "asha" (whitespace removed) print(name.strip().upper()) # "ASHA" text = "2024-06-15" parts = text.split("-") print(parts) # ['2024', '06', '15'] joined = "-".join(["2024", "06", "15"]) print(joined) # "2024-06-15"

Strings are immutable — every one of these methods returns a brand NEW string; they never change the original. Just like Day 41's sorted(), you must capture the result: clean_name = name.strip(), not just call name.strip() and expect name itself to change.

04 f-strings — the modern way to format text

name = "Priya" age = 25 print(f"{name} is {age} years old") # Priya is 25 years old

An f-string (prefix the quotes with f) lets you embed variables directly inside { } placeholders — far cleaner than the string-concatenation-with-+ style you've been using since Day 27. You can put any expression inside the braces, not just a bare variable name:

price = 500 print(f"Total with tax: {price * 1.18}") # Total with tax: 590.0

05 Real-world example (cleaning messy customer input)

A genuine, constant real-world need

raw_names = [" Asha ", "ROHAN", "priya ", " Meera"] clean_names = [] for i in range(len(raw_names)): cleaned = raw_names[i].strip().title() clean_names.append(cleaned) print(clean_names) # ['Asha', 'Rohan', 'Priya', 'Meera']

Form input, scraped data, and spreadsheet exports are almost never perfectly clean — this exact strip-then-standardize-case pattern is something you'll write constantly before any real analysis can begin.

06 Second example (splitting a data line)

Foreshadows reading real files tomorrow

line = "Rohan,28,1200.50,True" fields = line.split(",") print(fields) # ['Rohan', '28', '1200.50', 'True'] name = fields[0] age = int(fields[1]) print(f"{name} is {age} years old")

This is essentially how a CSV file's row gets processed under the hood — split the line on commas, then convert each piece to its proper type. Tomorrow's file-handling lesson builds directly on exactly this skill.

07 Common mistakes to avoid

Mistake 1 — Forgetting strings are immutable. name.strip() alone does nothing to name — you must reassign: name = name.strip().

Mistake 2 — Confusing .split() and .join() direction. .split() is called ON a string, producing a list. .join() is called ON the delimiter string, taking a list as its argument — easy to get backwards at first.

Mistake 3 — Forgetting the f before an f-string. "{name}" without the f prefix just prints the literal text {name}, not the variable's value.

Mistake 4 — Assuming .split() with no argument splits on a single space. With no argument, .split() splits on ANY whitespace (including multiple spaces, tabs) and also discards leading/trailing empty pieces — genuinely useful default behavior, but worth knowing explicitly.
