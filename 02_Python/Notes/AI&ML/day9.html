Probability Basics

~2 hours · Sample space, events, and your first probability formulas

01 Why this matters for AI/ML

When a classification model says "87% chance this is spam," that number is a probability, produced using the exact same rules you'll learn today, just computed automatically from data. Naive Bayes (a full algorithm you'll build in Phase 3) is literally built entirely out of today's formulas. Probability is the language ML uses to express uncertainty — and almost every prediction a model makes is really a probability in disguise.

02 What is probability?

Probability measures how likely an event is to happen, expressed as a number between 0 (impossible) and 1 (certain):

P(event) = (favorable outcomes) / (total possible outcomes)

Example: A bag has 3 red balls and 7 blue balls (10 total). What's the probability of drawing red?

P(red) = 3 / 10 = 0.3 (or 30%)

03 Sample space and events

The sample space is the set of ALL possible outcomes of an experiment. An event is any specific outcome (or group of outcomes) you're interested in — a subset of the sample space.

Example: Rolling a die. Sample space = {1, 2, 3, 4, 5, 6} — 6 total outcomes.

Event "rolling an even number" = {2, 4, 6} — 3 outcomes out of the sample space.

P(even) = 3/6 = 0.5

Another sample space example

Tossing 2 coins. Sample space = {HH, HT, TH, TT} — 4 total outcomes.

Event "at least one Head" = {HH, HT, TH} — 3 outcomes.

P(at least one head) = 3/4 = 0.75

04 Real-world example (quality control)

Business example

A factory produces 500 units in a batch, and past data shows 15 are typically defective. What's the probability a randomly picked unit is defective?

P(defective) = 15 / 500 = 0.03 (3%)

This exact calculation — historical frequency used to estimate future probability — is precisely how ML models "learn" probabilities from training data. The model doesn't know the true defect rate; it estimates it from patterns in the data it's seen, just like this factory calculation does.

05 Complementary events

The complement of an event is "everything except that event." Since all probabilities must add up to 1:

P(not A) = 1 − P(A)

Example: If P(defective) = 0.03, then P(not defective) = 1 − 0.03 = 0.97 (97% of units are fine).

This is often the fastest way to solve a probability problem — sometimes it's much easier to calculate the complement and subtract from 1 than to calculate the event directly.

06 Second example (loan approval)

Finance example

A bank's records show that out of 1,000 loan applications last year, 720 were approved. Based on this data, what's the probability a new application gets approved?

P(approved) = 720/1000 = 0.72. P(rejected) = 1 − 0.72 = 0.28.

This is genuinely how a real credit-scoring ML model starts — by learning approval probability patterns from thousands of historical applications, then refining that estimate using more detailed features (income, credit history, etc.) which you'll learn to incorporate in Phase 3.

07 Common mistakes to avoid

Mistake 1 — Probability values outside 0 to 1. If your calculated probability is negative or greater than 1, you've made an error — go back and check your favorable/total counts.

Mistake 2 — Miscounting the sample space. Forgetting an outcome (or double-counting one) throws off every probability calculated from it. List out the sample space explicitly for tricky problems.

Mistake 3 — Forgetting all probabilities in a sample space must sum to 1. If P(A) + P(B) + P(C) ≠ 1 for all possible outcomes A, B, C, something's wrong.

Mistake 4 — Assuming past frequency always equals true future probability. A factory's historical 3% defect rate is an estimate, not a guarantee — real-world probability from data always carries some uncertainty, especially with small sample sizes.
