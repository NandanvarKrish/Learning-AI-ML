Classes & Objects

~2 hours · Bundling data and behavior together — the pattern behind scikit-learn's entire API

01 Why this matters for AI/ML

Nearly every ML library you'll use is built around classes. In Phase 3, you'll write things like model = LinearRegression() then model.fit(X, y) — that's creating an object from a class, then calling a method on it. Today you learn exactly what's happening when you write that code, instead of it feeling like memorized magic syntax.

02 Classes and objects — the core idea

A class is a blueprint — it describes what kind of data and behavior something will have, without being any specific instance of it. An object (or "instance") is one actual thing built from that blueprint.

class Dog: pass # an empty class for now my_dog = Dog() # creates an OBJECT (instance) of the Dog class print(type(my_dog)) #

Think of "Dog" as the general idea/blueprint, and my_dog as one particular, real dog built from that blueprint. You could create many dogs — dog1 = Dog(), dog2 = Dog() — each a separate, independent object.

03 Attributes — data attached to an object

class Dog: pass my_dog = Dog() my_dog.name = "Bruno" my_dog.age = 3 print(my_dog.name) # Bruno print(my_dog.age) # 3

An attribute is a piece of data stored ON a specific object. Two different Dog objects can have completely different attribute values — that's the point of an object representing one specific "thing."

04 Methods — functions that belong to a class

class Dog: def bark(self): print(self.name + " says woof!") my_dog = Dog() my_dog.name = "Bruno" my_dog.bark() # Bruno says woof!

A method is just a function defined inside a class. The first parameter is always self — it refers to "this particular object" the method was called on, letting the method access that object's own attributes (like self.name above).

You never pass a value for self yourself — Python fills it in automatically as whichever object you called the method on.

05 Real-world example (Customer class)

Reconnects to Day 27 and Day 37's customer data

class Customer: def show_info(self): print(self.name + " is " + str(self.age) + " years old") def apply_discount(self, percent): discounted = self.order_value - (self.order_value * percent / 100) return discounted customer1 = Customer() customer1.name = "Rohan" customer1.age = 28 customer1.order_value = 1200 customer1.show_info() # Rohan is 28 years old print(customer1.apply_discount(20)) # 960.0

Compare this to Day 27's separate variables, and Day 37's dictionary — a class bundles the DATA (name, age, order_value) together WITH the BEHAVIOR (show_info, apply_discount) that acts on it, in one organized unit.

06 Second example (multiple independent objects)

Each object keeps its own separate data

class Product: def describe(self): print(self.name + ": ₹" + str(self.price)) pen = Product() pen.name = "Pen" pen.price = 20 notebook = Product() notebook.name = "Notebook" notebook.price = 60 pen.describe() # Pen: ₹20 notebook.describe() # Notebook: ₹60

pen and notebook are both Product objects, built from the same class, but each holds its own independent set of attribute values.

07 Common mistakes to avoid

Mistake 1 — Forgetting the parentheses when creating an object. my_dog = Dog (no parentheses) just refers to the CLASS itself, not a new object — you need Dog().

Mistake 2 — Forgetting self as a method's first parameter. Every method needs it, even if unused — Python automatically passes the calling object as the first argument.

Mistake 3 — Confusing the class with an instance. Dog is the blueprint; my_dog is one specific object built from it.

Mistake 4 — Typo'd attribute names silently creating a NEW attribute. If you accidentally write my_dog.nmae = "Bruno" (typo), Python doesn't error — it just creates a new, different attribute. A genuinely sneaky source of bugs.
