Exponents & Logarithms

~2 hours · Last math-refresher day before Linear Algebra

01 Why this matters for AI/ML

Two things you'll meet constantly once you start real ML: the sigmoid function (which turns any number into a probability using e^(-x)) and log loss / cross-entropy (the most common way to measure how wrong a classification model is, which literally uses logarithms in its formula). Both are unavoidable — you can't understand classification or neural network training without today's topic.

02 What is an exponent?

An exponent tells you how many times to multiply a number by itself:

2³ = 2 × 2 × 2 = 8

Here, 2 is the base and 3 is the exponent (or power). Read it as "2 to the power of 3" or "2 cubed."

03 The core exponent rules

Product Rule
aᵐ × aⁿ = aᵐ⁺ⁿ
Quotient Rule
aᵐ ÷ aⁿ = aᵐ⁻ⁿ
Power of a Power
(aᵐ)ⁿ = aᵐˣⁿ
Zero Exponent
a⁰ = 1 (a ≠ 0)
Negative Exponent
a⁻ⁿ = 1/aⁿ
Fractional Exponent
a^(1/2) = √a
See each rule with a worked number example

Product: 2² × 2³ = 2⁵ = 32 (check: 4 × 8 = 32 ✓)

Quotient: 5⁴ ÷ 5² = 5² = 25

Power of a power: (3²)³ = 3⁶ = 729

Zero: 9⁰ = 1

Negative: 2⁻² = 1/2² = 1/4 = 0.25

Fractional: 16^(1/2) = √16 = 4

04 Real-world example (compound interest)

Finance example — exponential growth in action

You invest ₹50,000 at 10% annual compound interest. The formula (which you've likely seen in commerce):

A = P(1 + r)ⁿ

Where P = principal (₹50,000), r = rate (0.10), n = number of years. After 5 years:

A = 50000 × (1.10)⁵ = 50000 × 1.61051 ≈ ₹80,526

That (1.10)⁵ is exactly an exponent in action — the base (1.10) multiplied by itself 5 times. This is also why compound interest grows so much faster than simple interest (Day 3's linear example): exponents cause explosive growth, while slopes cause steady, constant growth. Neural networks rely on this same explosive-growth behavior (via e^x) to model probabilities smoothly.

05 What is a logarithm?

A logarithm answers the opposite question of an exponent. Instead of "what do I get if I raise 2 to the power of 3?", it asks: "what power do I need to raise 2 to, to get 8?"

log₂(8) = 3    because    2³ = 8

In general: log_b(x) = y means exactly the same thing as b^y = x. A logarithm is simply the inverse operation of an exponent — same relationship as addition/subtraction or multiplication/division.

The most common log you'll see in ML: natural log, written "ln". This uses the special number e ≈ 2.71828 as its base instead of 10 or 2. You don't need to know why e is special yet — just recognize ln(x) when you see it in a loss function later.

06 Second real-world example (doubling time)

Finance example — using logs to reverse-solve

You want to know: how many years will it take for an investment to double at 8% annual compound interest? Set up: 2P = P(1.08)ⁿ → 2 = (1.08)ⁿ. To solve for n (which is stuck in the exponent), you need a logarithm:

n = log(2) / log(1.08) ≈ 9.006 years

This is exactly why logarithms exist — they let you pull a variable back down out of an exponent so you can solve for it. This is precisely the technique used behind the scenes when ML training algorithms need to "undo" an exponential relationship.

07 Common mistakes to avoid

Mistake 1 — aᵐ × aⁿ ≠ a^(m×n). You ADD exponents when multiplying same-base terms, not multiply them. (aᵐ)ⁿ is where you multiply.

Mistake 2 — Negative exponent does NOT mean negative number. 2⁻² = 1/4 = 0.25 (positive!), not -4.

Mistake 3 — log(0) and log(negative numbers) are undefined. You can never take the log of zero or a negative number — this matters a lot in ML when loss functions can break if a probability hits exactly 0.

Mistake 4 — log(a) + log(b) ≠ log(a+b). The actual rule is log(a) + log(b) = log(a×b) — logs turn multiplication into addition, not addition into addition.
