List Methods

~2 hours · append, remove, sort — modifying a list after you've made it

01 Why this matters for AI/ML

The pattern "start with an empty list, then append results to it inside a loop" is probably the single most common structure you'll write while processing data — collecting predictions, filtered rows, cleaned values, or computed features one at a time. Today's methods are the toolkit for that.

02 Lists are mutable

Unlike numbers and strings, lists can be changed in place after creation — this is called being "mutable." That's the whole point of today's methods: they modify the existing list directly, rather than creating a new one.

03 The core list methods

.append(x)
Adds x to the end of the list
.insert(i, x)
Inserts x at position i
.remove(x)
Removes the FIRST occurrence of value x
.pop()
Removes and returns the last item
.sort()
Sorts the list in place, ascending
.reverse()
Reverses the list in place
.count(x)
Counts how many times x appears
.index(x)
Finds the position of the first x
scores = [85, 92, 78] scores.append(95) # [85, 92, 78, 95] scores.remove(78) # [85, 92, 95, 95]... wait, removes value 78: [85, 92, 95] scores.sort() # [85, 92, 95] scores.reverse() # [95, 92, 85]

04 The .sort() trap — a genuinely common bug

Critical gotcha: .sort() sorts the list in place and returns None. This means:
# WRONG — this will make sorted_scores equal to None! sorted_scores = scores.sort() # RIGHT — sort first, then use the original variable scores.sort() sorted_scores = scores

This exact mistake (assigning the result of .sort() expecting a sorted list back) trips up nearly everyone at least once — flag it now so it costs you zero debugging time later.

05 Real-world example (the append-in-a-loop pattern)

The single most common data-processing pattern you'll write

raw_scores = [45, 88, 92, 30, 76, 55, 99] passing_scores = [] for i in range(len(raw_scores)): if raw_scores[i] >= 50: passing_scores.append(raw_scores[i]) print(passing_scores) # [88, 92, 76, 55, 99]

Start with an empty list, loop through your data, conditionally append what passes a filter — this exact skeleton is something you'll reuse constantly, well before you ever meet Pandas' built-in filtering (which does the same job faster, but this is the concept underneath it).

06 Second example (sorting for median — reconnects Day 6)

Ties back to Day 6's statistics

responses = [23, 45, 12, 67, 34, 89, 21] responses.sort() print(responses) # [12, 21, 23, 34, 45, 67, 89] middle_index = len(responses) // 2 print(responses[middle_index]) # the median (for odd-length lists)

Remember Day 6's rule: "sort the data first" to find the median? This is that exact step, now written as real code — .sort() is precisely how you'd implement it.

07 Common mistakes to avoid

Mistake 1 — Assigning the result of .sort() (covered above). Always remember it returns None — the list itself is what's changed.

Mistake 2 — Confusing .remove() with .pop(). .remove(x) deletes by VALUE (the first matching item); .pop(i) deletes by POSITION (index). Mixing these up removes the wrong thing.

Mistake 3 — Trying to .remove() a value that isn't in the list. This causes a ValueError — always make sure the value actually exists first if you're not certain.

Mistake 4 — Modifying a list while looping over it by index. Appending or removing items during iteration can silently skip elements or cause errors — this is a genuinely subtle bug that catches experienced programmers too, not just beginners.
