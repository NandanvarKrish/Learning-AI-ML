Matplotlib: Line & Bar Charts

~2 hours · Seeing your data, not just reading it

01 Why this matters for AI/ML

Numbers in a table hide patterns that jump out instantly in a chart — trends, outliers, gaps. Before modeling anything, real data work almost always includes a visualization step, and after modeling, you'll plot results to explain them. Matplotlib is the foundational Python plotting library — even fancier tools (Seaborn, Plotly) are typically built on top of it or designed to feel similar.

02 The basic setup

import matplotlib.pyplot as plt plt.plot([1, 2, 3, 4], [10, 25, 15, 30]) plt.show()

plt is the standard alias, exactly like np and pd before it. plt.show() displays the chart — in scripts you must call it explicitly; in Jupyter notebooks or Colab, charts often display automatically, but calling it is still good habit.

03 Line charts — for trends over a sequence

days = ["Mon", "Tue", "Wed", "Thu", "Fri", "Sat", "Sun"] sales = [1200, 1500, 900, 1800, 2000, 1100, 1700] plt.plot(days, sales) plt.xlabel("Day") plt.ylabel("Sales (₹)") plt.title("Weekly Sales") plt.show()

Line charts are ideal when the x-axis represents something continuous or sequential — time, in this case. The line visually connects each point, emphasizing the trend from one value to the next.

04 Bar charts — for comparing categories

categories = ["Electronics", "Clothing", "Groceries"] totals = [45000, 32000, 28000] plt.bar(categories, totals) plt.xlabel("Category") plt.ylabel("Total Sales (₹)") plt.title("Sales by Category") plt.show()

Bar charts are better for comparing distinct, unordered categories — there's no "trend" between "Electronics" and "Clothing," so a line connecting them would be misleading. This choice (line vs. bar) matters more than it might seem: it's about matching the chart to what kind of comparison you're actually making.

05 Real-world example (reconnects Day 30/34's sales data)

The exact dataset from earlier days, finally visualized

daily_sales = [1200, 1500, 900, 1800, 2000, 1100, 1700] days = ["Mon","Tue","Wed","Thu","Fri","Sat","Sun"] plt.plot(days, daily_sales, marker="o") plt.title("Weekly Sales Trend") plt.xlabel("Day") plt.ylabel("Sales (₹)") plt.show()

The marker="o" argument adds a visible dot at each data point — a small but genuinely useful touch for readability. Looking at this chart, the Wednesday dip and weekend pattern are immediately obvious — far faster than scanning the raw list of numbers.

06 Common mistakes to avoid

Mistake 1 — Mismatched x and y lengths. plt.plot(x, y) requires x and y to have the exact same number of values, or it raises an error.

Mistake 2 — Using a line chart for unordered categories. Connecting "Electronics" to "Clothing" with a line implies a trend or order that doesn't exist — use a bar chart instead.

Mistake 3 — Forgetting axis labels and a title. A chart with unlabeled axes is often meaningless to anyone (including future you) looking at it later — always label what's being shown.

Mistake 4 — Forgetting plt.show() in a script. Without it, a chart may simply never appear when running a plain Python file (behavior differs slightly in notebooks, but the habit is worth keeping).
