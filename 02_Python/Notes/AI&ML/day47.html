Inheritance

~2 hours · Reusing and extending an existing class instead of duplicating it

01 Why this matters for AI/ML

Every model class in scikit-learn (which you'll use constantly in Phase 3) inherits from a common base class that provides shared functionality — inheritance is precisely how libraries avoid rewriting the same setup code for every single model type. Understanding it now means the phrase "X inherits from Y" in library documentation won't be a mystery.

02 Basic inheritance

class Animal: def __init__(self, name): self.name = name def speak(self): print(self.name + " makes a sound") class Dog(Animal): pass my_dog = Dog("Bruno") my_dog.speak() # Bruno makes a sound

class Dog(Animal): means Dog inherits from Animal — Dog automatically gets everything Animal has (the __init__, the speak method) without rewriting any of it. Animal is called the parent (or base/super) class; Dog is the child (or subclass).

03 Overriding a method

class Dog(Animal): def speak(self): print(self.name + " says Woof!") my_dog = Dog("Bruno") my_dog.speak() # Bruno says Woof! — Dog's own version is used instead

A child class can define its own version of a method with the same name — this overrides the parent's version. When you call speak() on a Dog, Python uses Dog's own definition instead of Animal's, because it checks the child class first.

04 super() — calling the parent's version

class Employee: def __init__(self, name, salary): self.name = name self.salary = salary class Manager(Employee): def __init__(self, name, salary, team_size): super().__init__(name, salary) # reuse Employee's setup self.team_size = team_size # add Manager-specific data m = Manager("Priya", 80000, 5) print(m.name) # Priya (set by Employee's __init__ via super()) print(m.team_size) # 5 (set directly by Manager's own __init__)

super().__init__(...) calls the PARENT class's constructor, letting you reuse its setup logic instead of duplicating those same lines in the child. This is the standard, correct way to extend a class's initialization rather than replacing it entirely.

05 Real-world example (Employee hierarchy)

The classic inheritance teaching example, for good reason

class Employee: def __init__(self, name, salary): self.name = name self.salary = salary def describe(self): print(self.name + " earns " + str(self.salary)) class Manager(Employee): def __init__(self, name, salary, team_size): super().__init__(name, salary) self.team_size = team_size def describe(self): print(self.name + " manages a team of " + str(self.team_size)) emp = Employee("Rohan", 40000) mgr = Manager("Priya", 80000, 5) emp.describe() # Rohan earns 40000 mgr.describe() # Priya manages a team of 5 — Manager's OWN describe() is used

Both classes share the same underlying name/salary setup (via inheritance and super()), but each has its own specialized describe() — a genuinely realistic structure for related-but-different real-world entities.

06 Second example (SavingsAccount extends BankAccount)

Reconnects directly to Day 46's BankAccount

class BankAccount: def __init__(self, owner, balance=0): self.owner = owner self.balance = balance def deposit(self, amount): self.balance = self.balance + amount class SavingsAccount(BankAccount): def __init__(self, owner, balance, interest_rate): super().__init__(owner, balance) self.interest_rate = interest_rate def add_interest(self): interest = self.balance * self.interest_rate / 100 self.deposit(interest) # reuses the PARENT's deposit method directly savings = SavingsAccount("Meera", 10000, 5) savings.add_interest() print(savings.balance) # 10500.0

07 Common mistakes to avoid

Mistake 1 — Forgetting to call super().__init__(). If a child class defines its own __init__ without calling super().__init__(), the parent's setup never runs, and any attributes it was supposed to set simply won't exist.

Mistake 2 — Accidentally overriding when you meant to extend. Redefining a method with the same name completely REPLACES the parent's version unless you explicitly call the parent's version too (often via super()).

Mistake 3 — Using inheritance for an "has-a" relationship instead of "is-a." A Manager IS-A Employee (inheritance fits). A Car HAS-A Engine (the car should probably just hold an Engine object as an attribute, not inherit from it) — misusing inheritance here creates confusing, incorrect class relationships.

Mistake 4 — Assuming the child automatically has NEW attributes the parent never set. Inheritance only gives you what the parent actually defines — any additional attributes need their own setup in the child's __init__.
