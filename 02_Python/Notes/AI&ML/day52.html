Pandas: Series & DataFrames

~2 hours · The tool you'll use to load and explore every real dataset from here on

01 Why this matters for AI/ML

Pandas is where "raw data" becomes something you can actually work with. It's built on top of yesterday's NumPy, and it's the very first thing most real ML projects do: load a dataset, look at it, clean it. Nearly every Kaggle notebook, tutorial, or production pipeline you'll ever see starts with import pandas as pd.

02 Series — a single labeled column

import pandas as pd scores = pd.Series([85, 92, 78, 90]) print(scores) # 0 85 # 1 92 # 2 78 # 3 90 # dtype: int64

A Series is a 1D labeled array — similar to a NumPy array, but with an index (the labels on the left, 0-3 by default) attached. Think of it as one column of a spreadsheet.

03 DataFrame — a full table

data = { "name": ["Asha", "Rohan", "Priya"], "age": [28, 34, 25], "order_value": [1200, 800, 1500] } df = pd.DataFrame(data) print(df)

A DataFrame is a 2D table — rows and columns, exactly like Day 18's matrix concept and Day 37's dictionary-of-records, but now a real, powerful object with built-in tools for exploring and cleaning. This dictionary-of-lists pattern (each key becomes a column) is the most common way to build a small DataFrame directly in code.

04 First things to check on any DataFrame

.head(n)
First n rows (default 5)
.tail(n)
Last n rows
.shape
(rows, columns)
.columns
List of column names
.info()
Column types, missing value counts
.describe()
Mean, std, min, max for numeric columns

.describe() is Day 6–7's entire statistics week, computed instantly for every numeric column at once — mean, standard deviation, min, max, and quartiles, without writing a single loop.

05 Selecting columns and rows

df["age"] # one column, returned as a Series df[["name", "age"]] # multiple columns, returned as a DataFrame df.loc[0] # row with LABEL 0 df.iloc[0] # row at POSITION 0 (same result here, but conceptually different) df.iloc[0:2] # first two rows by position

.loc selects by label (the index value itself); .iloc selects by integer position, regardless of what the labels are. With a default 0,1,2... index they often look identical — the difference matters once you filter or reorder a DataFrame and the labels no longer match position.

06 Real-world example (exploring a customer dataset)

The first few lines of almost every real analysis

df = pd.DataFrame({ "name": ["Asha", "Rohan", "Priya", "Meera"], "age": [28, 34, 25, 41], "order_value": [1200, 800, 1500, 950] }) print(df.shape) # (4, 3) — 4 rows, 3 columns print(df.columns) # Index(['name', 'age', 'order_value']) print(df["order_value"].mean()) # 1112.5 print(df.describe()) # full stats table for age and order_value

Four lines, and you already know the shape of your data, its column names, and complete summary statistics — this is genuinely how real exploration starts, every time.

07 Common mistakes to avoid

Mistake 1 — Confusing .loc and .iloc. .loc uses the INDEX LABEL; .iloc uses POSITION. After sorting or filtering a DataFrame, these can point to completely different rows.

Mistake 2 — Forgetting a single column selection returns a Series, not a DataFrame. df["age"] is a Series; df[["age"]] (double brackets) is a one-column DataFrame — subtly different types with different available methods.

Mistake 3 — Assuming .describe() covers text columns too. By default it only summarizes NUMERIC columns — text/categorical columns need different exploration (like .value_counts(), coming soon).

Mistake 4 — Forgetting the import alias. pd.DataFrame(...) without import pandas as pd causes a NameError, exactly like yesterday's NumPy import rule.
