Return Values & Default Arguments

~2 hours · Making functions hand back results instead of just printing

01 Why this matters for AI/ML

Yesterday's functions could only print. That's fine for a final display, but useless if you want to use the result — feed it into another calculation, store it in a list, or pass it to a second function. return is what makes functions truly composable, which is exactly how real ML pipelines chain steps together (load → clean → train → predict, each function handing its output to the next).

02 The return statement

def square(n): return n * n result = square(5) print(result) # 25

print() just displays a value on screen — it doesn't give you anything back to use in code. return sends a value back to wherever the function was called, so you can capture it in a variable, use it in a larger expression, or pass it straight into another function.

return also immediately ends the function — any code after a return statement inside that same execution path never runs.

03 Functions with no explicit return

def greet(name): print("Hello " + name) # no return statement x = greet("Asha") print(x) # None — since greet() never explicitly returns a value

If a function never hits a return statement, calling it produces None by default. This is exactly why yesterday's print-only functions couldn't have their "result" meaningfully captured — there was never anything to capture.

04 Default arguments

def apply_discount(price, discount_percent=10): return price - (price * discount_percent / 100) print(apply_discount(1000)) # 900.0 — uses the default 10% print(apply_discount(1000, 25)) # 750.0 — overrides the default

A default argument lets a parameter be optional — if the caller doesn't supply it, the default value is used instead. This is genuinely common in real libraries (including ones you'll use in Phase 3) where most function calls only need to specify a couple of the available options, letting sensible defaults handle the rest.

05 Real-world example (composable discount calculator)

Now genuinely reusable in a bigger calculation

def apply_discount(price, discount_percent=10): return price - (price * discount_percent / 100) cart_prices = [500, 1200, 300] total = 0 for i in range(len(cart_prices)): discounted = apply_discount(cart_prices[i]) total = total + discounted print(total) # 1800.0 — sum of all discounted prices

Because apply_discount RETURNS a value instead of printing it, you can feed that result directly into a running total — this simply wasn't possible with yesterday's print-only version. This is the difference between a function that just displays something and one that actually contributes to further computation.

06 Second example (break-even, now returning a value)

Reconnects to Day 38's break-even function

def units_to_breakeven(fixed_cost, price_per_unit, cost_per_unit=40): profit_per_unit = price_per_unit - cost_per_unit return fixed_cost / profit_per_unit units = units_to_breakeven(4000, 90) # uses default cost_per_unit=40 print(units) # 80.0 units2 = units_to_breakeven(4000, 90, 50) # overrides the default print(units2) # 100.0

Now the result can be used in further code — compared against a target, added to a report, plotted — instead of only ever being printed directly.

07 Common mistakes to avoid

Mistake 1 — Using print() inside a function, then trying to use its "result" elsewhere. x = my_function() where the function only prints (no return) gives you x = None, not the printed value.

Mistake 2 — Forgetting return ends the function immediately. Any code written after a reached return statement (at the same execution path) never executes.

Mistake 3 — Putting a default argument before a non-default one. def f(x=5, y): is a syntax error — parameters with defaults must come AFTER all parameters without defaults.

Mistake 4 — Assuming a function must always return the same type. Python doesn't enforce this, but it's a real source of bugs (e.g., a function returning a number in one path and None in another) — good practice is to make sure every path through a function returns something sensible.
