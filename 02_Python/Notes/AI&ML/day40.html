*args & **kwargs

~2 hours · Functions that accept a flexible number of arguments

01 Why this matters for AI/ML

You've actually already used a function with flexible arguments — print() itself accepts any number of values: print(1, 2, 3) works just as well as print("hi"). Many real ML library functions (which you'll meet soon in scikit-learn and beyond) accept optional, flexible settings the exact same way. Today you learn how that's built.

02 *args — flexible positional arguments

def add_all(*numbers): total = 0 for i in range(len(numbers)): total = total + numbers[i] return total print(add_all(1, 2, 3)) # 6 print(add_all(10, 20, 30, 40)) # 100 print(add_all(5)) # 5

*numbers collects any number of positional arguments into a single tuple named numbers inside the function. The name after the asterisk is up to you (args is just a common convention) — the asterisk itself is what matters.

03 **kwargs — flexible keyword arguments

def show_profile(**details): for key in details: print(key + ": " + str(details[key])) show_profile(name="Asha", age=28, city="Surat") # name: Asha # age: 28 # city: Surat

**details collects any number of named (keyword) arguments into a dictionary. This is genuinely useful when you don't know in advance which fields will be provided — the function adapts to however many named values it's given.

04 Combining regular parameters with *args and **kwargs

def describe_product(name, *features, **details): print("Product: " + name) print("Features: " + str(features)) print("Details: " + str(details)) describe_product("Laptop", "fast", "lightweight", price=55000, brand="TechCo")

Order matters: regular parameters first, then *args, then **kwargs — always in that sequence. Python enforces this ordering; writing them in the wrong order causes a syntax error.

05 Real-world example (flexible cart total)

A genuinely useful pattern — no predetermined cart size

def cart_total(*prices): total = 0 for i in range(len(prices)): total = total + prices[i] return total print(cart_total(500, 1200)) # works for a 2-item cart print(cart_total(500, 1200, 300, 900)) # works for a 4-item cart, same function

Without *args, you'd need to know the exact number of items in advance, or pass a list explicitly every time. This lets the SAME function handle a cart of any size, called naturally.

06 Second example (flexible customer record)

Reconnects to Day 37's dictionaries

def create_customer(**fields): return fields customer_a = create_customer(name="Rohan", age=28) customer_b = create_customer(name="Priya", age=25, city="Mumbai", is_premium=True) print(customer_a) # {'name': 'Rohan', 'age': 28} print(customer_b) # {'name': 'Priya', 'age': 25, 'city': 'Mumbai', 'is_premium': True}

Some customers have more fields recorded than others — **kwargs lets one function handle any of these variations without needing a separate function signature for every possible combination of fields.

07 Common mistakes to avoid

Mistake 1 — Wrong parameter order. Regular parameters, then *args, then **kwargs — any other order is a syntax error.

Mistake 2 — Forgetting *args is a tuple internally. Since it's a tuple, you index it and loop through it exactly like Day 34's tuples — but you cannot modify it (tuples are immutable).

Mistake 3 — Forgetting **kwargs is a dictionary internally. Access its contents the same way you learned on Day 37 — looping over keys, using .get(), etc.

Mistake 4 — Overusing *args/**kwargs when regular parameters would be clearer. If a function always needs exactly 2 or 3 specific values, plain named parameters are more readable and catch mistakes earlier — reach for *args/**kwargs specifically when the number of inputs genuinely varies.
