Operators

~2 hours · Arithmetic, comparison, and logical — how code actually DOES things

01 Why this matters for AI/ML

Operators are how you turn variables into decisions and calculations — filtering a dataset ("only rows where age > 18"), computing a new feature ("price per unit = total / quantity"), or checking a condition before acting. Every single one of these is built from today's three operator families.

02 Arithmetic operators

+ Addition — 5 + 3 = 8
- Subtraction — 5 - 3 = 2
* Multiplication — 5 * 3 = 15
/ Division — 5 / 2 = 2.5 (always returns a float, even if evenly divisible)
// Floor division — 5 // 2 = 2 (divides, then rounds down/discards remainder)
% Modulus — 5 % 2 = 1 (the remainder after division)
** Exponent — 5 ** 2 = 25 (power, same idea as Day 4's exponents)

Important Python 3 detail: / ALWAYS returns a float, even for evenly divisible numbers — 10 / 2 gives 5.0, not 5. If you need a whole-number result, use // instead.

03 Comparison operators

== Equal to — 5 == 5 → True
!= Not equal to — 5 != 3 → True
> Greater than — 7 > 3 → True
< Less than — 2 < 9 → True
>= Greater or equal — 5 >= 5 → True
<= Less or equal — 4 <= 3 → False

Every comparison operator produces a bool (True or False) — nothing else. This is the exact output type you'll feed into conditionals (tomorrow's topic).

Critical distinction: = vs ==

x = 5 ASSIGNS the value 5 to x (an action). x == 5 CHECKS whether x equals 5, returning True or False (a question). Confusing these two is one of the most common beginner errors in any programming language.

04 Logical operators

and True only if BOTH sides are True
or True if AT LEAST ONE side is True
not Flips True to False, or False to True

Example: age = 20, has_id = True

age >= 18 and has_id → True and True → True (can enter)

age >= 18 and not has_id → True and False → False (can't enter without ID)

05 Real-world example (discount eligibility)

Business logic example

An online store gives a discount if a customer is a premium member AND their cart total is over ₹2,000, OR if it's their birthday month:

cart_total = 2500 is_premium = True is_birthday_month = False eligible = (is_premium and cart_total > 2000) or is_birthday_month print(eligible) # True

This single line combines comparison operators (>) with logical operators (and, or) to encode a real business rule — exactly the kind of logic you'll write constantly when filtering and processing data.

06 Second example (modulus for A/B testing)

A genuinely common real use of %

A company wants to randomly split customers into two A/B test groups using their customer ID:

customer_id = 4471 group = customer_id % 2 # 0 or 1 if group == 0: print("Group A") else: print("Group B")

% here checks whether the ID is even or odd — an easy, deterministic way to split any population roughly 50/50. This exact modulus trick shows up constantly in real data engineering, not just as a math curiosity.

07 Common mistakes to avoid

Mistake 1 — Using = when you mean ==. if x = 5: is a syntax error in Python (good — it stops you), but in other languages this silently does the wrong thing. Always double-check which one you need.

Mistake 2 — Expecting / to give a whole number. 7 / 2 is 3.5, not 3 — use // if you specifically want floor division.

Mistake 3 — Operator precedence surprises. 2 + 3 * 4 is 14, not 20 — multiplication happens before addition, just like in standard math. Use parentheses when unsure.

Mistake 4 — Forgetting that and/or only work correctly between actual boolean expressions. Comparisons like age > 18 naturally produce booleans; make sure both sides of an and/or are genuinely comparisons or booleans, not raw values you assume are "truthy" without checking.
