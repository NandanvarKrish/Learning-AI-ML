Mini Project: Console To-Do List

~2 hours · Lists, loops, and menus — a genuinely useful little tool

01 Why this matters for AI/ML

Today isn't about a new concept — it's about combining lists, dictionaries, loops, and conditionals into a menu-driven program that keeps running until the user chooses to stop. This "loop, show options, act on input, repeat" structure is the backbone of countless real tools, including data-labeling scripts and interactive pipelines you may build later.

02 Planning the program

We'll store tasks as a list of dictionaries, each with a text and a done flag:

tasks = [] # each task looks like: {"text": "Buy milk", "done": False}

The program loop will repeatedly show a menu and act on the user's choice:

1. Add task 2. View tasks 3. Mark task done 4. Remove task 5. Quit

03 Building it, step by step

Adding a task:

tasks.append({"text": "Buy milk", "done": False})

Viewing tasks (with a done/pending marker):

for i in range(len(tasks)): task = tasks[i] if task["done"]: marker = "[x]" else: marker = "[ ]" print(str(i+1) + ". " + marker + " " + task["text"])

Marking a task done (user picks by 1-based number):

index = int(input("Which task number? ")) - 1 tasks[index]["done"] = True

Note the - 1 — users naturally think in 1-based numbering ("task #1"), but Python lists are 0-indexed, so converting between the two is essential and a very common source of off-by-one bugs.

04 The complete program (with functions, best-practice structure)

tasks = [] def add_task(text): tasks.append({"text": text, "done": False}) def view_tasks(): for i in range(len(tasks)): task = tasks[i] marker = "[x]" if task["done"] else "[ ]" print(str(i+1) + ". " + marker + " " + task["text"]) def mark_done(index): tasks[index]["done"] = True while True: print("1.Add 2.View 3.Done 4.Remove 5.Quit") choice = input("Choose: ") if choice == "1": text = input("Task: ") add_task(text) elif choice == "2": view_tasks() elif choice == "3": num = int(input("Task number: ")) mark_done(num - 1) elif choice == "5": print("Goodbye!") break

Splitting the logic into named functions (add_task, view_tasks, mark_done) instead of cramming everything into the loop makes the program far easier to read, test, and extend — exactly the organizing principle Day 38's functions were building toward.

05 Common mistakes to avoid

Mistake 1 — Off-by-one between user-facing numbers and list indices. Always subtract 1 when converting a "task #3" the user typed into tasks[2].

Mistake 2 — Forgetting the quit condition inside the while True loop. Without a break reachable from some menu choice, the program runs forever.

Mistake 3 — Not validating the task number before using it. If a user enters a number bigger than the list, you'll hit an IndexError — a real program should check this first or wrap it in try/except (Day 44).

Mistake 4 — Rebuilding logic inline instead of using functions. Repeating the same view-tasks loop in multiple places (instead of calling one view_tasks() function) makes future changes error-prone — update one function, not five copy-pasted blocks.
