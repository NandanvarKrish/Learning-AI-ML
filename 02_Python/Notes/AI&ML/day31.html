While Loops

~2 hours · Repeating until a condition changes, not a fixed count

01 Why this matters for AI/ML

Yesterday's for loop is perfect when you know exactly how many times to repeat something (10 epochs, 7 days of sales). But often in ML you don't know the count in advance — you want to keep training "until the error is small enough" or keep retrying "until an API call succeeds." That's precisely what a while loop is for: repeating based on a condition, not a fixed number.

02 The while loop

A while loop keeps running its block as long as a condition stays True:

count = 0 while count < 5: print(count) count = count + 1

Output: 0, 1, 2, 3, 4 — same result as yesterday's range(5) for loop, but built from a condition instead of a fixed sequence. Before each pass, Python checks the condition; the moment it becomes False, the loop stops.

03 The infinite loop danger

This is the single most important warning in today's lesson: if you forget to update the variable that the condition depends on, the loop runs forever (or until your program crashes/hangs). This is called an "infinite loop," and it's a genuinely common beginner mistake.

Broken example (never write this):

count = 0 while count < 5: print(count) # forgot to update count! This never stops.

Every while loop needs something inside its body that eventually makes the condition False — usually updating a counter, or changing a variable the condition checks.

04 Real-world example (convergence loop)

Direct connection to Day 24's gradient descent

error = 100 step = 0 while error > 1: error = error * 0.6 step = step + 1 print("Step " + str(step) + ": error = " + str(error))

This is structurally almost identical to how real gradient descent training loops work: keep improving until the error is small enough — you don't know in advance exactly how many steps that will take, so a while loop (condition-based) fits far more naturally than a for loop (fixed-count) for this kind of task.

05 Second example (bank withdrawal simulation)

Business example

balance = 5000 withdrawal = 750 while balance >= withdrawal: balance = balance - withdrawal print("Withdrew " + str(withdrawal) + ", remaining: " + str(balance)) print("Insufficient funds for another withdrawal")

The number of withdrawals possible isn't known ahead of time — it depends entirely on the balance and withdrawal amount, which is exactly the kind of scenario where while is the natural, correct choice over for.

06 When to use while vs for

Use for when you know the exact number of iterations in advance (loop through 10 epochs, loop through every row of a 500-row dataset).

Use while when repetition depends on a condition that changes unpredictably during execution (keep going until converged, keep retrying until successful, keep processing until a balance runs out).

07 Common mistakes to avoid

Mistake 1 — Forgetting to update the condition variable. Covered above — this is the #1 while loop bug, causing infinite loops.

Mistake 2 — Off-by-one condition boundaries. while count < 5 vs while count <= 5 produce different numbers of iterations — always double check which one you actually need.

Mistake 3 — Updating the variable in the wrong place. If the update line is accidentally placed outside the loop's indented block, it only runs once, and the loop condition never changes — same infinite-loop result.

Mistake 4 — Using while when for is clearly more appropriate. If you already know you need exactly 10 repetitions, a for loop with range(10) is clearer and less error-prone than manually managing a counter with while.
