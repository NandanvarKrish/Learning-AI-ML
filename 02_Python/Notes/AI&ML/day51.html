NumPy: Arrays & Vectorized Math

~2 hours · The array library nearly all of Python ML is built on top of
Data libraries begin 📊

NumPy today, Pandas next — the tools you'll use to load and manipulate every real dataset from here forward.

01 Why this matters for AI/ML

Pandas is built on NumPy. Scikit-learn expects NumPy arrays. TensorFlow and PyTorch's tensors work almost identically to NumPy arrays by design. Every single ML library you'll touch from here on either IS NumPy underneath, or was deliberately designed to feel like it. Today's concepts aren't just "one more library" — they're the shared vocabulary of the entire ecosystem.

02 Installing and importing

pip install numpy
import numpy as np

np is the near-universal convention for NumPy's alias — you will see it written exactly this way in virtually every tutorial, codebase, and library you ever encounter.

03 Creating an array

import numpy as np scores = np.array([85, 92, 78, 90, 88]) print(scores) # [85 92 78 90 88] print(type(scores)) # <class 'numpy.ndarray'>

This looks similar to a Python list, but it's a fundamentally different, faster, more capable object underneath — an ndarray (n-dimensional array).

04 The single biggest advantage: vectorized math

This is the concept that makes NumPy worth learning

Remember the append-in-a-loop pattern from Day 35? To double every value in a plain Python list, you needed a loop:

# The OLD way (plain Python list) prices = [100, 200, 300] doubled = [] for i in range(len(prices)): doubled.append(prices[i] * 2)

With a NumPy array, the same operation is one line, with NO loop at all:

# The NumPy way prices = np.array([100, 200, 300]) doubled = prices * 2 print(doubled) # [200 400 600]

Every arithmetic operation on a NumPy array automatically applies to every element — this is called vectorization, and it's both dramatically less code AND dramatically faster (NumPy runs the loop internally, in optimized low-level code, not slow Python).

05 A crucial contrast: lists vs. arrays with *

python_list = [1, 2, 3] print(python_list * 2) # [1, 2, 3, 1, 2, 3] — duplicates the list! numpy_array = np.array([1, 2, 3]) print(numpy_array * 2) # [2 4 6] — multiplies each element!

The exact same * 2 means completely different things depending on the type — this is a genuinely important distinction to internalize early, since the symbols look identical but the behavior is opposite in spirit.

06 Array attributes and aggregate functions

.shape
Dimensions, e.g. (5,)
.ndim
Number of dimensions
.dtype
Data type stored (e.g. int64)
.sum()
Total of all elements
.mean()
Average (Day 6, instantly!)
.std()
Standard deviation (Day 7, instantly!)
.max() / .min()
Largest / smallest value
np.arange(a,b)
Like range(), but returns an array
scores = np.array([85, 92, 78, 90, 88]) print(scores.mean()) # 86.6 print(scores.std()) # ~5.03 print(scores.max()) # 92

Remember hand-calculating mean and standard deviation on Days 6–7? This is that exact same math, computed instantly, on any size of dataset, with zero manual loop-writing.

07 2D arrays — real matrices (reconnects Day 18)

grid = np.array([[1, 2, 3], [4, 5, 6]]) print(grid.shape) # (2, 3) — 2 rows, 3 columns print(grid[0]) # [1 2 3] — first row print(grid[0, 1]) # 2 — row 0, column 1

This is Day 18's "matrix as a table of numbers" — except now it's a real, fast, directly usable object instead of a nested Python list you'd have to loop through manually.

08 Common mistakes to avoid

Mistake 1 — Forgetting the import. np.array(...) without import numpy as np first causes a NameError.

Mistake 2 — Confusing array multiplication with matrix multiplication. arr1 * arr2 multiplies element-by-element; real matrix multiplication (Day 19's row·column rule) needs np.dot(arr1, arr2) or the @ operator instead.

Mistake 3 — Shape mismatches. Operating on two arrays with incompatible shapes raises an error (or triggers "broadcasting" rules you'll learn more about soon) — always sanity-check .shape when something goes wrong.

Mistake 4 — Expecting list methods to work identically. NumPy arrays don't have .append() the way lists do (technically np.append() exists but creates a whole new array each time — genuinely inefficient in a loop). Arrays are best built all at once, not grown incrementally.
