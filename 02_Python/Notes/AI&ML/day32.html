Break & Continue

~2 hours · Finer control over both for and while loops

01 Why this matters for AI/ML

break is literally the mechanism behind "early stopping" — a real, widely-used ML training technique where you stop training the moment a model's improvement plateaus, instead of wasting time and risking overfitting by running all planned epochs regardless. continue is exactly what you use to skip over bad or missing data rows while processing a dataset, without aborting the entire loop.

02 break — exit the loop immediately

break stops the loop entirely, right where it is, regardless of the original condition:

for i in range(10): if i == 4: break print(i)

Output: 0, 1, 2, 3 — then the loop stops completely the moment i reaches 4, never printing 4-9 even though range(10) would normally continue.

03 continue — skip to the next iteration

continue skips the REST of the current pass only, then moves on to the next iteration — the loop itself keeps going:

for i in range(6): if i == 3: continue print(i)

Output: 0, 1, 2, 4, 5 — notice 3 is skipped, but the loop still continues through 4 and 5, unlike break which would have stopped entirely.

04 Real-world example (early stopping — direct ML technique)

A genuine, named ML training technique

error = 50 for epoch in range(100): error = error * 0.7 print("Epoch " + str(epoch) + ": error = " + str(error)) if error < 1: print("Early stopping triggered!") break

Even though the loop was set up to potentially run 100 epochs, it stops far earlier once the error drops below the threshold. This is not a simplified teaching example — "early stopping" is a genuinely standard, named technique you'll use directly when training real models in Phase 4, and it's built from exactly this break pattern.

05 Second example (skipping bad data)

Data cleaning example

transactions = [500, -200, 750, -50, 1200] total_sales = 0 for i in range(5): amount = transactions[i] if amount < 0: continue total_sales = total_sales + amount print(total_sales)

Negative values here represent refunds, which shouldn't count toward total sales — continue skips just those entries while the loop carries on processing every other transaction normally. (Lists are formally covered on Day 34 — this previews indexing again, same as Day 30.)

06 Common mistakes to avoid

Mistake 1 — Confusing break and continue. break = stop the whole loop now. continue = skip just this one pass, keep looping. Mixing these up produces very different (and confusing) results.

Mistake 2 — Expecting break to exit more than one loop. In a nested loop (a loop inside another loop — not yet covered here, but you'll see it soon), break only exits the innermost loop it's directly inside, not any outer loops.

Mistake 3 — Placing break/continue outside any loop. These statements only make sense inside a for or while loop's body — using them elsewhere causes a syntax error.

Mistake 4 — Forgetting that code after continue in the same iteration never runs. Any lines after continue (within that same loop pass) are skipped entirely for that iteration — only the very next loop pass resumes normal execution.
