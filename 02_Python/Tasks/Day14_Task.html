📊 Normalise Student Scores — The ML Way
You have a list of 6 student scores. In Machine Learning, before training a model, we normalise all numbers to the 0–1 range. Why? Because a model treats 88 as "88 times bigger" than 1 — but 0.88 and 0.01 mean something sensible as probabilities.

Write a list comprehension that divides each score by 100. Then write a second one that only normalises scores of 50 or above (the passing ones).

Expected output:
All normalised: [0.85, 0.45, 0.72, 0.33, 0.91, 0.58]
Passing only: [0.85, 0.72, 0.91, 0.58]
List Comprehension ML Preprocessing ⭐ Beginner
🔐
Solve to unlock solution code
Get the answer right → code appears instantly
What does [s/100 for s in scores if s >= 50] do to the list [85, 45, 72, 33, 91, 58]?
A Divides ALL scores by 100 → [0.85, 0.45, 0.72, 0.33, 0.91, 0.58]
B Keeps only scores ≥50, THEN divides each by 100 → [0.85, 0.72, 0.91, 0.58]
C Returns True/False for each score
D Sums all scores above 50
🔓Solution Code — Unlocked!
Python — List Comprehension · Task 1
scores = [85, 45, 72, 33, 91, 58] # Step 1: Normalise ALL scores (divide by 100) # [expression for item in list] all_norm = [s/100 for s in scores] print("All normalised:", all_norm) # [0.85, 0.45, 0.72, 0.33, 0.91, 0.58] # Step 2: Normalise ONLY passing scores (≥50) # [expression for item in list if condition] # ↑ filter runs FIRST — only scores ≥50 get divided pass_norm = [s/100 for s in scores if s >= 50] print("Passing only:", pass_norm) # [0.85, 0.72, 0.91, 0.58] ← 45 and 33 excluded # 💡 This is EXACTLY what Pandas does: # df["marks_norm"] = df["marks"] / 100

🏷️ Assign Pass/Fail Labels — Building ML Training Data
In supervised ML, every data point needs a label — "spam" or "not spam", "pass" or "fail", 1 or 0. You'll create labels for your student scores using a ternary expression inside a list comprehension.

Write a list comprehension that produces "Pass" for scores ≥ 50 and "Fail" for anything below. Then make a second version that produces 1 and 0 (the format ML models actually use).

Real world: This is how you create the y (labels) column for training an ML model!
Ternary in Comprehension ML Labels (y) ⭐ Beginner
🔐
Solve to unlock solution code
In ["Pass" if s>=50 else "Fail" for s in scores] — where does the condition go?
A After "for s in scores" — like [s for s in scores if s>=50]
B BEFORE "for" — it's a ternary expression: ["A" if cond else "B" for x in list]. The if/else is part of the output value, not a filter.
C In a separate if statement before the comprehension
D Both before and after "for" — double condition
🔓Solution Code — Unlocked!
Python — Ternary in Comprehension · Task 2
scores = [85, 45, 72, 33, 91, 58] # Pattern: [value_if_true if condition else value_if_false for x in list] # The condition is part of the OUTPUT expression — not a filter! # Text labels (human-readable) labels = ["Pass" if s >= 50 else "Fail" for s in scores] print("Labels:", labels) # ['Pass', 'Fail', 'Pass', 'Fail', 'Pass', 'Pass'] # Binary labels (1/0) — this is y in ML! y = [1 if s >= 50 else 0 for s in scores] print("Binary (y):", y) # [1, 0, 1, 0, 1, 1] ← THIS is your ML training label! # Combine scores (X) with labels (y) — this is your training dataset dataset = [{"marks": s, "passed": 1 if s >= 50 else 0} for s in scores] print("Dataset:", dataset)

🔗 Build a Student Dictionary Using zip() — No More Index Errors
You have two lists — names and scores. You want to combine them into a dictionary. The old way would be using a counter variable and risking index errors. zip() is cleaner, safer, and what every Python developer uses.

Use zip() inside a dict comprehension to create {"Ali": 88, "Sara": 45, ...}. Then use zip() in a for loop to print each student's report.

Also: Compute accuracy using zip(y_true, y_pred) — the exact line used in every ML evaluation script.
zip() + dict comprehension ML Accuracy Calculation ⭐⭐ Intermediate
🔐
Solve to unlock solution code
You have y_true=[1,0,1,1] and y_pred=[1,0,0,1]. What does sum(1 for t,p in zip(y_true,y_pred) if t==p) return?
A 4 — sums all values in both lists
B 2 — counts where y_true and y_pred are different
C 3 — counts positions where prediction matches truth (index 0, 1, 3 match)
D 0.75 — gives accuracy as a decimal directly
🔓Solution Code — Unlocked!
Python — zip() · Task 3
names = ["Ali", "Sara", "Usman", "Zara"] scores = [88, 45, 72, 33 ] # Dict comprehension using zip() — clean, no index errors! grade_map = {n: s for n, s in zip(names, scores)} print(grade_map) # {'Ali': 88, 'Sara': 45, 'Usman': 72, 'Zara': 33} # Print each student's report for name, score in zip(names, scores): status = "✅ Pass" if score >= 50 else "❌ Fail" print(f"{name}: {score} → {status}") # ───────────────────────────────────────── # ML ACCURACY — the exact formula used everywhere y_true = [1, 0, 1, 1] # actual answers y_pred = [1, 0, 0, 1] # model's guesses correct = sum(1 for t, p in zip(y_true, y_pred) if t == p) accuracy = correct / len(y_true) * 100 print(f"Correct: {correct}/4 → Accuracy: {accuracy:.1f}%") # Correct: 3/4 → Accuracy: 75.0%

🔢 Number Every Item With enumerate() — Training Loop Style
When printing reports or running training epochs, you often need both the index AND the value. Without enumerate(), beginners write i = 0 then i += 1 inside the loop — messy and error-prone.

Use enumerate(scores, start=1) to print student reports numbered from 1. Then simulate a training loop with epoch numbers and loss values.

Real world: Every ML training loop uses: for epoch, loss in enumerate(losses, 1):

What is the difference between enumerate(scores) and enumerate(scores, start=1)?
A No difference — both start from 0
B enumerate(scores) starts index from 0. enumerate(scores, start=1) starts from 1. For student reports, start=1 is more natural: "Student 1" not "Student 0".
C start=1 skips the first score
D enumerate(scores, start=1) only works on numbers

Python — enumerate() · Task 4
scores = [85, 45, 72, 33, 91, 58] # WITHOUT enumerate() — messy! ❌ i = 0 for s in scores: print(f"Student {i}: {s}") # starts from 0 — not natural i += 1 # easy to forget or mess up # WITH enumerate() — clean! ✅ for i, score in enumerate(scores, start=1): status = "✅" if score >= 50 else "❌" print(f"Student {i}: {score} {status}") # Student 1: 85 ✅ # Student 2: 45 ❌ # Student 3: 72 ✅ ... # ───────────────────────────────────────── # TRAINING LOOP — this is the real ML pattern losses = [2.1, 1.4, 0.8, 0.4, 0.2] for epoch, loss in enumerate(losses, 1): print(f"Epoch {epoch}/5 — loss: {loss:.1f}") # Epoch 1/5 — loss: 2.1 # Epoch 2/5 — loss: 1.4 ...

⚙️ Generator vs List — Processing 1 Million Images
Imagine you are training an AI image classifier on 1 million images. You cannot load all 1 million images into memory at once — your computer only has 16GB RAM but the images take 200GB. This is exactly the problem generators solve.

Write both versions: a list comprehension (loads everything now) and a generator expression (lazy — loads one at a time). Print the type of each. Then write a generator function using yield that simulates loading images in batches.

Real world: PyTorch DataLoader uses this exact generator pattern.
Generator Expression + yield Large Dataset Processing ⭐⭐⭐ Advanced
🔐
Solve to unlock solution code
What is the KEY difference between [x**2 for x in range(1000)] and (x**2 for x in range(1000))?
A No difference — both create a list immediately
B () creates a tuple instead of a list
C [] creates ALL 1000 values in memory right now. () creates a lazy generator — values are computed ONE AT A TIME when you ask for them. The generator uses almost no memory.
D [] is faster, () is just shorthand
🔓Solution Code — Unlocked!
Python — Generators · Task 5
# LIST comprehension — ALL values in RAM now list_version = [x**2 for x in range(1000)] print(type(list_version)) # <class 'list'> print(len(list_version)) # 1000 values ALL in RAM # GENERATOR expression — lazy, tiny memory gen_version = (x**2 for x in range(1000)) print(type(gen_version)) # <class 'generator'> print(next(gen_version)) # 0 ← yields FIRST value print(next(gen_version)) # 1 ← yields SECOND value print(next(gen_version)) # 4 ← third, and so on # ───────────────────────────────────────── # GENERATOR FUNCTION — using yield (AI batch loader) def batch_loader(data, batch_size=2): """Yields one batch at a time — never loads all data at once""" for i in range(0, len(data), batch_size): yield data[i : i + batch_size] # ← pauses here, resumes next call images = ["img1", "img2", "img3", "img4", "img5", "img6"] for batch_num, batch in enumerate(batch_loader(images), 1): print(f"Batch {batch_num}: {batch}") # Batch 1: ['img1', 'img2'] # Batch 2: ['img3', 'img4'] # Batch 3: ['img5', 'img6'] # 💡 PyTorch DataLoader works EXACTLY like this!

# ============================================ # MINI ML PREPROCESSING PIPELINE # Using: zip, dict comprehension, # list comprehension, enumerate # ============================================ # Raw data (imagine this came from a CSV file) names = ["Ali", "Sara", "Usman", "Zara", "Ahmed"] scores = [88, 45, 72, 33, 91 ] # STEP 1: Build full dataset dict using zip() full_data = {n: s for n, s in zip(names, scores)} print("Full data:", full_data) # STEP 2: Normalise ALL scores (list comprehension) X = [s/100 for s in scores] # Features print("Normalised X:", X) # STEP 3: Create binary labels (ternary comprehension) y = [1 if s >= 50 else 0 for s in scores] # Labels print("Labels y:", y) # STEP 4: Filter passing students only (dict comprehension + filter) passing = {n: s for n, s in zip(names, scores) if s >= 50} print("Passing students:", passing) # STEP 5: Numbered report using enumerate() print("\n=== STUDENT REPORT ===") for i, (name, score, norm, label) in enumerate(zip(names,scores,X,y), 1): status = "✅" if label else "❌" print(f"{i}. {name:<8} | raw:{score} | norm:{norm:.2f} | y={label} {status}") # Output: # 1.
