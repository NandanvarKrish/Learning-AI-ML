📂 open() Reference

The 4 File Modes — Every Detail

The mode argument in open("file.txt", mode) determines what you can do with the file. Getting the mode wrong can destroy your data.

ModeNameWhat It DoesFile Must Exist?ML Use Case
"r"ReadOpens for reading only. File pointer at start.Yes (FileNotFoundError if not)Load a dataset CSV or config JSON
"w"WriteCreates new file OR overwrites existing content completely.No — creates itSave model results (fresh each run)
"a"AppendAdds to end of file. Does NOT touch existing content.No — creates it if neededAdd new training log entries without losing old ones
"x"CreateCreates new file. Fails with FileExistsError if file already exists.Must NOT existSafe file creation — prevents overwriting
"rb"/"wb"BinaryRead/write binary data (images, audio, model weights)Depends on r or wLoading image files, saving model pickles

🛡️ The with Statement — Why It Is Mandatory

Python — with vs without
# ❌ WITHOUT with — dangerous! File may never close f = open("data.txt", "r") content = f.read() # If an error occurs here, f.close() never runs! f.close() # Must remember this — easy to forget # ✅ WITH with — safe and clean (ALWAYS use this) with open("data.txt", "r") as f: content = f.read() # File closes AUTOMATICALLY when block ends — even if error occurs! print(content) # Use content OUTSIDE the with block
⚠️ Critical rule: ALWAYS use with open(). Without it, unclosed files cause: memory leaks, data corruption, the file remaining locked so other programs cannot access it. In production ML systems with thousands of file operations per second, forgetting close() is catastrophic.

csv.DictReader — See Each Row as a Dict

Type or edit CSV data below:
💡 csv.reader vs csv.DictReader:
csv.reader → row = ["Ali", "88", "92", "Karachi"] (access by index: row[1])
csv.DictReader → row = {"name":"Ali","marks":"88","att":"92","city":"Karachi"} (access by name: row["marks"])
Always use DictReader — it is more readable and does not break if columns reorder.
Python — Full CSV Pipeline
import csv # READ CSV with DictReader with open("students.csv", "r", newline="") as f: reader = csv.DictReader(f) data = list(reader) # list of row-dicts # Access by column name — not fragile index! for row in data: print(row["name"], row["marks"]) # WRITE CSV with DictWriter with open("results.csv", "w", newline="") as f: writer = csv.DictWriter(f, fieldnames=["name", "grade"]) writer.writeheader() writer.writerow({"name": "Ali", "grade": "A"})

💡 The json.dump() pattern:
json.dump(data, f) → writes to FILE (use with with open())
json.dumps(data) → returns a STRING (the 's' = string)
json.load(f) → reads FILE → gives you Python dict
json.loads(s) → parses STRING → gives you Python dict

You Already Understand How Pandas Works

Pandas pd.read_csv() is built on exactly what you learned today — it just adds automatic type detection, DataFrame structure, and hundreds of analysis methods. The underlying operations are the same.

Python File I/O vs Pandas
# ===== WHAT YOU KNOW (Pure Python) ===== import csv with open("students.csv", "r") as f: data = list(csv.DictReader(f)) marks = [int(r["marks"]) for r in data] avg = sum(marks) / len(marks) # ===== WHAT PANDAS DOES (Month 2) ===== import pandas as pd df = pd.read_csv("students.csv") # same file! avg = df["marks"].mean() # auto type-converts numbers! # pd.read_csv() = open() + DictReader + type detection + DataFrame
🎯 Why this matters: When Pandas' read_csv() fails, you now know how to diagnose it — open the file manually with csv.DictReader and inspect each row. When an API returns JSON and Pandas fails to parse it, you can debug it with json.loads(). You are not just a Pandas user — you understand the foundation it is built on.
