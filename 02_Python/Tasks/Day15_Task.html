Part 1
🎓 The Student Class — Foundation of Everything
Start by building the Student class. This is the core object — every feature of the system works with Student objects.

What your Student class needs:
• __init__(roll, name, marks) — validates marks using a @property setter (raises ValueError if marks outside 0–100)
• grade @property — returns A+/A/B/C/D/F based on marks
• is_passing @property — True if marks ≥ 50
• to_dict() — returns a dict with all student data (needed for CSV saving)
• __repr__ — so printing a Student looks nice

Why this matters in AI: In sklearn, every model object stores its own state (self.threshold, self.fitted_). The marks setter with validation is exactly how production systems prevent bad data from entering your pipeline.
OOP · class @property · setter raise · ValueError __repr__

Solve to unlock the Student class code
Answer correctly → full Part 1 code appears
In the Student class, marks is stored as self._marks (with underscore) but accessed as student.marks. Why?
A Underscore is required by Python for all class attributes
B _marks is the private storage. The @property + @setter lets you control access — so student.marks = 150 raises ValueError before it's stored. Without this, anyone could set invalid marks directly.
C It makes the code faster
D Underscore means the attribute is a class variable, not instance variable

# student.py — The Student class import datetime class Student: pass_mark = 50 # class variable — shared by all students def __init__(self, roll, name, marks): self.roll = str(roll) self.name = str(name).strip() self.marks = marks # calls the @setter — validates! self.added = datetime.date.today() @property def marks(self): return self._marks @marks.setter def marks(self, val): if not isinstance(val, (int, float)): raise TypeError("marks must be a number") if not (0 <= val <= 100): raise ValueError(f"marks {val} not in 0–100") self._marks = round(val, 1) @property def grade(self): for threshold, letter in [ (90, "A+"), (80, "A"), (70, "B"), (60, "C"), (50, "D") ]: if self._marks >= threshold: return letter return "F" @property def is_passing(self): return self._marks >= Student.pass_mark def to_dict(self): return { "roll" : self.roll, "name" : self.name, "marks" : self._marks, "grade" : self.grade, "status": "Pass" if self.is_passing else "Fail" } def __repr__(self): return f"Student({self.roll}, {self.name!r}, {self.grade})" # === ScholarStudent inherits from Student === class ScholarStudent(Student): """Student who also tracks scholarship eligibility.""" scholarship_threshold = 85 def __init__(self, roll, name, marks): super().__init__(roll, name, marks) # ← calls Student.__init__ @property def qualifies_for_scholarship(self): return self._marks >= ScholarStudent.scholarship_threshold def to_dict(self): d = super().to_dict() # get parent's dict first d["scholar"] = self.qualifies_for_scholarship return d # === QUICK TEST (run this file directly to test) === if __name__ == "__main__": s1 = Student("101", "Ali", 88) print(s1) # uses __repr__ print(s1.grade) # "A" print(s1.is_passing) # True print(s1.to_dict()) ss = ScholarStudent("102", "Sara", 91) print(ss.qualifies_for_scholarship) # True # Test validation try: Student("103", "Bad", 150) except ValueError as e: print(f"Validation caught: {e}")

Part 2
📚 The GradeBook — CSV, JSON, Search & Reports
The GradeBook holds ALL students. It automatically loads from a CSV file when it starts and saves to it whenever a student is added. This is what "persistence" means — data survives after the program closes.

What GradeBook needs:
• __init__(filename) — loads existing data from CSV on startup
• add(roll, name, marks) — creates a Student, validates, adds to list, saves to CSV
• leaderboard() — returns students sorted by marks (highest first) using lambda
• search(name) — finds a student by name (case-insensitive)
• stats() — returns average, highest, lowest, pass count using comprehensions
• export_json() — saves full summary to a JSON file
• batch_report() — generator that yields one report line at a time

Why this matters: This is a real data management class. Every ML project has something like this — a class that loads data, processes it, and saves results.
File I/O · CSV · JSON Comprehensions Generator · yield lambda · sorted()
🔐
Solve to unlock the GradeBook code
The batch_report() method uses yield instead of returning a list. Why is this better for a large class of 500+ students?
A yield is faster than return
B yield produces one report line at a time — never builds the full 500-line list in memory. You could process thousands of students without running out of RAM. A return would require all 500+ lines to be created at once.
C yield automatically saves to a file
D There is no difference — both are the same for small classes

# gradebook.py — GradeBook class import csv, json, os, datetime from student import Student class GradeBook: """Manages students with full CSV persistence.""" def __init__(self, filename="students.csv"): self.filename = filename self.students = self._load() # load on startup # ── PRIVATE: Load from CSV ────────────────── def _load(self): if not os.path.exists(self.filename): return [] students = [] with open(self.filename) as f: for row in csv.DictReader(f): try: s = Student(row["roll"], row["name"], float(row["marks"])) students.append(s) except (ValueError, KeyError) as e: print(f"⚠️ Skipped bad row: {e}") return students # ── PRIVATE: Save to CSV ─────────────────── def _save(self): with open(self.filename, "w", newline="") as f: fields = ["roll", "name", "marks", "grade", "status"] w = csv.DictWriter(f, fieldnames=fields) w.writeheader() w.writerows(s.to_dict() for s in self.students) # ── PUBLIC: Add student ───────────────────── def add(self, roll, name, marks): try: s = Student(roll, name, marks) self.students.append(s) self._save() # auto-save after every add print(f"✅ Added: {s}") except (ValueError, TypeError) as e: print(f"❌ Cannot add student: {e}") # ── Leaderboard: sorted by marks ─────────── def leaderboard(self): return sorted(self.students, key=lambda s: s.marks, reverse=True) # ── Search by name ────────────────────────── def search(self, name): matches = [s for s in self.students if name.lower() in s.name.lower()] return matches # ── Stats using comprehensions ────────────── def stats(self): if not self.students: return {} all_marks = [s.marks for s in self.students] return { "count" : len(self.students), "average" : round(sum(all_marks)/len(all_marks), 2), "highest" : max(all_marks), "lowest" : min(all_marks), "passing" : sum(1 for s in self.students if s.is_passing), "grades" : set(s.grade for s in self.students), } # ── Export to JSON ────────────────────────── def export_json(self, outfile="summary.json"): data = { "exported": str(datetime.date.today()), "stats" : self.stats(), "students": [s.to_dict() for s in self.students], } data["stats"]["grades"] = list(data["stats"].get("grades", [])) with open(outfile, "w") as f: json.dump(data, f, indent=2) print(f"✅ Exported to {outfile}") # ── Batch report — GENERATOR ──────────────── def batch_report(self): """Yields one formatted report line at a time — memory efficient.""" yield f"{'#':<4} {'Name':<15} {'Marks':>6} {'Grade':>6} {'Status':>8}" yield "-" * 44 for i, s in enumerate(self.leaderboard(), 1): status = "✅ Pass" if s.is_passing else "❌ Fail" yield f"{i:<4} {s.name:<15} {s.marks:>6} {s.grade:>6} {status:>8}"

🖥️ The Main Menu — Putting It All Together
The main menu is what the user sees. It creates a GradeBook, then shows a menu in a loop. Each option calls a method from GradeBook or Student.

Menu options:
1️⃣ Add student (with error handling for bad input)
2️⃣ View leaderboard (ranked list with enumerate)
3️⃣ Search student by name
4️⃣ Class statistics
5️⃣ Print batch report (uses the generator)
6️⃣ Export JSON summary
7️⃣ Quit

The whole point: When you add a student, it's saved to students.csv automatically. Close and reopen the program — the data is still there. This is persistence.

🔐
Final puzzle — unlock the main.py
The menu uses for line in gb.batch_report(): print(line). Why is iterating a generator this way correct?
A It is wrong — you must call next() manually on generators
B A for loop automatically calls next() on any generator — so each iteration yields the next line one at a time, never loading all lines at once. This is the standard Pythonic way to consume a generator.
C for loop converts the generator to a list first, then iterates
D You need list(gb.batch_report()) before you can loop it

(y/n): ").lower() == "y" if scholar: s = ScholarStudent(roll, name, marks) gb.students.append(s) gb._save() print(f"✅ Scholar added: {s}") else: gb.add(roll, name, marks) except ValueError as e: print(f"❌ Invalid input: {e}") elif choice == "2": # ── Leaderboard ──────────────────────── print("\n🏆 LEADERBOARD") for rank, s in enumerate(gb.leaderboard(), 1): medal = {1:"🥇", 2:"🥈", 3:"🥉"}.get(rank, " ") print(f" {medal} {rank}. {s.name:<15} {s.marks:>6} {s.grade}") elif choice == "3": # ── Search ───────────────────────────── q = input("Search name: ") found = gb.search(q) if found: for s in found: print(f" Found: {s} marks={s.marks} grade={s.grade}") else: print(f" No student named '{q}'") elif choice == "4": # ── Statistics ───────────────────────── st = gb.stats() print("\n📊 CLASS STATISTICS") for k, v in st.items(): print(f" {k:12}: {v}") elif choice == "5": # ── Batch report — generator ─────────── print("\n📋 BATCH REPORT") for line in gb.batch_report(): # ← iterates generator! print(" " + line) elif choice == "6": gb.export_json() elif choice == "7": print("👋 Goodbye! Data saved to students.csv") break else: print("❓ Invalid choice. Enter 1–7.") # ── Entry point ───────────────────────────── if __name__ == "__main__": main()
