📦 Import Reference

4 Ways to Import — Side by Side

Python gives you 4 different import syntaxes. Each has a different use case. ML code uses all 4 — sometimes in the same file.

SyntaxWhat It DoesHow to UseWhen to Use
import math Loads the entire module math.sqrt(25)
math.pi		 When you need many functions from the module
from math import sqrt Imports only one specific function sqrt(25) — no prefix! When you only need 1–2 specific items
from math import sqrt, pi, floor Imports multiple specific items sqrt(25), pi, floor(3.7) When you need a few specific items, no full module
import numpy as np Loads module with a short alias np.array([1,2,3])
np.mean(data)		 Standard for ML libraries — np, pd, plt are universal conventions
⚠️ Never use: from math import * — this imports EVERYTHING and pollutes your namespace. You can accidentally overwrite built-in functions. Professional ML code never uses import *.

🤖 The ML Stack — Memorise These 5 Imports

Every ML project starts with these exact imports
np←import numpy as npArrays, maths, matrix operations
pd←import pandas as pdDataFrames, CSV loading, data manipulation
plt←import matplotlib.pyplot as pltCharts, graphs, visualisation
sklearn←from sklearn.model_selection import train_test_splitML models, train/test split, metrics
tf←import tensorflow as tfDeep learning, neural networks (Month 6+)
💡 Why np, pd, plt? These are not required by Python — they are universal community conventions. Every ML tutorial, every Stack Overflow answer, every Kaggle notebook uses the same aliases. Using different names (e.g. import numpy as num) makes your code unreadable to other ML engineers.

🔨 Own Module

Build mltools.py — Your Personal ML Utility Module

A module is simply any .py file. Save your reusable functions in mltools.py — then import them from anywhere. This is exactly how sklearn, pandas, and numpy are structured.

📄 mltools.py (your module)
def normalise(val, mn=0, mx=100):
  return (val-mn)/(mx-mn)

def get_grade(marks):
  if marks>=80: return "A"
  elif marks>=60: return "B"
  else: return "Fail"

def class_average(*scores):
  return sum(scores)/len(scores)
📄 main.py (imports your module)
import mltools

# Use your functions:
n = mltools.normalise(75)
g = mltools.get_grade(85)
avg = mltools.class_average(80,90,70)

# OR import specific:
from mltools import get_grade
grade = get_grade(88)
💡 Rules for your own module: (1) Both files must be in the SAME folder. (2) The filename (without .py) becomes the module name. (3) No spaces in filename — use underscores. (4) Test your module functions by running the .py file directly first.

Part 4 — random.seed() — Reproducible AI
Why seed(42) is the most important line in ML experiments
⏱ 10 min
🎲 random.seed()

Why random.seed(42) is Critical in ML

Every ML model involves randomness — random train/test splits, random initial weights, random data shuffling. Without a seed, results change every run. With a seed, the same "random" sequence is always produced.

Python — seed() demo
import random # WITHOUT seed — different every run: print(random.randint(1,100)) # 73 today, 18 tomorrow # WITH seed — always the same: random.seed(42) print(random.randint(1,100)) # always 82 print(random.randint(1,100)) # always 15 # In ML — reproducible train/test split: from sklearn.model_selection import train_test_split X_train, X_test = train_test_split(X, test_size=0.2, random_state=42) # random_state=42 ← same as seed — same split every time!
🔬 Why 42? It is a convention from "The Hitchhiker's Guide to the Galaxy" where 42 is "the answer to everything". Any integer works — 0, 1, 99, 2024. The number itself does not matter; using the SAME number consistently does. When you report ML results, always state your seed so others can reproduce.
